# Каталог запросов бенчмарка

Подготовительная серверная часть без HTTP/UI: BenchmarkRunCatalog находит журнал по проверенным владельцу, сессии и requestId и создаёт новый журнал только при отсутствии такой записи. Файловое ядро, журнал и координатор этим пакетом не меняются.

## Привязка запроса

RunId версии1 — первые16 байт SHA-256 UTF-8 строки WebVault.Bench.Request.v1|<owner invariant>|<session invariant>|<request Guid N>, преобразованные через new Guid(byte[]). Каталог журнала: DataRoot/Bench/<RunId N>. Поколение права не входит в адрес: повтор того же запроса после перевыдачи права должен конфликтовать со старой записью, а не оживлять её.

Параметры владельца/сессии/поколения права предоставляет только доверенный серверный адаптер. Клиентский requestId — непустой случайный GUID, не путь и не право доступа. Стабильный адрес не заменяет аутентификацию. В Entry есть внутренние DirectoryPath и Identity; этот объект нельзя напрямую сериализовать в HTTP-ответ с абсолютным путём и служебными полями.

Find не создаёт Bench при его отсутствии. Start после первоначального callback полномочий может создать Bench с тем же маркером версии1, который использует файловое ядро. Неизвестный или повреждённый корень не принимается под управление. DataRoot должен существовать, иметь допустимый абсолютный локальный путь, длину4–100 и родителей без reparse points. Будущий HTTP-адаптер дополнительно проверяет нахождение вне сайта через действующий контракт DataRoot.

Root.lock согласует поиск, проверку квот и создание между взаимодействующими процессами и файловым ядром. Конфликт блокировки — отказ без ожидания/повторного исполнения. Журнал отдельно блокирует свои переходы. Callback в начале и перед возвратом обязан проверять актуальный контекст; в рабочем адаптере он не может быть пустым.

## Повторы и неопределённость

Повтор Start возвращает существующий совпадающий журнал через Initialize, не сбрасывая next/фазу и не продлевая срок. Несовпадение параметров или поколения права вызывает конфликт. Остановленный/очищенный либо просроченный запрос не начинает работу заново; вызывающий код обязан учитывать возвращённую фазу и срок перед запуском шага. Другие владелец/сессия получают другой адрес и не находят старый запрос.

Сбой после сохранения журнала, но до ответа разрешается через Find. Если процесс остановился после создания каталога, но до полноценного журнала, повтор даёт benchmark_run_unconfirmed, а не перезаписывает неизвестное состояние. Прерванный journal.new и повреждение журнала также не очищаются автоматически.

Для внутреннего подсчёта квот каталог читает ограниченные служебные записи других запусков из доверенного хранилища, проверяет контрольную сумму и совпадение ID с адресом и повторно использует валидатор журнала. Это не выдача чужих журналов пользователю. Контрольная сумма не защищает от администратора ОС; ACL обязательны.

## Квоты и сохранность

- Не более одного незавершённого/неподтверждённо очищенного запуска на настоящего владельца, включая старую сессию и истёкший срок.
- До8 незавершённых запусков во всём каталоге. Завершённый счётчик без подтверждения очистки не освобождает эту квоту.
- Перед новым журналом допускается менее31 существующего GUID-каталога: после его создания остаётся место для одного файлового каталога при глобально последовательном ядре. Все физические остатки учитываются, даже без journal.bin. Общий обход ограничен34 записями корня: маркер, блокировка и максимум32 каталога.
- Повтор существующего запроса допускается без нового места при полной квоте. Новое создание при превышении квоты отказывает и ничего не удаляет.

Очищенные журналы пока сохраняются как записи о прежних запросах и продолжают занимать физическую квоту. Автоматического удаления или срока хранения в этом пакете нет: молчаливое удаление такой записи позволило бы старому requestId повторно создать запуск. Поэтому после исчерпания физической ёмкости новые запуски блокируются до отдельной безопасной политики обслуживания. Это ограничение подготовительного каталога, не готовая долговременная эксплуатация.

## Windows-проверка

Из корня репозитория после получения коммита:

```powershell
powershell.exe -NoProfile -File .\tools\Test-BenchmarkRunCatalog.ps1
if ($LASTEXITCODE -ne 0) { throw 'Ошибка проверки каталога запусков; остановка' }
```

Ожидается PASS: 12/12 run-catalog groups; CLR ...

Скрипт компилирует каталог и настоящий журнал в новом процессе Windows PowerShell и использует уникальную временную .wvk-* папку внутри рабочей копии, удаляемую в finally без перехода по reparse points. Рабочий DataRoot, IIS, SQL, npm и build не используются. Ассистент Windows-прогон не выполнял; прежние результаты10/12/13/10 не являются проверкой нового каталога.

Проверяются поиск без побочных созданий, повтор после потерянного ответа/сохранённого Begin, конфликт параметров, изоляция контекста, блокировка незавершённого старого запуска, новый запрос после очистки без оживления старого, смена поколения права, логическая/физическая квоты, повреждение, неизвестный объект и отказ полномочий.
