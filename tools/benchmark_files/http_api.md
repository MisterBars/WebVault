# HTTP-протокол файлового бенчмарка

Первый защищённый HTTP-вход для server.files.cycle: api/benchmark_files.ashx → BenchmarkFilesHandler. Существующий api/benchmark.ashx и экран не меняются. Это ещё не готовая пользовательская функция или приёмка IIS.

## Выключено по умолчанию

Новые start/step разрешены только при appSettings BenchmarkFilesEnabled=true, без учёта регистра и без лишних пробелов. Отсутствие настройки, false и другие значения запрещают новые файловые операции с benchmark_files_disabled. Рабочий Web.config этим пакетом не меняется. Включение и публикация — отдельные согласованные действия на стенде после локальных проверок, не следствие push.

status/cancel остаются доступны прежней действующей сессии при выключенном флаге и после отзыва отдельного права, чтобы не препятствовать сверке/очистке. Это не анонимный доступ: все действия требуют POST, JSON, штатные заголовки, Origin/HTTPS-проверки и действующую неограниченную обычную учётку с CSRF. Администратор не запускает файловый тест. SQL-схема00–08 требуется для start/step; повторная миграция08 при установленном столбце не нужна.

Физическая квота каталога и сохранение очищенных журналов пока ограничивают число новых запусков. Безопасная политика обслуживания/хранения и очистка без действующей пользовательской сессии ещё открыты. Не включать этот подготовительный маршрут на рабочем сайте как завершённый эксплуатационный бенчмарк.

## Запросы версии1

Все поля обязательны по действию; неизвестные поля отклоняются. requestId — непустой lowercase GUID N из32 шестнадцатеричных символов. Пользователь не задаёт владельца, сессию, поколение права, runId, путь, URL, SQL или текст файла.

- start: action, requestId, actors1–8, sizeKiB1–64, count1–13.
- status: action, requestId.
- step: action, requestId, index0–12.
- cancel: action, requestId.

Числа — JSON-целые, не строки, bool или дробные значения. count означает число полных последовательных файловых циклов, каждый обходит заданное число псевдохранилищ. Это не число одновременных пользователей. Прогрев/измерения на уровне клиентского отчёта здесь ещё не реализованы; протокол не принимает warmup/repetitions и не совместим автоматически с ранее подготовленным черновиком транспорта files.*.

## Сессия и право

Каждая контрольная точка повторно вызывает WebApi.RequireUser(write:true), сравнивает исходные UserId/SessionId/CSRF и отклоняет смену контекста. Для start/step дополнительно проверяются флаг и текущее BenchmarkGrant через SQL с активностью, обычной ролью, отсутствием forced change, отзывом и обоими сроками сессии. Перевыдача создаёт другое поколение и не оживляет старый запрос. Защиты в коде не означают выполненные негативные/конкурентные испытания.

DataRoot получается через VaultHandler.DataRoot: вне сайта, с проверкой родителей и существованием общих vaults/history. Регистрация личного VaultId не нужна. Меняются только управляемые тестовые каталоги Bench; рабочие заметки, история и сессии не записываются этим обработчиком.

## Ответы и неопределённость

start/status/cancel возвращают ограниченное представление: protocolVersion, scenario/version, fixtureVersion, requestId, found, runId, state (absent/ready/working/stopped), next, count, actors, bytes, expiresUtc, expired и cleanup. Нет абсолютного DirectoryPath, внутренних Owner/Session/Grant, токенов или содержимого файлов. Отсутствие собственного запроса в status обозначено found=false, не успешным выполнением.

step возвращает идентичность протокола/запроса/журнала, payloadId текущего файлового вызова, index, actors, bytes, verifiedReads, serverCycleMs, cleanup=ok и remainingObjects=0 для файлов именно этого шага. Это не подтверждение очистки всего запуска или удаления журнала. Байты проверяются сервером, тексты обратно не передаются. serverCycleMs включает проверки/промежуточные SQL-проверки полномочий и не является физической задержкой диска. Клиентские HTTP samples этим обработчиком не создаются.

Ошибка после Complete или потерянный ответ могут сопровождаться уже увеличенным next. После любого неопределённого изменяющего запроса сверять status; не повторять файловую операцию ради потерянного времени и не подставлять его как успешный замер. Повтор start использует прежний requestId без сброса прогресса; остановленный/просроченный ответ не разрешает новые шаги.

cancel получает operation.lock через координатор, останавливает журнал и адресно проверяет/очищает все count привязанных файловых каталогов. Только после успеха всех проверок ConfirmCleanup устанавливает подтверждение для запуска. Журнал сохраняется. Занятая операция, неизвестные файлы, неверный маркер, прерванный журнал и ошибка сессии не дают ложного подтверждения. Очистка может быть частичной; SQL/ФС не атомарны. На новую сессию старый запуск не переносится.

Контролируемые ошибки имеют ограниченные коды: отсутствие запуска404, конфликты409, квота429, выключенная функция/недостающая схема503, отказ сессии/права по штатным кодам. Конфликт блокировки — benchmark_busy, прочая ошибка IO — неопределённый результат хранилища; обёрнутые ошибки могут остаться общим server_error. Произвольные сообщения исключений и пути клиенту не выводятся. Новый запрос не повторяется автоматически.

## Локальная проверка без публикации

Из корня рабочей копии:

```powershell
powershell.exe -NoProfile -File .\tools\Test-BenchmarkFilesProtocol.ps1
if ($LASTEXITCODE -ne 0) { throw 'Ошибка проверки файлового HTTP-протокола; остановка' }
```

Ожидается PASS: 13/13 files-protocol groups; App_Code compiled; CLR ...

Скрипт компилирует весь текущий App_Code с framework-сборками и тестовой обвязкой, проверяет привязку .ashx, валидацию действий/типов/диапазонов/лишних полей, флаг по умолчанию, отсутствие служебных данных в JSON и ограниченные ответы ошибок. Для ошибки создаётся только модель HttpContext с выводом в память; настоящий HTTP-запрос не исполняется. SQL, рабочий DataRoot, браузер и IIS не используются, флаг включать не требуется. Это не test:all, не прогон настоящих сессий и не новый замер производительности. Ассистент C#/Windows-проверку не выполнял.

После компиляции отдельно согласовать стенд и проверить анонимного/обычного/администратора/forced-change, без права/с правом/отзыв/regrant, CSRF/Origin/метод/JSON, start→status→step→cancel, сохранность рабочих данных, повторные запросы/потерянный ответ, параллельные шаг/отмену, recycle, маркеры/reparse и квоты. Подключение интерфейса, согласование транспорта и канонической документации, политика хранения и эксплуатационная приёмка остаются открытыми.
