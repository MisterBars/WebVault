# Вычислительный бенчмарк WebVault

[Индекс и граф](../../docs/note_graph.md) · [Требования](../../docs/next_steps.md#диагностика-производительности--будущая-функция) · [Продолжение](../../docs/handoff.md)

## Область

Минимальная вычислительная часть PERF-ADMIN-01 на сборочном ПК с Node20+. Не требует новых зависимостей или изменения lock. Не подключается к IIS, API, пользовательским заметкам, редактору или сессии. Node не становится зависимостью сайта. Административное право, серверный runner и браузерные сценарии остаются будущей работой.

Стабильные ID версии1: index.references.extract, index.graph.build, index.backlinks.lookup. Проверяются точные ссылки, направленные рёбра/повторы и backlinks. Данные версии1 детерминированы без случайности; size — число блоков Markdown либо число заметок кольцевого графа. Ожидаемые результаты заданы отдельно от измеряемых операций.

## Запуск и проверки

Из tools/cm6 после установки существующих зависимостей проекта:

```text
node --test perf_runner.test.mjs perf_scenarios.test.mjs
npm run test:all
node perf_runner.mjs
node perf_runner.mjs --config <локальный-файл.json>
```

Проверять exit code каждой команды; после провала не объявлять последующие стадии успешными. npm test не полный набор. Build и публикация bundle для только этого инструмента не требуются. Интеграционные тесты и полный набор переданы на локальную проверку; наличие файлов не доказательство успеха. Исходных замеров пока нет.

Пример конфигурации:

```json
{"select":"index","defaults":{"repetitions":30,"warmup":3,"timeoutMs":5000,"size":50},"overrides":{"index.graph.build":{"size":100}},"maxRunMs":120000}
```

select: all, index или непустой массив уникальных ID. Порядок фиксирован каталогом. repetitions1–200, warmup0–20, timeoutMs100–30000, size2–300; maxRunMs100–600000. Неизвестные поля/ID, null вместо объекта, неверные типы и overrides невыбранных ID отклоняются. Код, SQL, URL, путь worker или путь vault через CLI не задаются.

## Завершение и результаты

Один worker на сценарий, повторы последовательны. Подготовка и проверка правильности не входят во время операции, но имеют таймаут. После ошибки/таймаута/отмены worker завершается, остаток набора отмечается skipped. Между повторами пауза10 мс, общий deadline может её сократить с последующей остановкой. Лимиты V8 worker: old128/young32/stack4 MiB; это не предел RSS всего процесса. Завершение и отчёт могут добавить время после deadline.

stdout содержит JSON. Коды:0 — весь набор успешен,1 — ошибка/неполный запуск,130 — обработанная отмена SIGINT/SIGTERM. Принудительное завершение ОС не гарантирует отчёт. Доставку сигналов Windows проверить отдельно; соответствующий POSIX CLI-тест там явно пропускается. AbortSignal и таймауты проверяются независимо.

Сохраняются конфигурация, версии, ID запуска, хеш fixtures, SHA/dirty при доступности Git, Node/ОС/архитектура/CPU и fingerprint файлов js/mjs верхнего уровня tools/cm6 плюс package.json/package-lock.json. Fingerprint не проверяет node_modules, bundle или установленный сайт. Для сравнения нужны одинаковые данные, настройки, зависимости и среда. Неизвестные условия не считать совпавшими.

Времена в ms, прогрев отдельно; медиана/min/max/MAD. MAD — медиана абсолютных отклонений от медианы. p95 nearest-rank только от100 успешных измеряемых повторов. Ошибка не включается в успешную выборку; частичная статистика не делает сценарий успешным. Прогрев не обещает управляемый холодный старт. HTTP, готовность UI, память, загрузка CPU и серверные стадии не измеряются.

Runner не хранит результаты: экспорт stdout пользователь сохраняет вне репозитория/публикуемого сайта. Автоматического удаления и срока хранения нет; хранить нужную пару до/после, остальные удалять вручную. Тексты заметок, токены и абсолютные пути в отчёт не включаются. Это не оптимизация и не функциональная/безопасностная приёмка сайта.

## Дедлайн браузерных компонентных сценариев

Этот раздел относится к отдельному benchmark_workloads.js, не к worker-инструменту выше. Проверка общего лимита120 секунд повторяется после обеих асинхронных проверок authorize: до подготовки операции и перед добавлением успешного замера. Ответ проверки полномочий на границе120000 ms или позже даёт run_timeout; поздний замер не попадает в успешную статистику. Отмена сохраняет приоритет. Это отбраковка позднего результата, не принудительное завершение уже отправленного запроса authorize и не строгая гарантия завершить очистку/отчёт за120 секунд.

Адресная регрессия: node --test benchmark_deadline.test.mjs. Тест вызывает настоящий createWorkloadRunner с управляемыми часами, моделью графа и callback полномочий: граница/превышение до работы и перед публикацией замера, допустимый ответ до границы и отмена. Он не проверяет настоящий parser, D3, DOM или серверный отзыв права. Новый тест и полный test:all/build переданы владельцу на локальный прогон; успешный запуск этого нового теста здесь не заявлен. Для изменения браузерного модуля после успешных тестов требуется штатный build и отдельная публикация bundle. Существующие статусы остальных браузерных сценариев и общего руководства этим узким исправлением не пересмотрены.
