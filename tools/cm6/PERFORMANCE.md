# Вычислительный бенчмарк WebVault

[Индекс и граф](../../docs/note_graph.md) · [Требования](../../docs/next_steps.md#диагностика-производительности--будущая-функция) · [Продолжение](../../docs/handoff.md)

## Область

Минимальная вычислительная часть PERF-ADMIN-01 на сборочном ПК с Node20+. Не требует новых зависимостей или изменения lock. Не подключается к IIS, API, пользовательским заметкам, редактору или сессии. Node не становится зависимостью сайта. Административное право, серверный runner и браузерные сценарии остаются будущей работой.

Стабильные ID версии1: index.references.extract, index.graph.build, index.backlinks.lookup. Проверяются точные ссылки, направленные рёбра/повторы и backlinks. Данные версии1 детерминированы без случайности; size — число блоков Markdown либо число заметок кольцевого графа. Ожидаемые результаты заданы отдельно от измеряемых операций.

## Запуск и проверки

Из tools/cm6 после установки существующих зависимостей проекта:

```text
node --test perf_runner.test.mjs perf_scenarios.test.mjs
npm run test:all
node perf_runner.mjs
node perf_runner.mjs --config <локальный-файл.json>
```

Проверять exit code каждой команды; после провала не объявлять последующие стадии успешными. npm test не полный набор. Build и публикация bundle для только этого инструмента не требуются. Интеграционные тесты и полный набор переданы на локальную проверку; наличие файлов не доказательство успеха. Исходных замеров пока нет.

Пример конфигурации:

```json
{"select":"index","defaults":{"repetitions":30,"warmup":3,"timeoutMs":5000,"size":50},"overrides":{"index.graph.build":{"size":100}},"maxRunMs":120000}
```

select: all, index или непустой массив уникальных ID. Порядок фиксирован каталогом. repetitions1–200, warmup0–20, timeoutMs100–30000, size2–300; maxRunMs100–600000. Неизвестные поля/ID, null вместо объекта, неверные типы и overrides невыбранных ID отклоняются. Код, SQL, URL, путь worker или путь vault через CLI не задаются.

## Завершение и результаты

Один worker на сценарий, повторы последовательны. Подготовка и проверка правильности не входят во время операции, но имеют таймаут. После ошибки/таймаута/отмены worker завершается, остаток набора отмечается skipped. Между повторами пауза10 мс, общий deadline может её сократить с последующей остановкой. Лимиты V8 worker: old128/young32/stack4 MiB; это не предел RSS всего процесса. Завершение и отчёт могут добавить время после deadline.

stdout содержит JSON. Коды:0 — весь набор успешен,1 — ошибка/неполный запуск,130 — обработанная отмена SIGINT/SIGTERM. Принудительное завершение ОС не гарантирует отчёт. Доставку сигналов Windows проверить отдельно; соответствующий POSIX CLI-тест там явно пропускается. AbortSignal и таймауты проверяются независимо.

Сохраняются конфигурация, версии, ID запуска, хеш fixtures, SHA/dirty при доступности Git, Node/ОС/архитектура/CPU и fingerprint файлов js/mjs верхнего уровня tools/cm6 плюс package.json/package-lock.json. Fingerprint не проверяет node_modules, bundle или установленный сайт. Для сравнения нужны одинаковые данные, настройки, зависимости и среда. Неизвестные условия не считать совпавшими.

Времена в ms, прогрев отдельно; медиана/min/max/MAD. MAD — медиана абсолютных отклонений от медианы. p95 nearest-rank только от100 успешных измеряемых повторов. Ошибка не включается в успешную выборку; частичная статистика не делает сценарий успешным. Прогрев не обещает управляемый холодный старт. HTTP, готовность UI, память, загрузка CPU и серверные стадии не измеряются.

Runner не хранит результаты: экспорт stdout пользователь сохраняет вне репозитория/публикуемого сайта. Автоматического удаления и срока хранения нет; хранить нужную пару до/после, остальные удалять вручную. Тексты заметок, токены и абсолютные пути в отчёт не включаются. Это не оптимизация и не функциональная/безопасностная приёмка сайта.

## Дедлайн браузерных компонентных сценариев

Этот раздел относится к отдельному benchmark_workloads.js, не к worker-инструменту выше. Проверка общего лимита120 секунд повторяется после обеих асинхронных проверок authorize: до подготовки операции и перед добавлением успешного замера. Ответ проверки полномочий на границе120000 ms или позже даёт run_timeout; поздний замер не попадает в успешную статистику. Отмена сохраняет приоритет. Это отбраковка позднего результата, не принудительное завершение уже отправленного запроса authorize и не строгая гарантия завершить очистку/отчёт за120 секунд.

Адресная регрессия: node --test benchmark_deadline.test.mjs. Тест вызывает настоящий createWorkloadRunner с управляемыми часами, моделью графа и callback полномочий: граница/превышение до работы и перед публикацией замера, допустимый ответ до границы и отмена. Он не проверяет настоящий parser, D3, DOM или серверный отзыв права. Новый тест и полный test:all/build переданы владельцу на локальную проверку; успешный запуск этого нового теста здесь не заявлен. Для изменения браузерного модуля после успешных тестов требуется штатный build и отдельная публикация bundle. Существующие статусы остальных браузерных сценариев и общего руководства этим узким исправлением не пересмотрены.

## Согласованные задачи браузерного стенда — открыто

Уточнение PERF-ADMIN-01 от30 октября2026: требования ниже согласованы с владельцем, не отчёт об их реализации. Предыдущие разделы относятся к указанным инструментам и историческим состояниям; формулировка о будущих браузерных сценариях выше не отменяет уже подключённые компонентные сценарии. Текущий браузерный контракт — [performance_benchmark.md](../../docs/performance_benchmark.md); его описание прежнего модального размещения потребуется согласовать с реализацией нового стенда.

- У администратора оставить вкладку «Бенчмарк» в настройках только для выдачи/отзыва права обычной учётке. Не помещать туда запуск тестов. У обычной учётки убрать эту вкладку из настроек даже при наличии права.
- Пользователь открывает стенд кнопкой ribbon в центральной рабочей области. Сверху компактная панель: настройки, запуск, отмена, результаты, возврат к заметке. Параметры открываются отдельно, пояснения в подсказках при наведении и фокусе; ошибки и существенное состояние остаются видимыми. Буфер, курсор, Undo/Redo и обычное autosave заметки сохраняются.
- Внутри стенда слева тестовое дерево папок/заметок, всё оставшееся пространство занимает граф. Проверять создание синтетического набора, появление заметок, рендер/обновление дерева через рабочие компоненты, не декоративную имитацию. Изоляция от настоящего файлового дерева/vault; тестовые команды не выполняют реальные файловые операции. Серверное создание тестовых файлов потребовало бы отдельного сценария и согласования.
- Граф интерактивен во время проверки: перемещение, масштабирование, drag узлов и наведение. Различать автоматический воспроизводимый прогон и интерактивную нагрузку; отмечать режим и условия в отчёте. Не снимать лимиты и не называть стенд доказательством максимальной нагрузки всего проекта. Размер области графа сохранять: изменение геометрии меняет условия сравнения.
- Снизу закрепить прогресс: действие, прогрев/измерение, повтор и общее число завершённых повторов. Процент по завершённым повторам не прогноз оставшегося времени;100% только при успешном завершении очистки. Уход со стенда/смена аккаунта отменяют работу и блокируют поздний вывод.
- Результаты показывать отдельной модалкой после завершения/ошибки/отмены; открывать последний отчёт повторно кнопкой. Русские подписи, статусы, ошибки, условия, ограничения и формат чисел; таблица и раскрываемые подробности. Кнопки копирования и сохранения JSON. Экспорт сохраняет стабильные машинные ключи/ID/коды, не переводится с потерей совместимости.
- Не требовать vault для чисто синтетического теста. Отдельное условие доступа бенчмарка не ослабляет ограничения личных заметок/графа; запуск и выдача права сохраняют серверные проверки. Новые сценарии, события прогресса и публичные версии согласовать с тестами/отчётом. Адресные проверки у ассистента допустимо сократить; полный локальный набор, build и визуальный фидбек выполняет владелец. Не приписывать этим планам успешные прогоны.

## История результатов в БД и импорт — будущий отдельный этап

- Сохранение отчётов в БД с пользовательским названием прогона/правки, комментарием, датой, полной конфигурацией, составом и версиями сценариев, исходными повторами и статистикой, средой, режимом и условиями. Название правки не заменяет идентификатор версии.
- Сохранять полный SHA, заголовок и дату именно тестируемого коммита. Версионные данные включать в поставку и JSON; не подменять их текущим HEAD GitHub при сохранении/импорте. При неизвестной версии явно сохранять неопределённость, не угадывать. Метаданные импорта не являются доказательством исполнения указанного кода.
- Импорт JSON с другого, в том числе рабочего ПК: проверка формата/версии/размеров/значений, источник отчёта и время импорта отдельно от времени тестирования. Сохранить исходную среду и версию; отличать локально выполненный и импортированный прогон, учитывать повторный импорт. Не исполнять содержимое отчёта.
- Выбор прогонов и графики отдельных показателей по сценариям: медиана, p95 при достаточной выборке и прочие поддержанные метрики. Явно показывать рост/падение и смысл улучшения для конкретной метрики. Разные машины, корпуса, параметры, геометрию, версии сценариев и автоматический/интерактивный режим не выдавать за сопоставимые условия.
- Перед реализацией отдельно определить схему/миграцию/API, владельца и права доступа к отчётам, лимиты, срок хранения/удаление и резервное копирование. Не сохранять пароли, cookies, CSRF, личные тексты и секреты среды. Этот этап не входит в текущий UI-пакет и не разрешает менять БД автоматически.

## Общий конструктор строки дерева

assets/js/file_tree_view.js предоставляет WebVaultFileTreeView.apiVersion=1 и createButton(row,path,kind,level,active,expanded,rootLabel). Функция создаёт и добавляет только кнопку строки в переданный DOM-контейнер через его ownerDocument. kind=file/folder; level — целое1–64. Сохраняются nav-file-title/is-active, data-path/data-kind, role=treeitem, aria-level и aria-expanded папки. Имя выводится textContent; у файла снимается только конечный .md без учёта регистра. Корень по умолчанию «Хранилище», тестовый вызов может передать отдельную подпись.

Конструктор не читает учётку/vault и не назначает click/keydown/drag/контекстные команды. Обработчики, выбор, lazy-loading, сохранение буфера и файловые операции остаются у вызывающего кода. Это DOM-утилита, не валидатор серверного пути и не предоставление доступа к данным. Повторная загрузка той же версии сохраняет API; конфликт версии отклоняется.

Первоначальная отдельная часть337db746 не меняла загрузку application.js/file_tree.js и не переключала рабочее дерево на новый API. Адресная команда: node --test file_tree_view.test.mjs. Шесть тестов прошли у ассистента в изолированной Node-среде с тестовым DOM; это не полноценная проверка файловых команд или браузера.

## Изолированное тестовое дерево

benchmark_tree.js экспортирует renderBenchmarkTree({host,notes,createButton,expanded,onSelect}). Вызывающий код передаёт createButton из WebVaultFileTreeView версии1 и синтетические записи с path. Компонент не обращается к WebVaultCore, protectedApi, vault или файловым командам. Выбор вызывает только явно переданный onSelect; по умолчанию он ничего не делает. Это визуализация путей, не создание заметок на сервере.

Корпус ограничен300 заметками и300 папками, включая корень. Пути только под Bench/, конечное расширение .md, длина до180 символов и до16 компонентов; пустые компоненты, . и .., обратный слеш и дубликаты путей без учёта регистра отклоняются. Это ограничения тестовых данных, не замена серверного валидатора путей. Раскрыты корень и Bench по умолчанию; папки переключаются кликом/стрелками, Up/Down/Home/End перемещают фокус. snapshot возвращает files/folders/visibleRows/selected. dispose отключает обработчики и очищает только принадлежащий экземпляру контейнер.

DOM строится в отдельном fragment до замены отображения. Владение контейнером и поколение обработчиков не позволяют старому callback или старому disposer менять новый экземпляр. Ошибка первичного построения сохраняет прежнее дерево. Адресная команда: node --test benchmark_tree.test.mjs. Семь тестов прошли у ассистента с настоящим file_tree_view.js и тестовым DOM: общий конструктор, раскрытие/клавиатура, выбор, некорректный корпус, устаревший экземпляр, ошибка конструктора и освобождение. Это не браузерная геометрия, не полный test:all и не проверка сервера.

После подключения рабочего дерева владелец передал отдельный вывод6 успешных тестов и полный набор481/480 pass/0 fail/1 skip. Это результат до добавления benchmark_tree.js, не новые числа для этой части. Компонент пока не импортируется bundle и не включён в экран/каталог измеряемых сценариев; изменения вида сайта не ожидаются. Для этой добавленной части build/публикация не требуются, пока она не подключена; локально выполнить адресную команду и test:all. Подключение и измеряемый сценарий — следующая часть; БД, зависимости и установленный bundle не меняются.
