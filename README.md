# WebVault

Автономный браузерный сайт заметок для IIS: классический ASP.NET / .NET Framework, C#, HTML/CSS/JavaScript и MS SQL Express 2014. Markdown хранится в личных каталогах вне публичного сайта. ASP.NET Core не используется.

## Состояние

Рабочее развивающееся приложение: вход/администрирование, личные хранилища, папки, файловые операции, корзина с восстановлением, группы и drag с прокруткой, автосохранение, CodeMirror 6 и три режима Markdown. Пользователь проверил основные файловые сценарии и режимы на «00 — Markdown — Навигация». Полная совместимость с Obsidian и все негативные тесты не подтверждены. Delete/Ctrl+A дерева пока отложены как неработающие.

Новый этап: [импорт нескольких .md и экспорт одной заметки](docs/note_transfer.md) — исходники подготовлены, требует сборки и проверки. ZIP/папки/групповой экспорт ещё не реализованы. Интерактивные флажки, редактируемые свойства/таблицы, подсказки ссылок и другие уточнения — в [очереди задач](docs/next_steps.md), не считать готовыми.

## Установка и обновление

Публиковать только src/WebVault.Web, не корень Git, docs, tools или node_modules. DataRoot и рабочий Web.config не коммитить. На рабочий ПК переносить готовый JS; Node/npm для его запуска не нужны.

Миграции в database/install — 00–07. first_install.md описывает базу до 05; дополнения 06/07 читать отдельно по ссылкам выше. На существующей установке только ещё не применённые миграции после бэкапа БД/DataRoot, не запускать установку заново наугад.

Изменения tools/cm6 и его зависимостей требуют новой сборки по npm_build.md. Исходники в Git не означают обновлённый bundle. После обновления сохранить заметки и Ctrl+F5. npm test/build не заменяют проверку в браузере. Обычные JS/C#/CSS вне сборки сами по себе не требуют npm.

## Среда и данные

Цель: Windows 7 / .NET Framework 4.5 / Firefox 113, IIS и SQL Express 2014 на одной машине, работа без интернета и новых системных установок на рабочем ПК. Сборка — отдельно дома. Независимые установки не синхронизируются.

Не коммитить реальные заметки, вложения, DataRoot, бэкапы, пароли, рабочий Web.config и секреты. node_modules игнорируется; package-lock.json сохранять с соответствующим package.json. Готовый проверенный bundle можно включать в комплект переноса. История и внешние бэкапы не стираются кнопкой удаления заметки.

Каждый комплект обновляет профильную инструкцию и README/указатель при изменении шагов. Различать реализацию, пользовательскую проверку, ограничения и план; не отмечать непроведённые тесты пройденными.
