# WebVault

Автономный сайт Markdown-заметок для IIS: классический ASP.NET/.NET Framework, C#, HTML/CSS/JavaScript и SQL Express 2014. Личные файлы хранятся вне сайта; ASP.NET Core не используется.

## Текущее состояние

- Аккаунты и личные хранилища, файловые операции, группы, корзина, автосохранение, импорт/экспорт .md и ZIP.
- CodeMirror 6: исходник, динамический режим и чтение; индекс ссылок и граф.
- Свойства редактируются в dynamic/reading: chips, ссылки, подсказки значений и имён, добавление полей, безопасные преобразования типов.
- Общая история заметки: Undo/Redo и верхняя панель с SVG-кнопками. Исправлены отступы/исходные номера блоков и общая прокрутка.

История изменений — в CHANGELOG, области проверок — в предметных руководствах и документации проверок. Это не отчёт о полной регрессии или совместимости со всеми возможностями/темами/плагинами Obsidian. История undo не переживает повторное открытие заметки/страницы; общая схема типов остаётся в плане; календарь свойств имеет собственное тематическое оформление.

## Обновление и данные

Целевая среда: Windows 7, .NET Framework 4.5, Firefox 113, IIS и SQL Express 2014. Сборка JS выполняется на подходящем компьютере; Node/npm для запуска сайта не нужны. Публиковать src/WebVault.Web, не корень Git, tools, docs или node_modules. Изменения браузерных исходников CM требуют проверенного нового bundle и отдельной публикации; после переноса — сохранить заметки и Ctrl+F5. Docs-only не требует сборки/публикации сайта.

SQL 00–07 находятся в database/install; новая установка описана полностью в first_install.md. При обновлении применять только подтверждённо неприменённые скрипты после бэкапа БД/DataRoot. Не заменять рабочий Web.config шаблоном и не переносить чужие данные поверх своих.

Не коммитить настоящие заметки, DataRoot, вложения, бэкапы, секреты, рабочий Web.config или node_modules. Сохранять package-lock.json; проверенный bundle переносится отдельно или согласованным комплектом. История Git и внешние бэкапы не очищаются удалением заметки; установки не синхронизируются автоматически.

README содержит назначение, состояние и навигацию. История — в месячном changelog, ограничения — в профильных руководствах, требования — в next_steps; полная ревизия ещё продолжается. Прежний архивный README и его checksum удалены как больше не нужный исторический снимок, без нового архива взамен. Сохранённые [исторические свидетельства](docs/npm_build.md#исторические-свидетельства-рабочей-области) не являются результатами текущего HEAD.
