# WebVault

Автономный сайт Markdown-заметок для IIS: классический ASP.NET/.NET Framework, C#, HTML/CSS/JavaScript и SQL Express2014. Личные файлы — вне публичного сайта. ASP.NET Core не используется.

## Состояние
Работают аккаунты, личные хранилища, файловые операции, корзина, группы/drag, автосохранение и CM6 с тремя режимами. Пользователь подтвердил основные файловые сценарии, Markdown-режимы на «00 — Навигация», импорт/экспорт .md и ZIP. Delete дерева также подтверждён последним отзывом; Ctrl+A дерева ранее отмечен неработающим и остаётся ограничением. Полная совместимость с Obsidian не заявляется.

Новый этап: [общий индекс связей и граф](docs/note_graph.md). Исходники подготовлены, требуется npm install/test/build и браузерная проверка; это ещё не Obsidian API. Интерактивные флажки, свойства, таблицы, подсказки и прочие уточнения остаются в очереди.

## Обновление и среда
Публиковать только src/WebVault.Web, не корень Git, tools, docs или node_modules. Изменение tools/cm6/зависимостей требует сборки; исходники в Git не означают обновлённый bundle. Сохранить заметки, перенести готовый JS, Ctrl+F5. npm test/build не заменяют браузерную проверку. Node/npm на рабочем ПК для запуска не нужны.

SQL00–07 в database/install; first_install перечисляет базу до05, дополнения06/07 читать отдельно. На обновлении применять только неприменённые после бэкапа БД/DataRoot. Новый граф SQL/Web.config не меняет. Цель: Windows7/.NET Framework4.5/Firefox113, IIS/SQL Express2014 на одной машине, без интернета и новых системных установок на рабочем ПК; сборка дома.

Не коммитить реальные заметки, DataRoot, вложения/бэкапы, пароли, рабочий Web.config и секреты. node_modules игнорируется, lock сохранять с package.json; проверенный bundle можно переносить через Git. История/бэкапы не стираются кнопкой удаления. Независимые установки не синхронизируются автоматически.

Каждый комплект обновляет инструкцию и README/указатель; различать реализацию, пользовательскую проверку, ограничения и план.
