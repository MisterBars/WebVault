# Согласованные следующие задачи

[README](../README.md) · [Указатель](index.md). Список требований, не обещание готовности. Последние этапы: перенос .md/ZIP и граф проверены пользователем; новый Properties UI описан в properties_panel.md и пока требует сборки/проверки.

## Граф — отложенное развитие
Приблизить к графу Obsidian по поведению/внешнему виду и настройкам: фильтры, группы/цвета, отображение узлов/подписей/связей, параметры сил/раскладки, локальный граф. Перед реализацией сверить актуальный набор настроек оригинала; не обещать точную копию и не задерживать сейчас Markdown. Развить индекс: серверная/worker-обработка больших vault, более полные события, YAML-связи/aliases/теги, безопасный совместимый слой API. Текущий клиентский индекс не является готовым Obsidian API или поддержкой всех плагинов.

## Markdown и интерактивность
- Флажки задач [ ]/[x] и символы матрицы ☐/☑ — настоящие checkbox-контролы. Мышь переключает, текстовый курсор в маркере раскрывает исходник; код/escape не превращать в контролы. Активны также в read без свободного редактирования текста.
- Дата/время включения справа, UTC хранение/локальный показ, снятие убирает дату, повторное включение обновляет; формат/видимость позже в настройках. Это не аудит и не дата YAML-enabled.
- Списки: исходная разметка строки только возле маркера/текстового курсора, не весь список.
- Таблицы редактируются по ячейкам, общий undo/autosave, Tab/Shift+Tab с приоритетом открытой подсказки.
- Тематическое выделение CodeMirror и DOM без сплошного белого.
- Значки типов callout info/note/tip/warning/error/success/question и нейтральный fallback.
- Подсказки после [[ по личному индексу: фильтр, пути при одинаковых именах, стрелки/Tab/Enter/Escape, без дублирования ]].
- Свойства: после проверки первой панели добавить управление именами/типами/добавлением/удалением и схемой, не переписывать посторонний YAML.

## Файлы/настройки
Импорт/экспорт сделать проще: автоматическая проверка вместо отдельной кнопки, короткий итог и один запуск; сохранить безопасность/конфликты. Подбор нового имени заметки: учитывать все числовые суффиксы, предлагать максимальный N+1 с серверной защитой от гонки. Будущая папка новых заметок как пользовательская настройка. Корзина: проверить новый счётчик/расположение, избавиться от прежнего stale-сообщения; развитие восстановления pending-операций. Ctrl+A дерева ранее не работал и отложен; Delete позже подтверждён пользователем.

## Навигация и вкладки
Обычный клик/ссылка/новая заметка открываются в текущей вкладке. Назад/Вперёд по успешным открытиям на сессию, сохранение перед уходом, обрезание forward после нового перехода, очистка при смене пользователя. Открыть в новой вкладке — позже с несколькими документами; затем split view/две заметки рядом.

Следующий локальный кандидат: properties-autocomplete-03. Подсказки для списковых полей поступают из одноимённых (без учёта регистра имени) свойств других личных заметок, включая простые строковые значения. Текущая заметка исключена, выбранные точные значения не предлагаются. Поиск подстроки без учёта регистра; до 20 вариантов. В YAML сохраняется полное значение, включая [[target|alias]], не только подпись. Скалярные поля не получают меню в этом комплекте.

Данные добавлены в существующий личный note_index при его чтении заметок без отдельного прохода запросов. Используются существующие лимиты 300 заметок/20 MiB и лимиты графа; ошибка графа/индекса может сделать подсказки недоступными, но свободный ввод сохраняется. Первое открытие может ждать построения индекса; после изменений существующая invalidation заставляет перестроить его при следующем запросе. Локальные несохранённые изменения других вкладок не видны. Дополнительный серверный API не добавлен.

Меню открывается по фокусу/вводу; по умолчанию ни один пункт не выбран. Стрелки выбирают; Enter/Tab подтверждают выбранный пункт и добавляют его. Без выбора Enter добавляет введённый текст. Escape закрывает меню без очистки, следующий Escape очищает ввод по прежнему правилу. Клик выбирает вариант. IME не должен преждевременно подтверждаться. Смена заметки/пользователя/режима проверяется перед выдачей, потеря фокуса и удаление поля закрывают меню; события изменения индекса закрывают уже открытые варианты. Ошибка индекса показана в title поля, ручной ввод остаётся доступным.

CSS-контракт дополнен реальными собственными классами: .wv-property-suggestions (fixed listbox в body, не внутри обрезаемой колонки) и .wv-property-suggestion[aria-selected=true]. Ввод имеет role=combobox, aria-expanded/controls/activedescendant. Стиль wv-property-suggestions-style использует background-primary, background-modifier-border/hover/box-shadow, text-normal, font-ui-small/font-interface, radius-m/s. Цвет тени имеет запасное значение; совместимость тем не заявляется полной.

## Дополнение 22.10.2026: создание свойств, кандидат properties-add-04
Предыдущая панель chips/ссылок/автодополнения сохранена. Новый локальный кандидат добавляет строку-кнопку «＋ Добавить свойство» в dynamic/reading, в том числе у заметки без frontmatter. Форма предлагает стандартные tags/aliases/cssclasses (списки) и известные имена личного индекса со значками, позволяет ввести новое имя и начальный тип. Подсказки имён до 30 вариантов, каталог до 1000 имён; повторяющиеся имена текущей заметки исключаются из меню и проверяются перед записью без учёта регистра. Конфликт типов в разных заметках не разрешается автоматически: форма предупреждает, тип выбирается для новой записи. Общая схема типов для всего хранилища этим не реализована.

Типы создания: текст, простой строковый список, число, флажок, дата, локальные дата/время. Для даты/времени требуется начальное значение, системный picker пока сохранён; тематический календарь остаётся задачей. Пустой список создаётся как []; значение текста, распознаваемое текущим parser как дата, не выдаётся молча за текст: нужно выбрать подходящий тип. Типы уже существующих свойств пока не изменяются. cssclasses можно создать/хранить; применение CSS-классов к заметке не входит в комплект.

Запись через propertyAddChange и существующую транзакцию CM, с текущими защитами пользователя/заметки/буфера. Изменение вставляется перед закрывающей границей YAML; существующие поля, комментарии и тело не сериализуются. Если frontmatter нет, создаётся в начале с сохранением BOM и исходного тела. Незавершённый/ошибочный YAML, дубликаты, превышение лимитов и опасные числа отклоняются; результаты повторно разбираются. Undo документа после commit проверять в source. Несохранённую форму добавления перед сменой режима нужно завершить или отменить; другие черновики списков предварительно подтвердить.

В dynamic без YAML используется синтетический block-widget нулевой длины: он не заменяет текст, не получает фиктивный исходный номер и не входит в atomicRanges. В reading панель добавляется перед телом без свободного редактирования Markdown. Индекс дополнен propertyNames из YAML при существующем чтении заметок. Унаследованы лимиты и ошибки личного индекса/графа; при недоступности индекса стандартные имена и ручной ввод остаются.

Контракт тем: собственные .wv-property-add-button, .wv-property-add-form, .wv-property-name-picker, .wv-property-name-menu[role=listbox], .wv-property-name-option[aria-selected=true], .wv-property-type-icon, .wv-property-add-status, .wv-property-add-actions. Имя — combobox с aria-controls/expanded/activedescendant; сообщения role=status, форма с явными label. Стиль wv-property-add-style использует background-primary, background-modifier-form-field/border/hover, text-normal/muted/error, radius-s/m, input-radius и наследуемый шрифт. Это не гарантия совместимости любой темы.
