# Личные файлы и первый редактор

Статус: код подготовлен, не выполнен в IIS. Сообщение пользователя после этапа смены пароля принято как подтверждение основного сценария предыдущего комплекта, не всех негативных тестов.

## Установка этого этапа
1. Резервная копия БД. Получить исходники, сохранить локальные изменения.
2. После 00–04 выполнить database/install/05_user_vaults.sql в SSMS под администратором. Новая схема storage и таблица storage.UserVaults. Файловые операции не хранят текст в SQL.
3. Создать каталоги вне репозитория и сайта. Административный PowerShell:

```powershell
New-Item -ItemType Directory -Force -Path 'D:\WebVaultData\vaults','D:\WebVaultData\history'
icacls 'D:\WebVaultData' /grant 'IIS AppPool\WebVaultPool:(OI)(CI)M'
```

Проверить унаследованные разрешения каталога: не давать другим обычным пользователям Windows чтение личных файлов. Команда выше добавляет право пулу, но не убирает существующие широкие разрешения. Для реальной приватности администратор должен отдельно проверить ACL. Не удалять права SYSTEM/администраторов наугад. Не давать пулу изменение исходников сайта.
4. В существующий appSettings локального Web.config добавить только DataRoot с value D:\WebVaultData. Не заменять строку подключения и остальные секции. На другом ПК выбрать существующий локальный диск/путь. UNC/сетевые папки, junction/symlink и каталог внутри/над сайтом запрещены текущей реализацией.
5. Ctrl+F5, войти личной обычной учёткой, нажать Создать личное хранилище. Административная учётка не допускается к файловому API.
6. Создать Тест.md, написать текст, Сохранить, Перечитать файл. Затем проверить другую обычную учётку.

## Хранение
БД: storage.UserVaults(VaultId uniqueidentifier PK, UserId int unique FK auth.Users, CreatedUtc UTC). По одному хранилищу на пользователя. Идентификатор генерируется сервером, не зависит от логина. FK без каскада, роль приложения SELECT/INSERT/UPDATE без DELETE.
Файлы: DataRoot/vaults/<VaultId N>/*.md. Предыдущие версии: DataRoot/history/<VaultId N>/<случайный GUID>.md. История пока без интерфейса/метаданных исходного имени/очистки; для отладки можно исследовать текст копий, полноценное восстановление ещё предстоит. История не заменяет бэкап. Путь и VaultId клиенту не выдаются, UserId из тела запроса не используется.
Реестр вынесен в storage, а не notes: это связь владельца с каталогом, не индекс содержимого заметок.

## Реализовано
Создание пустого хранилища явным POST, список файлов только в корне, создание пустого .md, чтение UTF-8, исходный текст в textarea, ручное сохранение, предупреждение несохранённых изменений. Размер файла до 256 KiB, отправляемый текст до 131072 UTF-16 единиц, список до 500 файлов, имя до 100 символов. Это ограничения первого этапа, не заявленная ёмкость будущей версии.
Запрещены пути/разделители/обход каталогов/Windows-зарезервированные имена, управляющие символы и скрытые dot-файлы. Проверяются reparse points; импорт жёстких ссылок и недоверенных каталогов не поддерживается. Работать только с обычной локальной папкой под доверенным администрированием.
Markdown/HTML не исполняются: сейчас нет предпросмотра, YAML и специальные блоки сохраняются как текст. Новые файлы UTF-8 без BOM; существующий UTF-8 BOM сохраняется. При изменении сохраняется единообразный CRLF, если такой был в исходнике; иначе LF. Неизменившийся по нормализованным переносам текст не переписывается. Смешанные переводы строк могут нормализоваться — не обещать побайтовую совместимость после редактирования.

## API
api/notes/vault.ashx:
- GET action=list (по умолчанию): hasVault/files, ничего не создаёт;
- GET action=read&name=имя.md: name/text/version;
- POST action=init;
- POST action=create, name;
- POST action=save, name/text/version.
POST JSON с обычными X-WebVault-Request и X-CSRF-Token. Проверяются сессия, активность, мягкое удаление и отсутствие административной роли. В SQL-транзакции блокируется запись владельца/хранилища для сериализации веб-операций. На каждый запрос интерфейс обновляет me; смена аккаунта в другой вкладке не позволяет записать старый текст в новую учётку. При 401/конфликте во время сохранения текст остаётся в редакторе, скопировать перед перезагрузкой.

## Сохранение и ограничения конкурентности
Версия — SHA-256 исходных байтов. Несовпадение -> 409 note_changed_reload_or_copy, принудительной перезаписи нет. Временный файл и File.Replace с предыдущим содержимым в history. При работе через приложение операции сериализуются блокировкой БД. Прямые изменения файлов сторонними программами не подчиняются SQL-блокировке: одновременное редактирование с Obsidian/синхронизатором пока НЕ поддерживается. Остановить внешние писатели до работы в браузере. Это не готовая двусторонняя синхронизация.
Файлы и SQL не образуют общую атомарную транзакцию: при обрыве после записи проверять результат повторным чтением. Инициализация при сбое может оставить пустой каталог без записи БД; автоматического удаления таких каталогов нет, разбирать вручную после проверки реестра. Пропавшие зарегистрированные каталоги не создаются молча заново.

## Удаление пользователя
Мягкое удаление работает: запрет входа и отзыв сессий. Полное удаление аккаунта с хранилищем сейчас блокируется FK, API возвращает user_has_dependencies. Аккаунт без хранилища по-прежнему можно полностью удалить. НЕ отключать FK и не удалять реестр вручную: иначе останутся бесхозные файлы. Полноценная очистка файлов/истории/реестра должна быть разработана отдельным шагом; пользователь уведомлён об ограничении до этого комплекта.
