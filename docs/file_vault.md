## Область и доказательства

Текущее предметное руководство вместо отдельного описания первого редактора, интерфейса корзины и мультивыделения. База статической сверки —610b180b9cbc03ea1a65cdc58879a987c3993700. Полностью прочитаны пять файловых руководств, VaultHandler/FileMoveHandler/TrashHandler/TrashManagementHandler/NoteTransferHandler/PurgeUserHandler, application.js/file_tree.js/folder_features.js/trash_ui.js, editor.js/mode_slider.js/workspace_layout.js/transfer.js/transfer_zip.js/trash_ribbon.js и package.json. Это не новый запуск C#/SQL/Node/build/IIS/Firefox и не приёмка установленного сайта.

Подключение в исходниках: index.html загружает application.js, тот после account_features.js загружает file_tree.js. Дерево добавляет trash_ui.js и assets/vendor/webvault-cm6.js; сборка начинается с tools/cm6/editor.js. Редактор вызывает installTrashRibbon(), импортирует mode_slider.js, который подключает transfer.js. Наличие этих связей не доказывает актуальность опубликованного bundle. Старый folder_features.js описывает прежнюю навигацию; текущая цепочка application.js подключает дерево, а не этот файл.

Source/dynamic/reading, история редактора и автосохранение описываются профильными руководствами. Прежнее «только textarea, нет папок/корзины/предпросмотра/автосохранения» было статусом раннего комплекта, не текущим общим контрактом. Копирование/cut/paste не объявлять выполненными только по наличию move/rename; полный объём файловых команд сохраняется в backlog до отдельной сверки.

## Установка и границы хранения

Следовать актуальной последовательности SQL00–07 в first_install.md/deployment.md, не применять только раннюю миграцию05 к произвольной схеме.05 создаёт storage.UserVaults;07 добавляет журнал удаления и разрешение DELETE на реестр без отключения FK/db_owner. Перед изменениями — согласованный бэкап БД и DataRoot, сохранение черновиков и локальных правок.

DataRoot задаётся в существующем appSettings рабочего Web.config без замены строки подключения/прочих секций. Пример локальных каталогов и права пула:

```powershell
New-Item -ItemType Directory -Force -Path 'D:\WebVaultData\vaults','D:\WebVaultData\history'
icacls 'D:\WebVaultData' /grant 'IIS AppPool\WebVaultPool:(OI)(CI)M'
```

Это пример административной настройки, не выполненная команда и не универсальное имя пула/диска. Modify пулу не удаляет унаследованные широкие ACL: отдельно исключить чтение чужими обычными пользователями Windows. Не снимать SYSTEM/администраторов наугад, не давать пулу изменение исходников сайта. DataRoot — обычный локальный каталог вне сайта, не его предок; UNC/сетевой путь, junction/symlink/reparse запрещены. Доверенное администрирование и отсутствие сторонних писателей обязательны; hard links/недоверенные каталоги не заявлены безопасным импортом.

storage.UserVaults связывает один UserId с серверным GUID VaultId и CreatedUtc; GUID не зависит от логина. Данные — DataRoot/vaults/<VaultId N>, предыдущие версии — DataRoot/history/<VaultId N>/<случайный GUID>.md. Это реестр владельца в storage, не SQL-хранилище текста или индекс notes. FK не отключать; исходные права SELECT/INSERT/UPDATE расширены миграцией07. Клиент не назначает себе VaultId, UserId или серверный путь. Пропавший зарегистрированный каталог не создаётся молча; старые сиротские каталоги после сбоя init не связываются с владельцем наугад.

## Владение и пути

Личное файловое API требует обычную активную учётку без мягкого удаления/MustChangePassword и действующую сессию. Администратор приложения не получает личное файловое API. SQL-блокировки Users/UserSessions/UserVaults повторно проверяют владельца; клиентский protectedApi сверяет me, CSRF и передаёт X-WebVault-User. Move/trash/trash_manage/transfer отдельно сравнивают этот заголовок с текущим пользователем. UI не заменяет серверные проверки.

Пути относительны корню личного vault, компоненты разделены /. Нельзя абсолютные/UNC/device пути, backslash, пустые/скрытые компоненты, . и .., управляющие/недопустимые символы, крайние пробелы/точку и Windows-зарезервированные имена, включая CONIN$/CONOUT$. Проверяются существующие компоненты на reparse и граница root+разделитель без учёта регистра. Общие ограничения этих маршрутов:16 компонентов,180 символов относительного пути,100 в компоненте,240 полного пути. Корень не является перемещаемой/удаляемой записью.

## Создание, чтение и сохранение

api/notes/vault.ashx:

| Метод / action | Контракт |
| --- | --- |
| GET list&folder=... | hasVault/folder/files/folders; список ничего не создаёт, пути полные относительно vault. |
| GET read&name=... | name/text/version для вложенного .md. |
| POST init | Явное создание пустого личного хранилища. |
| POST mkdir, name | Создаёт одну папку, существующий родитель обязателен. |
| POST create, name | Пустой .md без перезаписи существующего. |
| POST save, name/text/version | Запись с контролем исходной версии, не принудительная перезапись. |

Записи — JSON с X-WebVault-Request/X-CSRF-Token. Лимиты VaultHandler:256 KiB исходных/сохранённых байтов,131072 UTF-16 единицы входного текста,500 нескрытых non-reparse элементов одного каталога. Последний счётчик учитывает и неподдержанные обычные файлы, хотя в files выводятся только .md. Это не общая ёмкость vault.

Чтение строгое UTF-8; новые файлы без BOM, существующий UTF-8 BOM при сохранении сохраняется. SHA-256 версии считается по исходным байтам. Несовпадение даёт409 note_changed_reload_or_copy, не last-writer-wins. При текстовом изменении единообразный исходный CRLF сохраняется, иначе используется LF; смешанные переносы могут нормализоваться. Неизменённый по нормализованным переносам текст не переписывается. Не обещать побайтовую идентичность после редактирования.

Запись использует временный файл/Flush/File.Replace с предыдущим содержимым в history. Эти копии пока без стабильного ID заметки, сопоставления rename/move и полноценного интерфейса восстановления/очистки; история не бэкап. SQL и ФС не одна атомарная транзакция. Потерянный ответ требует сверки результата; ошибка сохранения не повод очищать редактор. Блокировки приложения не защищают одновременное внешнее редактирование Obsidian/синхронизатором.

## Дерево, выбор и меню

Дерево лениво загружает каталоги и сохраняет раскрытые ветви. Обычный клик выбирает один элемент; файл открывается после сохранения dirty-буфера. Ctrl/Meta-клик меняет выбор без открытия, Shift-клик выбирает диапазон видимых строк. ПКМ внутри выбранной группы сохраняет выбор, вне группы выбирает один. Escape снимает выбор; Ctrl+A действует в дереве и выбирает видимые строки, Delete отправляет выбранное в корзину без confirm. F2 — одиночное переименование при фокусе строки. Это описанная реализация клавиатуры, не новый успешный браузерный тест.

Свёрнутые выбранные потомки остаются в выборе; изменение фильтра сбрасывает выбор. При подготовке операции выбранные дети выбранной папки исключаются. Счётчик выбранных строк поэтому не равен числу корневых операций. Групповые команды требуют multi:true и c.items; реестр WebVaultCommands.register возвращает disposer, повторный ID отклоняется. Это текущий внутренний реестр, не полный будущий API расширений.

Имена редактируются inline с Enter/Escape и сохранением ошибки в форме. Контекстное меню ограничивается окном, поддерживает стрелки/Escape/Tab и Shift+F10/ContextMenu. Описанный drop-обработчик находится на кнопке папки; требование drop всей области папки остаётся FILES-DROP-01, не объявлять его выполненным.

## Move/rename и группы

GET api/notes/move.ashx?action=stat&path=... возвращает kind/stamp. POST move/rename принимает path/destination/expectedStamp. Stamp описывает тип, относительный путь, длину и LastWriteTimeUtc элементов, а не хеш содержимого всего дерева. При изменении —409 source_changed_refresh.

Rename сохраняет родителя; move в себя/потомка, одинаковый путь или case-only rename отклоняются. Существующее назначение не перезаписывается, родитель обязателен; .md не превращается в другой тип расширения. Проверяются и будущие пути всех детей. Preflight:до2000 узлов,50 MiB суммарных размеров,10 секунд, ограничения глубины/длины. Журнал .wv-ops/<GUID>.json фиксирует Planned до move и Complete после него. Если move уже выполнен, но подтверждение не завершилось,503 move_result_uncertain_refresh_tree требует обновить дерево, не повторять вслепую.

Группа дерева —до100 корневых элементов, последовательные операции без общего отката. До старта проверяются владельцы, совпадения конечных имён и перемещение папки в себя/потомка; тот же каталог пропускается. Перед действиями сохраняется открытый документ, редактор временно блокируется. Успешные элементы снимаются с выбора, ошибки остаются. При401/session_changed/result_uncertain дальнейшие действия группы останавливаются; ошибка последующего refresh может потребовать ручной сверки. Успешный move обновляет открытый путь/текущую папку/раскрытие, но не переписывает входящие wiki-ссылки и не создаёт стабильную историю заметки.

Drag выбранной строки переносит группу. Автопрокрутка только #files:42px у края,до600px/с, остановка при выходе/drop/dragend/blur. Автораскрытия папки и отдельной drag-картинки нет; индикатор текстовый. Проверять неподвижный курсор у края, отмену и скрытый выбор отдельно.

## Отправка в корзину

POST api/notes/trash.ashx, action=trash/path/expectedStamp перемещает запись в .wv-trash/<GUID N> и записывает соседний JSON с operationId/source/kind/createdUtc/payload. Проверяется тот же тип stamp, до2000 узлов/50 MiB/10 секунд и допустимость пути назначения. Старый JSON без state трактуется как active. Скрытые дети удаляемой папки входят в операцию, хотя обычное дерево их не показывает.

В UI обычное удаление не требует confirm. Точный необратимый пункт меню сначала запрашивает подтверждение, затем отправляет выбранные элементы в корзину и purge по полученным ID. Частичный результат может оставить элементы в корзине. При trash_result_uncertain_refresh_tree не считать отсутствие ответа отсутствием перемещения. Удаление открытого файла/родительской папки согласуется с сохранением и состоянием редактора; восстановление файла не является Undo редактора.

## Просмотр, restore и purge

api/notes/trash_manage.ashx:GET list/stat/read, POST restore/purge. ID —32 строчных hex-символа, метаданные до8192 байтов; проверяются operationId/payload/kind. Token основан на JSON и атрибутах корня payload, не на хеше всего дерева. List —до500 JSON-записей; испорченные записи показываются ошибкой, не удаляются молча.

Корзина показывает исходный путь, тип/состояние и локально форматированную дату из createdUtc. Ctrl/Shift/ПКМ и клавиатура управляют выбором; двойной клик/Enter открывают папку либо исходный .md без редактора/autosave. Просмотр .md —до256 KiB, каталог —до500 отображаемых записей. Скрытые дети не отображаются, но входят в восстановление/удаление всей записи. Восстановления отдельных детей удалённой папки нет.

Restore возвращает всю запись по исходному или явно выбранному новому пути. Существующее назначение не перезаписывается; отсутствующего родителя нужно создать отдельно или выбрать существующую папку. Перед move проверяется дерево:до2000 узлов,глубина16,пути240,15 секунд preflight. Состояние restoring и destination записываются до перемещения. После сбоя restoring требует ручной сверки source/destination/payload по JSON; автоматическое завершение незаконченного restore не реализовано.

Purge требует confirm=true; состояние purging записывается до удаления. После частичного сбоя запись остаётся для явного повтора, restore для purging запрещён; purge restoring запрещён. Проверки reparse повторяются при обходе удаления; бюджет20 секунд отсчитывается тем же Stopwatch, что и preflight, это не дополнительные20 секунд после проверки. При trash_operation_incomplete_refresh изменения могли уже произойти: обновить корзину. SQL не откатывает ФС.

Групповой restore UI —до100 записей. Clear обрабатывает снимок показанных ID последовательно, без wildcard и без новых записей, появившихся после снимка; ошибки/пропуски отражаются в результате. Не переносить сюда буквально гарантию остановки группы дерева: operate корзины собирает ошибки иначе, с повторной проверкой владельца/окна. Большая корзина и malformed JSON требуют отдельного обслуживания, а не обхода лимитов. История заметок и внешние бэкапы purge/clear не очищаются.

## Кнопка корзины и счётчик

trash_ui.js создаёт кнопку, а installTrashRibbon() переносит её в ribbon, оформляет SVG и показывает число записей list, не рекурсивных файлов. После trash/restore/purge планируется обновление; sequence/пользователь защищают от устаревшего ответа. При ошибке счётчик показывает?, не ложный0; смена пользователя сбрасывает прежнее число. Без vault сообщается о необходимости создать хранилище. Старое уведомление «В корзине:…» скрывается модулем ribbon; не обещать видимую кнопку быстрого восстановления только по наличию onTrashed в базовом trash_ui.js. Доступное восстановление остаётся в окне корзины. Браузерная геометрия/позиция и взаимодействие с темой требуют проверки опубликованного комплекта.

## Полное удаление владельца

Не путать purge записи корзины, старый SQL-purge пользователя и отдельное удаление владельца с файлами. Старый user_manage purge не очищает владельца с vault и может вернуть user_has_dependencies; это не запрет всех способов удаления. Текущий application.js направляет «Удалить вместе с заметками» в api/admin/purge_user.ashx с явными userId/rowVersion/confirmationLogin/deleteFiles=true.

PurgeUserHandler использует журнал storage.PurgeJobs, повторную проверку администратора/цели/FK, два каталога vaults/history и состояние Complete только после очистки и SQL-удаления. Мягкое удаление, точный логин и версия обязательны; себя/администратора удалить нельзя. RootHash защищает повтор на другом DataRoot. Детальные стадии, лимиты10000 узлов/24 уровня/240 символов/около20 секунд, RetryRequired и проверка схемы —[отдельный контракт](folders_and_purge.md). Внешние бэкапы/аудит/reset/purge-журнал не очищаются, безопасное стирание носителя не обещано.

## План регрессии

Проверять только на безопасной копии БД/DataRoot и отдельными тестовыми учётками, не на единственной копии MyVault. Следующее —план, не выполненные тесты:

1. SQL05/07 и общая последовательность00–07, ACL/DataRoot и рабочий Framework4.5; обычные учётки изолированы при одинаковых именах. Чужой userId/GUID не меняет владельца, без входа401, администратору личное API403, ограниченная сессия не получает доступ.
2. Создание/вложенные папки/переименование/переходы вверх и к файлам не теряют dirty-буфер; русский UTF-8/BOM/CRLF/YAML/код/wiki сохраняются. Чужой HTML не исполняется как произвольный документ.
3. Save/reopen/предыдущая history-копия, две вкладки и409, потеря ответа/истечение сессии/смена пароля без потери текста; rename логина не меняет vault.
4. Абсолютные/../служебные/зарезервированные/reparse пути, существующее назначение, case-only rename, папка в потомка, предельные размеры/число узлов/время.
5. Ctrl/Meta/Shift/ПКМ/видимый Ctrl+A/Delete/F2/Escape, папка+ребёнок,100+ корней, частичный успех/неопределённый результат, drag/автопрокрутка/отмена/Firefox113 и геометрия области drop.
6. Trash открытого файла/папки, старые и испорченные JSON, просмотр .md/папок, count/?/смена пользователя, restore-конфликт и отсутствующий родитель, группа/clear со свежей записью из другой сессии.
7. Purge cancel/confirm, частичный отказ ACL, перезапуск с purging/restoring, явный повтор и ручная сверка; история/внешние бэкапы нетронуты.
8. Удаление отдельного тестового владельца: точный логин/версия/роль/CSRF, незавершённое задание и повтор, отсутствие Users/UserSessions/UserVaults и двух каталогов при Complete; соседние каталоги и новый пользователь с повторно занятым логином не затронуты.

Для функциональных правок —адресные проверки, test:all, build после успеха, отдельная публикация и браузер по npm_build.md; Node-набор не тест C#/SQL/IIS. Для этого docs-only сведения ничего из этой цепочки не запускалось.
