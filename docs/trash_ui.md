# Корзина: интерфейс и восстановление
Статус: код подготовлен, C#/IIS/браузер не проверены. SQL и сборка CodeMirror не меняются. Сделать бэкап DataRoot, обновить сайт и Ctrl+F5.
Кнопка Корзина открывает список (до 500 JSON-записей), исходный путь, UTC дату и состояние. Старые метаданные без state считаются active. Папки можно просматривать, .md читать как исходный текст без редактора/автосохранения. Восстановление всей записи: путь редактируется в строке, перезаписи нет, отсутствующего родителя нужно создать самостоятельно или выбрать существующую папку. Восстановление отдельных детей удалённой папки пока не добавлено.
В корзину — без confirm, после успешного ответа появляется Восстановить. Необратимое удаление в ПКМ сначала перемещает в корзину, затем удаляет конкретный ID; при сбое промежуточный элемент может остаться в корзине. Подтверждение только перед необратимым действием и очисткой. Очистка обрабатывает снимок показанных ID последовательно, не включает новые записи, ошибки/пропуски учитываются и отображаются, malformed записи не удаляются молча. Нет общего wildcard delete. История заметок и внешние бэкапы этими действиями не очищаются.
Защита: текущая личная учётка/CSRF/сессия, блокировки Users/UserVaults, валидированный ID, ограниченные пути без служебных сегментов/reparse, token метаданных и корня payload (не хеш всего дерева). ОС-администратор и внешние изменения вне блокировок не входят в гарантию. Restore проверяет дерево/пути перед move. Purge перед удалением записывает purging; после частичного сбоя запись остаётся для явного повтора, восстановление purging запрещено. Restoring после сбоя требует ручной сверки source/destination/payload по JSON; автоматическое восстановление незавершённого restore не реализовано. SQL не откатывает файловые операции. Ошибку trash_operation_incomplete_refresh нельзя трактовать как отсутствие изменений: обновить корзину.
Лимиты: 500 записей на список/папку, 2000 узлов на операцию, 256 KiB на .md просмотр, 15с проверка/20с удаление. Большая корзина/повреждённые JSON требуют отдельного обслуживания, UI не обещает очистить их полностью. Скрытые дети в браузере корзины не показаны, но входят в восстановление/удаление папки.
Проверить на копиях: удаление без вопроса; быстрое восстановление; список ранее удалённых; папки и .md; конфликт имени; отсутствующий родитель; удаление открытого файла/папки; purge cancel/confirm; частичный отказ ACL; очистка с ошибками/новым элементом из другого профиля; разные пользователи/истёкшая сессия; ../ и reparse; перезапуск после частичного purge/restore. CodeMirror и Live Preview не меняются.
