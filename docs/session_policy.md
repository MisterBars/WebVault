## Область и границы

Политика собственной смены пароля/ника, временного пароля и отзыва сессий; здесь же собраны проверки базовой авторизации из прежнего TEST_CHECKLIST.md. Источники сверены на базе 6aaccba7dbdaeacc21d26cda986219b8745ec85a. Это документационная консолидация, не новый прогон SQL/IIS/браузера и не доказательство безопасности всей установки.

Правила сохранения текущей сессии ниже заменяют прежние указания об обязательном выходе после собственной смены пароля/ника в ТЗ 002, password_change.md и account_security.md. Административный сброс пароля цели — другое действие, оно отзывает все сессии цели. Для описанного пути требуется применённая миграция 06; эта редактура не добавляет SQL и не меняет Web.config. Применение миграций и обновление сайта — по first_install.md.

## Временный пароль

После успешного login и подтверждения me.mustChangePassword клиент передаёт только что введённый пароль в форму собственного изменения. Он подставлен в masked currentPassword как readOnly, фокус на newPassword. Сервер не возвращает пароль и по-прежнему проверяет его при изменении. После отправки формы/выхода/закрытия настройки очищается поле; пароль не хранится в Web Storage, URL или журнале. Нет обещания криптографического стирания JS-памяти. После перезагрузки при сохранённой ограниченной сессии требуется повторно ввести временный пароль: извлечения его из БД нет.

## Таблица действий

- Админ reset пароля цели: все сессии цели отозваны, MustChangePassword=1, админ остаётся в своей.
- Админ rename логина и/или DisplayName цели: все сессии цели отозваны, даже если изменено только имя.
- Пользователь меняет свой DisplayName: другие SessionId отозваны; текущий SessionId/токены сохранены.
- Пользователь меняет свой пароль, включая временный: другие SessionId отозваны; текущий SessionId сохранён, но TokenHash/CsrfTokenHash заменяются случайными новыми токенами в той же транзакции. Cookies обновляются после commit, клиент перечитывает me и продолжает без нового login.
- Созданная дата и абсолютный срок текущей сессии не сбрасываются при вращении токенов. Обычный me сохраняет прежнюю политику продления по активности.

Текущая сессия — запись SessionId, привязанная к cookies браузерного профиля, не отдельная вкладка. Вкладки с общими cookies продолжают ту же текущую сессию и получают новый CSRF через me перед записью. Отдельный браузер/приватный профиль/устройство имеет другую сессию и теряет доступ. Серверный отзыв проверяется следующим защищённым запросом; мгновенная блокировка уже показанного экрана без запроса не обещается.

## Надёжность

Собственная смена пароля атомарно обновляет пароль, текущие токены и отзыв остальных сессий в SQL. Ошибка до commit откатывает всё. При потере ответа после commit cookies могут не обновиться: тогда может потребоваться вход уже новым паролем. Не откатывать пароль через SQL наугад. Backend проверяет действительность текущей сессии и текущий пароль по-прежнему; предзаполнение не является обходом проверки.

Собственный ник и отзыв остальных сессий объединены в транзакцию. Все административные изменения в user_manage проходят прежние проверки роли/CSRF/RowVersion. Старые административные маршруты создания/мягкого удаления не ослабляются.

## Проверки смены пароля и сессий

Все пункты — воспроизводимый план, не отчёт о выполнении. Перед функциональным обновлением сохранить заметки и получить согласованные файлы без сброса локальных изменений; после отдельной публикации сайта выполнить Ctrl+F5. Для одной документационной правки обновление сайта не требуется.

- [ ] Войти временным паролем: он подставлен, курсор на новом поле.
- [ ] После смены сразу доступны заметки, логин повторно не требуется.
- [ ] Открыть две независимые браузерные сессии: собственный пароль сохраняет текущую, вторую отзывает.
- [ ] Проверить, что TokenHash/CsrfTokenHash текущего SessionId изменились, AbsoluteExpiresUtc не обнулился.
- [ ] Свой ник сохраняет текущую и отзывает другие сессии.
- [ ] Админ меняет только DisplayName цели: все её сессии отозваны.
- [ ] Админ reset отзывает все сессии цели и требует новый личный пароль.
- [ ] Неверный текущий/админский пароль не меняет пароль/сессии.
- [ ] При ошибке RowVersion нет частичного изменения.
- [ ] Несохранённая заметка в текущем окне не теряется после собственной смены пароля.
- [ ] После reload ограниченной сессии пароль не подставляется из хранилища.

## Проверки базовой авторизации

Перенесённый план охватывает setup, вход/выход, CSRF, сроки сессий и ограничения размещения. Проверять сначала в тестовой установке, затем в целевой среде .NET Framework 4.5; не использовать реальные учётки и данные для разрушительных сценариев. Чекбоксы не означают, что проверки уже выполнены. Численные пороги и HTTP-коды здесь сохранены как ожидаемые результаты исходного чек-листа; их актуальное соответствие реализации ещё требует сверки.

- [ ] me без cookies: 401 JSON, не перенаправление.
- [ ] Setup без включения: 403 setup_disabled.
- [ ] Неверный ключ setup: 403, пользователи не создаются.
- [ ] Правильные данные setup: 201, один администратор в auth.Users.
- [ ] Два одновременных корректных запроса setup не создают двух пользователей.
- [ ] Повторный setup при оставленном включении: 409.
- [ ] После установки setup выключен, ключ удалён из локального Web.config.
- [ ] Неверный пароль: 401 без cookies сессии.
- [ ] Правильный пароль: 200, me показывает пользователя.
- [ ] Обновление страницы сохраняет вход; секреты не попадают в URL/localStorage.
- [ ] В БД нет исходного пароля/токена сессии/CSRF-токена.
- [ ] POST без X-WebVault-Request, с чужим Origin или неверным типом содержимого запрещён.
- [ ] Logout без/с неверным X-CSRF-Token запрещён; с верным отзывает сессию.
- [ ] После logout старая сессия не принимается.
- [ ] IsActive=0 запрещает me и новый вход. Вернуть IsActive=1 тестовой учётке после сценария.
- [ ] Пять ошибок пароля блокируют вход на 15 минут; после истечения возможен вход. Не путать с отдельным IP-лимитом 429.
- [ ] Истечение по бездействию, абсолютный срок и RevokedUtc проверяются.
- [ ] HTTP с другой машины не допускает авторизацию; сетевое размещение не принимать без HTTPS-проверки.
- [ ] Права пула остаются без db_owner.
- [ ] Диагностика health.ashx по-прежнему работает; временные подробности локально убраны.

Для переноса этого чек-листа новый SQL-скрипт не требуется. Не вставлять пользователя вручную; setup проверять только в предназначенной для этого тестовой установке. Отсутствие опубликованных секретов и корректные права/HTTPS проверяются отдельно от наличия документации.

## Граница с удалением пользователя

Исходный комплект политики сессий ещё не реализовывал полное удаление пользователя с заметками и сохранял FK/user_has_dependencies. Это историческая граница комплекта, не утверждение об отсутствии последующей реализации. Согласованная очистка каталога заметок, истории и реестра, отслеживаемые стадии/повторная очистка и явное подтверждение относятся к [folders_and_purge.md](folders_and_purge.md) и дальнейшей сверке требований; этим переносом они не закрываются. Уникальность NormalizedLogin обеспечивается SQL UNIQUE; мягкое удаление сохраняет логин, полное освобождает. Ники не уникальны.
