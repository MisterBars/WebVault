# Таблицы

## Область и статус

Единое руководство по редактированию, ссылкам, задачам и структуре Markdown-таблиц. Контракты сверены с документами 18a–18h и основными модулями таблиц на базе e5dea981b4a40ba6e6313ff3a305115b8902a6d3. Это статическая сверка, не новый запуск тестов/сборки или полная браузерная регрессия. Наличие кода удаления осей не закрывает TABLE-AXIS-DELETE-01: полная браузерная проверка 18h в доступных источниках не подтверждена.

Markdown — единственный источник данных. UI выполняет транзакции CM, а не хранит отдельную таблицу вне заметки. Source остаётся исходником; reading не получает текстовый редактор ячеек или destructive controls. Checkbox в reading — отдельное разрешённое действие, не свободное редактирование тела.

## Допустимая структура и ограничения

Таблица должна иметь заголовок и строку-разделитель, одинаковое число ячеек во всех строках, распознаваемый delimiter каждого столбца. Заголовок не является строкой данных. Лимиты модели: 50 столбцов, 200 строк данных; для изменений — до 131072 символов заметки. Это ограничения редакторского пути, не разрешение обходить серверные лимиты.

Ragged/неоднозначные/слишком большие таблицы не нормализуются автоматически и не получают обхода защит. Если модель или сопоставление DOM с source отказывает, остаётся отображение и редактирование через source; причина может находиться в title. Отдельный текст ячейки не поддерживает физические CR/LF: Shift+Enter и многострочная вставка отклоняются, TSV/matrix paste не реализован. Длинный однострочный Markdown переносится только визуально.

Разделитель --- означает default темы/renderer, :--- — слева, :---: — центр, ---: — справа. Существующее выравнивание не переписывается массово. Неэкранированный pipe разделяет ячейки; pipe внутри значения требует структурного экранирования. Модель учитывает чётность предшествующих backslash.

## Создание и редактор ячейки

На отдельной строке source/dynamic /table или /таблица предлагает 2 столбца, заголовок и 2 строки данных с --- alignment. Enter/Tab/мышь применяют completion, Escape закрывает без замены. В dynamic открывается первая ячейка; в source остаётся курсор в Markdown. Команда не применяется в code/YAML/списках/цитатах и проверяет сессию/режим.

В dynamic таблица остаётся отрисованной при CM selection внутри её диапазона. Клик текста ячейки, Enter/F2 на сфокусированной ячейке открывает textarea только этой ячейки. В ней Markdown значения; снимается только структурное экранирование pipe, прочие backslash не декодируются. Подтверждение экранирует новые pipe, сохраняет уже корректные и проверяет форму/ширину/выравнивание результата. Меняется диапазон выбранной ячейки, не вся заметка; prefix/suffix и соседние данные сохраняются.

| Действие | Результат |
| --- | --- |
| Tab / Shift+Tab | Подтвердить и перейти к следующей/предыдущей ячейке. |
| Enter | Подтвердить и перейти ниже в том же столбце. |
| Escape | Отменить черновик, не записывая его. |
| Ctrl/Cmd+S | Подтвердить ячейку и запустить существующее сохранение. |
| Граница таблицы | Вернуть фокус CM, не создавать строки автоматически. |

Открытый picker имеет приоритет клавиш над навигацией таблицы. IME не должен преждевременно подтверждаться. Несколько одновременных черновиков не поддерживаются. В textarea действует native undo, а общая история документа блокируется незавершённым черновиком. Подтверждение — отдельный input.table/isolateHistory шаг, прежнее автосохранение.

Перед переходом, сменой режима и сворачиванием вызывается finishTableDraft; наружный pointerdown и blur также пытаются подтвердить. При отказе действие блокируется, ввод остаётся. Если commit перестроил DOM, обработчики должны продолжить на актуальной ячейке или потребовать повтор действия, не писать в старый диапазон. Перед кликом по ссылке после изменения ячейки надёжно сначала Enter/Ctrl+S: перестройка может превратить первый клик в фокус ячейки. Несохранённый черновик также учитывается beforeunload.

## Wiki-ссылки и source completion

В textarea ячейки [[ открывает общий picker: фильтр имени/пути, мышь/стрелки, Enter/Tab/Escape, выделение подписи после выбора, Ctrl+Space для обновления. Выбор меняет черновик; обычное подтверждение сохраняет его. Popup в body исключён из наружного pointerdown auto-commit, при закрытии редактора контроллер уничтожается.

Внутри textarea адрес и подпись разделены обычным pipe, в source сохраняется структурно экранированный pipe. Сохраняются число столбцов, alignment и соседний текст. Общий createLinkCatalog по умолчанию разделяет WeakMap-кэш на объект WebVaultCore между телом/свойствами/таблицами. Вызов с явными лимитами остаётся отдельным. Defaults каталога — 300 заметок/300 папок; обход получает пути, не тексты заметок/граф. Смена владельца, invalidation, generation/snapshot и stale response проверяются.

Property picker использует необязательные enabled/validateValue/menuLabel, не меняя defaults свойств. В code/скрытом комментарии ячейки меню выключено; при проверке завершённости links эти диапазоны маскируются, чтобы literal [[ не блокировал сохранение. Эта локальная политика picker не означает реализованные комментарии во всём Markdown.

Source completion в распознанном table-блоке ограничен текущей ячейкой; незавершённое [[ не захватывает ]] соседней. Строка alignment не принимает completion. Pipe вставки экранируется только внутри таблицы, выбор подписи учитывает итоговую длину. Защиты code/YAML/comments, пользователя/режима/snapshot сохраняются.

Старые уже сохранённые wiki с неэкранированным pipe не чинятся автоматически: структура неоднозначна. Исправлять конкретную ссылку в source либо создавать заново в корректной ячейке, не выполнять массовую regexp-замену заметок. Дефект вне таблицы требует отдельного примера, не считается исправленным этим правилом.

## Выравнивание столбца

В dynamic над заголовком при hover/focus доступно ⋯: По умолчанию/Слева/По центру/Справа. Меняется только нужная ячейка строки-разделителя; количество дефисов, прочие байты и значения сохраняются. Повтор текущего варианта — no-op. Одна input.table.align/isolateHistory транзакция, Undo/Redo и прежний autosave.

Перед меню завершается черновик; после изменения документа меню ищется на актуальном DOM. Controls не включают редактор заголовка и исключены из наружного pointerdown. Escape закрывает; стрелки/Home/End выбирают; Tab/focus доступны. Черновики свойств, readonly/busy/stale doc не обходятся. В reading меню отсутствует. Локально сверху отведены 22px, это не глобальный отступ всех Markdown-блоков.

## Checkbox и время ячеек

Одна задача в начале ячейки: ☐/☑ или [ ]/[x]/[X], далее допустимы подпись/Markdown. Три ячейки одной строки имеют независимые диапазоны и timestamps. Несколько checkbox в одной ячейке, символ посреди текста, code/escape/wiki-подпись/Markdown-ссылка не становятся задачами только из-за символа.

Dynamic/reading используют настоящий input checkbox. Меняются только символ и suffix выбранной ячейки: `<!--wv-task:UTC-ISO-с-миллисекундами-->`. Полный UTC хранится в Markdown, локальное время показывается под checkbox, title содержит UTC; у списков время остаётся справа. Снятие удаляет свою отметку, повторное включение создаёт новую. Старый checked без даты и ручное изменение source не получают вымышленного времени; это не аудит.

Символ и время меняются одной input.task/isolateHistory транзакцией; Undo/Redo возвращают ту же дату вместе с состоянием. Соседние ячейки, комментарии, alignment, пробелы, тело/YAML сохраняются. Некорректные/дублированные timestamps отключают контрол до исправления source. Callback проверяет doc/user/path/режим/права/readOnly/busy/черновики, видимый актуальный DOM и совпадение всей source-таблицы.

При черновике ячейки pointerdown по checkbox блокируется до наружного auto-commit: сначала Enter/Ctrl+S или Escape. Click не включает textarea. Незавершённые свойства блокируются общей history policy. Headless/частичный host без полного user/note/doc создаёт disabled checkbox без записи; отсутствие window не должно приводить к исключению. Не исключать исходный table_stamp_dom тест и не ослаблять его assertions.

Parser сопоставляет td/th tokens с исходными ячейками и снимает ошибочную списковую task-аннотацию. Неподдержанные таблицы не переписываются ради checkbox. Перед снятием task-префикса stripTaskStampTokens удаляет только подтверждённый marker текущей задачи из последовательности text-tokens, в том числе разделённый между ними; tokens не мутируются, code/прочие comments/invalid metadata не удаляются. Поэтому уже отмеченная задача должна показывать дату без сырого marker, без повторного переключения. В source/textarea marker остаётся данными, не скрывается глобальным CSS.

## Добавление, перенос и hover

В dynamic ＋ снизу добавляет пустую строку, ＋ справа — столбец с заголовком и ---; открывается первая новая ячейка. Добавление в произвольную позицию и автоматическое расширение по Tab не реализованы этим контрактом.

⋮⋮ слева от строк данных и над столбцами: drag показывает границу вставки, запись только при drop. Перенос со сдвигом, header в тело не переносится; столбец несёт header/alignment/все значения, строка — все ячейки. UTC и escaped wiki не пересчитываются. Своя позиция/no-op/отмена drag не меняют документ, перенос между таблицами не принимается, DataTransfer не содержит содержимого.

Для клавиатуры сначала сфокусировать ⋮⋮ кликом или Tab, затем Alt+↑/↓ для строки данных, Alt+←/→ для столбца — одна позиция. В textarea этот shortcut не действует. После клавиатуры фокус на ручке, после drag — ячейке, после добавления — textarea новой ячейки. aria-keyshortcuts/focus-visible описывают доступное управление.

Непрерывные прозрачные hitbox связывают ячейку с controls: верхняя зона 22px на ширину header, левая первоначально 22px на высоту строки; при × слева резерв расширяется до 44px. Alignment находится выше верхней зоны по z-index. Клик пустого поля не редактирует ячейку, mousedown ручки не отменяется для native drag. При удалении осей min-width ячейки 70px разделяет ×/⋮⋮/⋯. Геометрию высоких строк/узких колонок/scroll проверять в браузере.

Перед структурной операцией finishDraft; если изменён doc — повтор на актуальном DOM. Guards canWrite/canStart и source snapshot сохраняются. Одна input.table.structure/isolateHistory транзакция на add/move; соседний текст, хвостовые пустые строки, EOL в позициях строк и raw-сегменты сохраняются. Для крайней пустой ячейки при необходимости добавляется внешний pipe. Повторный parse проверяет значения/alignment и лимиты. Reading/source новых controls не получают.

## Удаление таблицы и осей

В dynamic «Удалить таблицу» доступно при hover/focus корректно разобранной таблицы. Тематический HTML dialog показывает размер и предупреждение; начальный фокус — Отмена. Escape/Отмена не создают удаления; если native dialog недоступен, удаления без подтверждения нет. Controls/dialog не запускают textarea, reading destructive control не получает.

Удаляются только исходные строки выбранной таблицы и один её завершающий EOL, не соседние разделительные пустые строки. Одна input.table.delete/isolateHistory транзакция и autosave. Undo возвращает значения/alignment/ссылки/checkbox/UTC, Redo удаляет; история не переживает повторную загрузку. Без соседнего текста заметка может стать пустой. Неподдержанную моделью таблицу редактировать/удалять через source.

Отдельные × у строки данных/столбца используют подтверждение с Отмена по умолчанию и не draggable. Строка удаляется со всеми ячейками, столбец — с header/alignment/значениями/UTC; остальные значения проверяются после parse, timestamps/links не пересчитываются. Последнюю строку данных удалить можно: остаются header+delimiter и ＋. Последний столбец удалить нельзя — disabled ×, использовать удаление всей таблицы. Для одной колонки добавляются внешние pipe, иначе parser может перестать видеть таблицу.

Каждое удаление оси — одна input.table.structure/isolateHistory операция, фокус соседней ячейки без textarea. Чужие текст/YAML/таблицы и пустой хвост не нормализуются. До диалога подтверждается черновик; если doc изменился, повторить на актуальном DOM. При подтверждении повторно проверить expected doc/source/canWrite/canStart. Не обходить занятость, readonly, сессию и черновики свойств.

2. /table и /таблица, границы completion, исходный/dynamic/reading режимы, соседние YAML/текст/другие таблицы и CRLF.

6. Metadata не видна на уже включённых задачах без повторного переключения, source/textarea её сохраняют; списковые задачи с подписью/без подписи тоже без сырого marker. Исходный table_stamp_dom и headless host-кейсы не исключены.
