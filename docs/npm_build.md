## Назначение и среда

Каноническая инструкция сборки CM6. Сборка выполняется на подходящем разработческом ПК с Node.js/npm; интернет нужен для получения зависимостей. На целевом Windows 7 Node/npm и node_modules для запуска сайта не нужны. Сайт работает с локальным bundle, не через CDN.

Исходники: tools/cm6. Команды определены в [package.json](../tools/cm6/package.json). Выход: src/WebVault.Web/assets/vendor/webvault-cm6.js. Это браузерный код с зависимостями и подключёнными стилями, не данные заметок и не серверный C#. Сборка esbuild использует format=iife, target=firefox113 и legal-comments=inline. Версия компонента в package.json не доказывает версию установленного сайта.

## Подготовка

Сохранить заметки и локальные изменения, получить согласованный коммит по инструкции переноса. Все Node-команды выполнять из D:\project\WebVault\tools\cm6, не из корня репозитория:

```powershell
Set-Location D:\project\WebVault\tools\cm6
node --version
if ($LASTEXITCODE -ne 0) { throw 'Node unavailable; stop' }
npm --version
if ($LASTEXITCODE -ne 0) { throw 'npm unavailable; stop' }
```

Нужен Node с поддержкой параметров --test и --test-concurrency, а также требований установленных зависимостей. Конкретная минимальная версия здесь не назначается. При engine/синтаксических ошибках проверить фактическую версию; не менять runtime целевого ПК ради сборки.

Если зависимости уже установлены и manifests не менялись, установку пропустить. npm install/ci не являются обязательным шагом обычной правки редактора или документации. Не удалять lock и не обновлять зависимости автоматически.

Для первой установки из согласованного package-lock.json либо отдельно согласованной чистой установки:

```powershell
npm ci
if ($LASTEXITCODE -ne 0) { throw 'Dependency installation failed; stop' }
```

Если lock отсутствует или не соответствует package.json, остановиться и сверить manifests. npm install допускается при отдельно согласованном создании/изменении зависимостей; он может изменить lock. Проверенный package-lock.json сохранять вместе с package.json, node_modules не коммитить.

## Тесты перед сборкой

Для функционального изменения сначала выполнить адресные тесты затронутых модулей, указанные в конкретном комплекте. При любом провале остановиться. Универсальный сокращённый набор не заменяет адресные проверки.

Затем полный автоматический набор:

```powershell
npm run test:all
if ($LASTEXITCODE -ne 0) { throw 'Full test suite failed; do not build' }
```

[run_all_tests.mjs](../tools/cm6/run_all_tests.mjs) обнаруживает обычные верхнеуровневые *.test.mjs в tools/cm6, сортирует их и запускает текущим Node с --test --test-concurrency=1 без shell glob. Вложенные каталоги, другие расширения и браузер автоматически не включаются. Использовать штатную команду, не node --test *.test.mjs. Ошибки обнаружения, пустой набор, ошибки запуска и сигналы дают ненулевой код; код завершения тестового процесса передаётся вызывающей оболочке.

npm test запускает только markdown.test.mjs, transfer_zip.test.mjs, note_index.test.mjs и properties.test.mjs. Его можно использовать как сокращённую проверку, но не вместо test:all. Старые числа успешных тестов не являются результатом нового HEAD. Не ослаблять assertions и не игнорировать провалы ради сборки.

### Самопроверка runner и защита от ложного успеха

runAllTests запускает отдельный процесс текущего Node через process.execPath с абсолютными путями тестов, shell:false и stdio:inherit. Файлы передаются одному запуску с --test-concurrency=1; это не shell glob и не отдельная команда на каждый файл. Отсутствующий/нечисловой код завершения также считается ошибкой.

independentTestEnv создаёт копию окружения без ключей NODE_TEST_CONTEXT независимо от регистра имени. Родительский process.env не меняется; PATH/Path, NODE_OPTIONS и остальные переменные сохраняются. Это важно при вызове runner из самотеста node:test: наследование worker-контекста может привести к пропуску вложенного запуска с предупреждением «node:test run() is being called recursively within a test file. skipping running files.» и ложным кодом 0. Нельзя считать такой пропуск успешным выполнением fixture или лечить его ослаблением assertions. Причина исторически воспроизведена под Node v20.20.1, не установлена как Windows-специфичная или дефект Markdown.

[test_all.test.mjs](../tools/cm6/test_all.test.mjs) проверяет обнаружение/порядок файлов и пустой набор, параметры процесса, передачу провалов, ошибки запуска/сигналы/отсутствующий status, сохранность родительского окружения. Реальные временные fixture должны действительно исполниться: тест проверяет их имена и TAP-итоги, отсутствие предупреждения о пропуске и код 1 от намеренного провала. TAP принудительно включён только для захваченных fixture-процессов самотеста, не для всего пользовательского запуска.

При изменении runner из D:\project\WebVault\tools\cm6 сначала выполнить адресную проверку, затем полный набор; блок останавливается при провале:

```powershell
& {
    Set-Location D:\project\WebVault\tools\cm6
    node --test test_all.test.mjs
    if ($LASTEXITCODE -ne 0) { throw 'Runner self-tests failed; stop' }
    npm run test:all
    if ($LASTEXITCODE -ne 0) { throw 'Full test suite failed; stop' }
}
```

Изменение только runner/самотестов не требует npm install, сборки browser bundle или публикации сайта. Если одновременно изменён браузерный код, действуют обычные условия сборки ниже. Наличие пяти самотестов или их прежний изолированный успех не доказывает успешный полный набор текущего WebVault. История исправления и результатов — в [октябрьском changelog](changelog/2026-10.md), не новый отчёт о запуске.

## Сборка и проверка артефакта

Только после успеха адресных тестов и test:all:

```powershell
npm run build
if ($LASTEXITCODE -ne 0) { throw 'Build failed; keep previously verified bundle' }
$bundle = Get-Item ..\..\src\WebVault.Web\assets\vendor\webvault-cm6.js -ErrorAction Stop
if ($bundle.Length -eq 0) { throw 'Bundle is empty; stop' }
$bundle | Select-Object FullName, Length, LastWriteTime
```

Проверить, что файл относится к нужной сборке; существование и время файла сами по себе не доказывают корректность. Сохранить уведомления лицензий зависимостей. Не обходить ошибки разрешения обязательных библиотек через external: bundle должен оставаться автономным.

## Публикация и браузер

Публикация отделена от Git и сборки. Сохранить заметки, резервные копии сайта, БД и DataRoot, рабочий Web.config и ACL. Перенести согласованный комплект src/WebVault.Web, включая нужные JS/CSS/handlers и проверенный bundle. Не заменять рабочий Web.config шаблоном и не переносить чужой DataRoot поверх своего. Не публиковать корень Git, .git, docs, tools или node_modules в IIS.

После публикации выполнить Ctrl+F5 и отдельную проверку на копии заметки: загрузка CM без интернета, ввод/русский текст/IME/emoji, source/dynamic/reading, свойства/ссылки, Undo/Redo и автосохранение, затем сценарии конкретного исправления. Целевой браузер Firefox 113 проверять отдельно. Успешные тесты или build не доказывают работу DOM, IIS, всех тем и всего Markdown. Рабочий резервный textarea не подтверждает загрузку CodeMirror.

## Диагностика и границы

- npm не найден: проверить установку/PATH на сборочном ПК.
- PowerShell блокирует npm.ps1: использовать npm.cmd с теми же аргументами, не ослаблять execution policy вслепую.
- Ошибка install/ci: сохранить вывод и manifests, не собирать с неизвестным набором зависимостей.
- Ошибка тестов: сохранить первый провал, итоговую сводку, HEAD и версии Node/npm; следующие шаги не выполнять.
- Старый вид сайта: проверить фактический путь IIS, перенос нового bundle и кеш.
- Новая сборка ломает ввод: сохранить текст отдельно и вернуть ранее проверенный комплект сайта/bundle; БД наугад не откатывать.

Изменения браузерных исходников tools/cm6 и используемых ими модулей требуют нового bundle для публикации. Изменение только test scripts не означает необходимость публикации сайта. Для docs-only пересборка CM не требуется; обычные файлы сайта вне сборочных исходников публикуются по составу конкретного комплекта. Сборка не публикует сайт автоматически.
