# Сборка браузерного JavaScript через npm

[README](../README.md) · [Все инструкции](index.md) · [Возможности редактора](live_preview_blocks.md).

## Где и зачем

Собирать на домашнем/разработческом компьютере с Node.js/npm и интернетом для загрузки зависимостей. На рабочий Windows 7 переносится готовый сайт с bundle; Node/npm и node_modules там для работы сайта не нужны. Серверная установка IIS/SQL — отдельный процесс: first_install.md.

Исходники: `tools/cm6`. Текущие команды задаются его package.json. Результат: `src/WebVault.Web/assets/vendor/webvault-cm6.js`. Файл объединяет редактор, зависимости и подключённые стили; это не файл заметки и не серверный C#.

## Первая сборка или изменение зависимостей

Сохранить заметки и локальные изменения. После получения нужного коммита из корня проекта:

```powershell
cd D:\project\WebVault\tools\cm6
node --version
npm --version
npm install
```

Выполнять следующую команду только после успешного завершения предыдущей:

```powershell
npm test
```

Если тесты прошли:

```powershell
npm run build
```

package.json должен быть совместим с установленным Node. Для текущих тестов нужен Node с поддержкой `node --test`. При engine/синтаксических ошибках проверить фактическую версию и требования зависимостей; не устанавливать новый runtime на рабочий ПК ради сборки.

`npm install` создаёт/обновляет package-lock.json. Сохранить его вместе с соответствующим package.json для повторяемых сборок. Не удалять lock автоматически ради устранения ошибки. Не коммитить node_modules.

## Повторная сборка

Если node_modules уже установлен и зависимости не менялись, достаточно:

```powershell
npm test
npm run build
```

Если нужна чистая установка зависимостей и есть согласованный package-lock.json:

```powershell
npm ci
npm test
npm run build
```

Эти строки — последовательные шаги: при ошибке остановиться. npm ci требует lock, соответствующий package.json; если lock отсутствует или package.json изменён, сначала использовать npm install и проверить обновлённый lock.

## Проверка результата и перенос

После успешной сборки из tools/cm6:

```powershell
Get-Item ..\..\src\WebVault.Web\assets\vendor\webvault-cm6.js | Select-Object FullName, Length, LastWriteTime
```

Проверить, что файл существует, непустой и относится к новой сборке. Переносить весь необходимый обновлённый сайт `src/WebVault.Web`, включая JS/CSS/обработчики из комплекта и новый bundle. Не заменять рабочий Web.config шаблоном и не переносить чужой DataRoot поверх своего. Не публиковать корень Git-репозитория, tools, docs или node_modules в IIS. Сохранить необходимые уведомления лицензий зависимостей; build настроен сохранять legal comments inline.

После установки — Ctrl+F5. Проверить на копии заметки ввод, исходный/динамический/читаемый режимы, автосохранение и Ctrl+Z. npm test проверяет только включённые тесты, не доказывает работу DOM/CodeMirror в Firefox 113. Успешный build также не заменяет браузерный тест.

## Если что-то не работает

- `npm` не найден: сборочные инструменты недоступны в этой оболочке. Проверить установку/PATH на домашнем компьютере.
- Ошибка PowerShell при запуске npm.ps1: можно вызвать npm.cmd с той же командой; не требуется ослаблять системную execution policy вслепую.
- install завершился ошибкой: сохранить вывод; не выполнять build с неизвестным/старым набором зависимостей.
- test завершился ошибкой: не считать сборку принятой. Сообщить текст ошибки и коммит.
- Сайт выглядит по-старому: проверить перенос именно нового bundle, путь сайта в IIS и обновление кеша.
- CodeMirror отсутствует: сайт может оставить резервный textarea. Наличие рабочего textarea не подтверждает загрузку CM.
- Новая сборка ломает ввод: сохранить текст отдельно, вернуть ранее проверенный комплект сайта/bundle, не откатывать БД наугад.

## Когда npm не нужен

Если менялись только обычные файлы сайта вне tools/cm6 и зависимостей сборки, пересборка CM сама по себе не требуется. Если менялись tools/cm6/editor.js, mode_slider.js, markdown_renderer.js или package.json — нужна новая сборка. На компьютере без интернета запускать готовый bundle, а не рассчитывать на CDN.
