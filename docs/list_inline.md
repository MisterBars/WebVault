## Область и границы

Единое руководство по корневым inline-спискам и задачам. Документы и текущие list_inline_model.js, list_inline.js, task_model.js, task_ui.js, markdown_renderer.js статически сверены на базе 3c476feea551e195bb7489fd4f16cfeac3e83b0b. Новые Node/CM/DOM/Firefox/IIS/build-проверки не запускались; полный editor.js и все пути вложенных контейнеров этим чтением не аудированы. Описанный контракт не полная готовность Markdown.

В source остаётся обычный Markdown. В dynamic текст поддержанного корневого списка остаётся редактируемым CM-текстом; маркер, wiki, checkbox и UTC-метка имеют независимые диапазоны. Reading не получает свободное редактирование тела, но поддержанные флажки используют защищённую транзакцию документа. Табличные задачи — отдельные модели/контролы, см. tables.md, не расширение этой грамматики на любую ячейку.

## Строки и локальное раскрытие

inlineListRows(text,block) получает уже разобранный markdown-it bullet_list_open/ordered_list_open; не ищет списки глобальным regexp по заметке. Для не-list возвращает null, для list — массив строк, включая пустой, даже если отдельная часть не поддержана. Сложное содержимое пункта не должно превращать весь корневой список в цельный BlockWidget; интеграцию decorate проверять отдельно.

Начала пунктов берутся из list_item_open.map. Локальный разбор маркера допускает пробелы/tabs, -/+/* или 1–9 цифр с . либо ), затем пробел/tab. Сохраняются отступ и исходные строковые номера; ненумерованный маркер показывается •, нумерованный — записанным номером. Пустые строки/продолжения остаются CM-текстом, не фиктивным пунктом. Диапазоны — JS/CM UTF-16 с offsets исходника; CRLF не нормализуется в заметке ради отображения.

Декорации replace создаются отдельно для частей, inclusive:false. Пустой курсор на границе или внутри части раскрывает её; непустой selection раскрывает пересекаемый диапазон. Другие части/строки не должны раскрываться целиком. Клик маркера или Alt+клик wiki переводит курсор в её реальный исходник при неизменном документе и не-readOnly; обычный клик ссылки вызывает существующий onNote. Это намеренное раскрытие по действию, не принудительная парковка курсора в начало блока.

Wiki-диапазоны сопоставляются с разобранными wv_wiki токенами и их target/подписью, вывод подписи через textContent. Обычный клик переходит, Alt+клик редактирует. Парсинг wiki может пропускаться локально рядом с code/link/image/html, backslash/backtick/%%/HTML comment; embed не превращается в обычную ссылку. Флажок/корректная служебная метка отделены от этого локального ограничения. Скрытые разделы заголовков не должны получать невидимые inline-контролы поверх закрытого тела.

## Грамматика задач и время

В начале тела пункта после маркера поддержаны [ ]/[x]/[X] и ☐/☑, после них пробел/tab или конец строки. Обычная bullet задачи скрывается, показывается настоящий input[type=checkbox], не статический символ под видом функции. Отдельный ☐/☑ вне спискового префикса этим parser не покрыт.

UTC-метка располагается в конце первой физической строки задачи:

```markdown
- [x] Сделано <!--wv-task:2026-10-23T17:39:00.123Z-->
```

Это пример формата, не результат прогона и не дата реальной заметки. Требуется канонический ISO UTC, совпадающий с Date.toISOString(), включая миллисекунды. Перед комментарием один структурный пробел; хвостовые пробелы/tabs входят в диапазон метки. Некорректная дата, нераспознанная или дублированная служебная отметка делает задачу invalid и блокирует переключение до исправления исходника. Чужие обычные комментарии не должны удаляться как timestamp.

toggleTaskChanges проверяет исходную строку/снимок и маркер. Включение заменяет [ ] на [x] либо ☐ на ☑ и ставит now.toISOString(); снятие удаляет связанную метку, повторное включение ставит новое время. Markdown-код флажка и suffix — одна input.task транзакция с isolateHistory.of('full'), одна операция Undo/Redo и штатное autosave. Итоговый клиентский текст не более 131072 UTF-16 единиц в этой ветке.

Ручное изменение Markdown не создаёт автоматического аудита/времени; старой выполненной задаче без timestamp дата не выдумывается. Отметка не журнал аудита и не YAML enabled/локальный datetime свойства. Dynamic/reading показывают localTaskTime с локальными датой/временем до секунд справа; time.dateTime/title содержат полный UTC. Точность хранения не урезается ради внешнего вида.

## Reading и защитные проверки

markdown_renderer привязывает taskForLine к исходной первой строке inline-токена и исключает табличные ячейки из обычной модели задач, используя отдельный tableTaskForCell. При отрисовке stripTaskStampTokens удаляет подтверждённую служебную метку из tokens до снятия task-префикса; код/прочие комментарии/invalid metadata не должны пропадать. Флажок и, для checked+корректной метки, время добавляются общими контролами. Полный текст/исходник остаётся доступен, данные не прячутся навсегда.

makeTaskCheckbox удерживает ожидаемые doc/user/path и требует текущий WebVaultCM6 view, тот же документ/пользователя/путь, доступную запись истории без blockedByDraft, не-readOnly, mode dynamic/reading, guard контроллера, подключённый DOM без скрытого предка. Старый/скрытый контрол не пишет. Начальное disabled учитывает invalid или отсутствие host/doc/user/path; остальные ограничения повторно проверяются при действии, не только по внешнему виду checkbox. Отсутствие window/полного host — не повод обходить guard или выдавать исключение; общий host-fix описан в истории таблиц.

Проверять busy/readonly/черновики/forced password/смену сессии и заметки через действующую историю/интеграцию приложения. Наличие локальных guards не самостоятельное доказательство всех серверных прав. Ошибки устаревшей строки/метки показываются без частичной записи.

## Ограничения и открытые задачи

LIST-INLINE-01, TASKS-UI-01, TASKS-TIME-01/02 сохранены в backlog; наличие кода не закрывает весь объём. Bold/em/code и другие сложные части dynamic могут оставаться исходником локально, не вызывая цельного fallback всего списка. Не объявлены полностью оформленными вложенные block-контейнеры, списки внутри цитат и все continuation-строки; matrix вне списков требует отдельного объёма. Links/BR/images, comments и точное клавиатурное попадание сверять по реальным контекстам.

Тематическое оформление/формат показа времени и глубина дата/минуты/секунды/без времени — TASKS-TIME-02. Не путать независимый checkbox списка с несколькими задачами одной табличной ячейки. Сохранять Enter/Backspace/Tab, мультивыделение, исходные номера/прокрутку/folding/свойства/календарь/общую историю и неизменный Markdown.

## DOM/CSS и диагностика

Маркер .wv-list-inline-marker, ссылка a.wv-list-inline-link[data-wv-note], style id wv-list-inline-style; text-muted, text-accent с interactive-accent fallback, underline/перенос длинного пути. Задачи: .wv-task-checkbox, .wv-task-time, .wv-task-item; style id wv-task-style, text-muted/interactive-accent/font-ui-smaller, круглый checkbox/видимый focus/disabled и time справа. Совместимость всех тем не заявлена.

Текущая метка installInlineListStyle — window.__WV_LIST_INLINE_TEST='list-inline-17b'. Метка означает загрузку ветки JS, не версию релиза/пройденные тесты/исправленные стрелки. Перед диагностикой сверять исходники, отдельную публикацию bundle и конкретный сценарий.

## Воспроизводимые проверки

План, не новый успешный прогон. Для функциональной правки из D:\project\WebVault\tools\cm6:

```powershell
& {
    Set-Location D:\project\WebVault\tools\cm6
    node --test list_inline_model.test.mjs list_inline.test.mjs markdown_dom.test.mjs task_ui_host.test.mjs table_stamp_dom.test.mjs
    if ($LASTEXITCODE -ne 0) { throw 'Targeted list and task tests failed; stop' }
    npm run test:all
    if ($LASTEXITCODE -ne 0) { throw 'Full suite failed; do not build' }
    npm run build
    if ($LASTEXITCODE -ne 0) { throw 'Build failed; do not publish' }
}
```

После отдельной публикации/Ctrl+F5 на копии данных:
1. Пройти стрелками сверху через каждый пункт к следующему заголовку и обратно без перескока списка/раскрытия всех строк. Структурный тест не доказательство вертикального движения CM.
2. Редактировать текст одного пункта, войти в маркер/checkbox/wiki, выйти и проверить локальность раскрытия соседних частей. Нумерованный/ненумерованный/вложенный/смешанный список, отступы, пустые строки и продолжения.
3. Wiki со своей подписью: обычный/Alt-клик, [[ меню, выделение подписи, Undo/Redo и сохранение/reopen. Source/reading не получают непредусмотренного свободного редактора.
4. Checkbox [ ]/[x]/[X]/☐/☑ в dynamic/reading: включение/снятие/повтор, local time/UTC title, canonical suffix исходника, общий Undo/Redo обоих изменений и autosave. Старые checked без метки, invalid/двойная метка, code/escape/обычный comment.
5. Смена doc/user/path/mode, detached/hidden DOM, busy/readOnly/черновик/ограниченная сессия и отсутствие host не создают запись устаревшим callback.
6. Bold/code/links/images/escape/comments рядом, выделение через строки/несколько курсоров, Enter/Backspace/Tab, folding/номера/геометрия/прокрутка, свойства/календарь/удаление/таблицы без потери текста.
