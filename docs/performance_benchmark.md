## Вход и оформление

Кнопка с локальным SVG-таймером в ribbon открывает раздел «Бенчмарк» существующего settingsModal; тот же раздел доступен в его навигации. Общее/Учётная запись сохраняются. benchmark.html — совместимый переход на index.html?benchmark=1, не отдельный неоформленный экран. Подключение через account_features.js независимо от загрузки CM6.

Используются стили оболочки workspace.css/application.css и текущая тема, без отдельного body или iframe. DOM: #benchmarkButton, #benchmarkTab, #settingsBenchmarkPanel.vertical-tab-content[role=tabpanel]; .wv-benchmark-options/actions/output. Только эти элементы дополняет benchmark.css: токены form-field/text-normal/border/input-radius, шрифт inherit; две колонки полей переходят в одну до650px. Таблица показывает итог, подробный JSON свёрнут. Палитра и дизайн оболочки не меняются. View-only атрибут на кнопках исключает принудительный click-save; открытие не вызывает save/open/discard и не использует app.run. Проверка наличия атрибута/DOM-fixture не заменяет реальный браузерный прогон.

Смена пользователя/CSRF, закрытие настроек или уход на другой раздел отменяют запуск и очищают приватный вывод; устаревшие ответы не публикуются. Отдельная отмена — кнопкой. Повторный выбор активного раздела не перезапускает тест. Переключение не сбрасывает CM-состояние, буфер, курсор или историю заметки. Обычное фоновое autosave не отключается и не ускоряется ради бенчмарка.

## Область и API

Первый фиксированный ID http.synthetic.read версии1: защищённый синтетический HTTP-ответ, разбор JSON и точная проверка содержимого. Это не дерево, открытие/сохранение заметки, Markdown, индекс или UI-ready; CPU/память/серверные стадии недоступны. Node измеряет другой предмет. Несколько браузерных ID/групп/overrides пока не реализованы. Во время повторов нет auth/me, записей заметок, настроек, паролей или сессий; данные только синтетические. При обычном открытии настроек сохраняется штатное поведение аккаунтного UI.

api/benchmark.ashx — классический BenchmarkHandler; только POST с WebApi.Prepare/Post/RequireUser(write:true), JSON/Origin/CSRF. Неизвестные поля и неверные типы отклоняются; произвольные URL/SQL/код/пути не принимаются. Миграция08 добавляет nullable auth.Users.BenchmarkGrant: NULL — запрет. Администратор выдаёт/отзывает право обычной цели с RowVersion и повторной проверкой своей сессии в транзакции. Выдача — активной неограниченной цели, отзыв — также отключённой/удалённой/ограниченной обычной цели. UI выбирает активные неудалённые записи из первых200 пользователей, текущий флаг права не показывает; после изменения обновляет список. Пароли/сессии/файлы не меняются; RowVersion меняется. Новая выдача создаёт новое поколение и не оживляет старый запуск.

start: repetitions1–100, warmup0–10, sizeKiB1–256, поколение проверяется при регистрации. Один живой запуск на владельца, до32 записей AppDomain, TTL120 секунд. step проверяет владельца/SessionId, действующую сессию/поколение до и после формирования ответа, точный очередной index, минимум50 мс между принятыми шагами. Чужой runId —404. Отзыв проверяется по SQL; принятый до отзыва ответ может уже передаваться по сети.

cancel удаляет только собственную запись той же действующей сессии, допускается после отзыва отдельного права; не purge и не файловое удаление. Запуски в памяти: recycle теряет их, другой IIS worker может дать404; для воспроизводимого прогона нужен один worker. Разрешения остаются в SQL. Просроченные записи убираются при следующем start/cancel или recycle; максимум32. Автовосстановления и слепых повторов нет.

## Измерение и отчёт

Клиент: timeoutMs1000–30000, последовательные повторы с паузой50 мс, AbortSignal в fetch, общий предел120 секунд. Время включает HTTP/JSON/проверку тела; проверка deadline после завершения исключает поздний pass. Отмена HTTP не доказывает отсутствие принятого шага. error/timeout/cancelled раздельны; неопределённая очистка — unconfirmed, иначе успешный запуск становится incomplete. Очистка пытается завершиться отдельно, без слепого повтора; при смене аккаунта новая сессия не используется для старого запроса.

Времена в ms, прогрев отдельно; сырые повторы, медиана/min/max/MAD; p95 nearest-rank только от100 успешных измеряемых повторов. Частичная статистика не означает успех всего запуска; прогрев не обещает холодный старт. Сохраняются конфигурация, версии, runId, browser userAgent. installedBenchmarkVersion=1 — протокол, benchmarkUIVersion=2 — интерфейс, не версия всего сайта; sourceMainSha неизвестен.

Экспорт JSON явный, без текстов заметок/токенов/CSRF/абсолютных путей. Постоянного серверного хранилища результатов и автоматического срока хранения экспортов нет. Экспорт хранит/удаляет владелец вне Git и сайта. До/после нужны одинаковые данные/настройки/сценарии и сопоставимая среда. Это не оптимизация и не приёмка сайта.

## Публикация и проверки

Миграция08 устанавливается вручную после00–07 и бэкапа БД на тестовой установке, не при запуске теста. Для UI-исправления повторять её не требуется. Web.config, зависимости/lock, SQL и CM6 bundle этим исправлением не меняются. Публиковать согласованные файлы сайта, не docs/tools/database. Для первоначального сервера нужны App_Code/BenchmarkHandler.cs и api/benchmark.ashx; для интерфейса — account_features.js, benchmark_page.js, неизменённый benchmark_core.js, benchmark.css и совместимый benchmark.html. Обновить кеш браузера. Сначала адресные тесты, затем test:all; CM6 build для runtime JS/CSS не требуется, публикация — отдельное действие.

Клиентский механизм: node --test benchmark_browser.test.mjs; встраивание: node --test benchmark_integration.test.mjs. Модельные DOM/transport-fixtures не подтверждают геометрию, стиль, Firefox, SQL или защиту в IIS. До UI-исправления владелец предоставил итог415 тестов/414 pass/0 fail/1 skip и успешный вывод SQL08; это не новый test:all UI-пакета, не приёмка C# и не замер. Браузерные тесты прежней страницы не проводились из-за оформления. Визуальная приёмка исправления пока не выполнена.

На тестовой установке проверить: кнопку и раздел в обеих ролях, Общее/Учётная запись и клавиатуру, тему/узкий экран/читабельность; dirty-буфер/курсор/Undo без форсированного save; закрытие/отмену/смену аккаунта. Серверный план остаётся открытым: анонимный/forced-change/без права, start/step после отзыва, чужой runId/другая сессия, regrant старого ID, неверные CSRF/Origin/метод/типы, RowVersion, частые/повторные/параллельные шаги, TTL/recycle и неопределённый ответ. Наличие guards не доказательство прохождения. Полная PERF-ADMIN-01 остаётся открытой.
