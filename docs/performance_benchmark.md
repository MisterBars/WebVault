## Область

Отдельная страница benchmark.html, открываемая в новой вкладке. Рабочий редактор, заметки, настройки и сессии во время повторов не изменяются. При открытии страницы auth/me получает текущую учётку/CSRF обычным механизмом входа. Первый ID http.synthetic.read версии1 измеряет защищённый синтетический HTTP-ответ, JSON и проверку точного содержимого. Это не замер дерева, открытия/сохранения заметки, Markdown, индекса или готовности UI. Время Node-набора — другой предмет.

## Право и сервер

IHttpHandler BenchmarkHandler, api/benchmark.ashx, только POST с WebApi.Prepare/Post/RequireUser(write:true), JSON/Origin/CSRF. Неизвестные поля и неверные типы отклоняются; URL/SQL/код/пути не принимаются.

Миграция08 добавляет nullable auth.Users.BenchmarkGrant: NULL означает запрет. Администратор выдаёт/отзывает право обычной учётке с RowVersion и повторной проверкой своей сессии в транзакции. Выдача разрешена активной неограниченной цели, отзыв допустим и для отключённой/удалённой/ограниченной обычной цели. UI первой версии выбирает только активные неудалённые записи из первых200 пользователей существующего API. Текущий флаг права в списке не показан. Изменение права меняет RowVersion; после него список обновляется. Пароли, сессии и файлы не меняются. Новая выдача создаёт новое поколение разрешения и не оживляет старый запуск.

start проверяет право обычной учётки, параметры и поколение при регистрации. Один живой запуск на владельца, до32 записей AppDomain, TTL120 секунд, repetitions1–100, warmup0–10, sizeKiB1–256. step проверяет владельца/SessionId, точный очередной index, сессию и разрешение до/после формирования ответа; между принятыми шагами минимум50 мс. Чужой runId —404. Отзыв проверяется по SQL, не по памяти worker; принятый до отзыва ответ может уже передаваться по сети.

cancel безопасно удаляет только собственную запись той же действующей сессии, в том числе после отзыва отдельного права. Никакого файлового удаления/purge. Нет слепого повтора неопределённого шага или очистки. Записи запуска в памяти: recycle их теряет, другой IIS worker может вернуть404. Для воспроизводимого прогона использовать один worker; разрешения остаются в SQL. Просроченные записи убираются при следующем start/cancel или recycle, максимум32 записи. Автовосстановления нет.

## Клиент и отчёт

Настройки повторов/прогрева/объёма и timeoutMs1000–30000. Один фиксированный сценарий; реестр нескольких ID/групп и их overrides в браузерной части пока не реализованы. Повторы последовательны с паузой50 мс, fetch получает AbortSignal и таймаут, общий клиентский предел120 секунд. Проверка времени после JSON/проверки тела исключает запоздавший pass. Отмена HTTP не доказывает отсутствие серверного шага. Ошибки/timeout/cancelled различаются; неподтверждённая очистка отмечается unconfirmed, а иначе успешный запуск становится incomplete.

Время в ms включает HTTP/JSON/проверку, не UI-ready. Прогрев отдельно; сырые повторы, медиана/min/max/MAD, p95 nearest-rank только от100 успешных измеряемых повторов. Частичная успешная статистика не означает успех всего запуска. Конфигурация, версии, runId и browser userAgent сохраняются. installedBenchmarkVersion=1 — версия протокола модуля, не версия всего сайта; sourceMainSha неизвестен. CPU, память и серверные стадии не измеряются. Прогрев не обещает управляемый холодный старт.

Экспорт JSON — явное действие пользователя. Текст заметок, токены, CSRF и абсолютные пути в отчёт не входят. Серверного постоянного хранилища результатов нет; экспорт хранит/удаляет владелец вне Git и сайта. Автоматического срока хранения экспортов нет. Сравнивать только одинаковые данные/настройки/сценарии и сопоставимые условия; это не оптимизация и не приёмка сайта.

## Установка и проверка

Сначала бэкап БД, затем вручную миграция08 после00–07 на тестовой установке. Рабочий Web.config не заменять. Отдельно публикуются согласованные App_Code/BenchmarkHandler.cs, api/benchmark.ashx, benchmark.html, assets/js/benchmark_core.js и benchmark_page.js. Не публиковать docs/tools/database. Bundle CM6 не изменён. Администратор открывает benchmark.html и выдаёт право; обычный пользователь открывает её в новой вкладке. Кнопки в основном workspace пока нет.

Адресные тесты из tools/cm6: node --test benchmark_browser.test.mjs, затем npm run test:all. Подготовленные14 клиентских transport-fixture тестов прошли в Node; это не C#/SQL/IIS/Firefox. Компиляция C#, миграция, полный test:all этого пакета, публикация и браузерные прогоны не подтверждены. Не начинать замеры до устранения ошибок.

Обязательная проверка на тестовой установке: анонимный/forced-change/без права; прямые start/step после отзыва; чужой runId/другая сессия того же владельца; regrant со старым runId; неверные CSRF/Origin/метод/типы; конфликт RowVersion; частые/повторные/параллельные шаги; TTL/recycle; timeout/отмена/неопределённая очистка; выдача/отзыв и сохранность dirty-буфера в соседней вкладке. Наличие guards не доказательство этих проверок. Полная функция PERF-ADMIN-01 и предметные сценарии заметок остаются открытыми.
