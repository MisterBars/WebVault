## Область и статус

База адресной актуализации браузерного контракта — 424c4941e602ea5208f090716aabca1b612c55cb. В исходниках уже есть защищённый синтетический HTTP, центральный экран, выбранные клиентские сценарии дерева/Markdown/графа и отдельная ручная проверка жестов. Это не выполненный серверный цикл заметок, не максимальная нагрузка проекта и не завершённая PERF-ADMIN-01. Наличие кода, модельные тесты, полный test:all, build, публикация и браузерное наблюдение различаются. Метаданные установленного сайта не подменяются HEAD GitHub.

Три разных предмета: вычислительный Node-набор index.* на сборочном ПК; браузерные автоматические/ручные проверки; внешний генератор независимых HTTP-сессий. Node-набор не проверяет DOM/IIS и не требует Node на рабочем сайте. Его параметры и технические сведения первоначальных частей — tools/cm6/PERFORMANCE.md; старые статусы подключения отдельных частей не определяют нынешний браузерный статус. Дальнейшие требования и остаток сохраняются в backlog, не в новом плане или архиве.

## Вход и оформление

У обычной неограниченной учётки ribbon-кнопка с локальным SVG-таймером открывает «Бенчмарк» в центральной рабочей области. Администратору оставлен раздел настроек для выдачи/отзыва права, не пользовательский запуск. Общее/Учётная запись сохраняются. benchmark.html — совместимый переход на index.html?benchmark=1, не самостоятельный неоформленный экран. Базовый UI подключается через account_features.js; предметные сценарии требуют актуального CM6 bundle.

Основной DOM: #benchmarkButton, #benchmarkWorkspacePane, .wv-benchmark-toolbar/stage/tree/graph/footer/preview; параметры — #benchmarkOptionsDialog, результаты — #benchmarkResultsDialog. Существующий #settingsBenchmarkPanel переносится адаптером, второй редактор/body/iframe не создаётся. Сверху настройки/запуск/отмена/результаты/возврат к заметке, слева синтетическое дерево, справа граф, снизу прогресс. После завершения/ошибки/отмены результаты доступны отдельной модалкой и кнопкой повторного открытия. Есть русская таблица/подробности, копирование и сохранение исходного JSON. Отказ clipboard API не отменяет сохранение в файл.

Используются workspace.css/application.css, benchmark.css/benchmark_workspace.css и текущие токены формы, текста, границы, фона и акцента; шрифт наследуется. Колонки полей и стенда адаптируются к узкому виду. View-only кнопки исключают принудительный click-save. Открытие не вызывает save/open/discard рабочей заметки и не использует WebVaultCore.run; обычное фоновое autosave не отключается и не ускоряется. Сохранность буфера/курсора/истории — контракт, не доказательство всех браузерных состояний.

Выход со стенда/смена пользователя или CSRF отменяют работу и очищают приватный вывод; поздний ответ не должен восстановить старый результат. Отмена доступна отдельно. Повторный выбор активного стенда не перезапускает его. Закрытие только диалога параметров центрального стенда не отменяет запуск: при ручном запуске этот диалог закрывается, чтобы не перекрывать граф. Закрытие старого settingsModal в резервном пути деактивирует раздел. Старый модальный путь остаётся резервным при недоступности центрального адаптера.

Текущий canOpen центрального адаптера дополнительно проверяет hasVault. Требование чисто синтетического центрального стенда без зависимости от личного vault не считать закрытым; резервный модальный путь не доказательство полной проверки этого случая. Видимость кнопки не серверное разрешение.

## Пояснения параметров

Автоматические ID выбираются флажками. Дерево/компоненты идут в порядке каталога; HTTP при выборе исполняется перед ними. Ручной граф запускается отдельной кнопкой, не включён в автоматический каталог. Полные общие/индивидуальные overrides браузерных ID и отдельные групповые действия остаются развитием; вычислительный CLI имеет собственный select/overrides.

| Параметры | Значения по умолчанию | Границы |
| --- | --- | --- |
| HTTP repetitions / warmup | 30 / 3 | 1–100 / 0–10 |
| HTTP sizeKiB / timeoutMs | 64 / 5000 | 1–256 KiB / 1000–30000 ms |
| Компоненты repetitions / warmup / timeoutMs | 3 / 1 / 10000 | 1–10 / 0–3 / 1000–30000 ms |
| Корпус notes / linksPerNote / noteKiB / seed | 100 / 3 / 4 / 1 | 2–300 / 0–6 и меньше notes / 1–64 KiB / 0–2147483647 |

HTTP возвращает строку x: размер относится к тексту одного ответа, JSON добавляет служебный объём. Компоненты используют общий детерминированный синтетический корпус, а не число пользователей. notes×noteKiB×1024 — объём текста корпуса; папки и запросы учитываются отдельно. Типы, диапазоны, сочетания и неизвестные поля/ID проверяются; увеличение настроек не отключает лимиты и валидацию.

HTTP-поля имеют связанные aria-describedby подсказки .wv-benchmark-help; #benchmarkPlan[aria-live=polite] пересчитывается без API. Пример:3+30=33 запроса,64 KiB=65536 байт текста каждого ответа, служебные start/cancel отдельно. У компонентных полей есть подписи диапазонов и общий план корпуса; не обещать уже одинаковые индивидуальные tooltip для всех параметров. Некорректное значение не выдаётся за корректный план. Таймаут — предел завершения, не задержка. Прогрев проверяется, хранится отдельно и не входит в статистику; управление настоящим холодным стартом не реализовано.

Общие рабочие и тестовые функции используются через изолированные источники: строка/обход/загрузчик дерева, индексатор, модель, SVG-сцена и контроллер жестов. Синтетический источник хранится в памяти экземпляра и не читает кэш личных заметок вместо корпуса. Для DOM дерева listingPreparation, для графов indexPreparation записываются отдельно и исключены из основной длительности. Индексатор считает folders/reads/bytes/lists/readYieldEvery; reads здесь не HTTP-запросы к реальному vault. Подготовка модели SVG также исключена из основного рендера; проверка результата входит. Изменение размера области внутри или между повторами не принимается как сопоставимый успех.

Экран использует createScreenWorkloadRegistry; общий createBenchmarkWorkloadRegistry объединяет дерево и компоненты, передаёт обе области и проверяет состав/порядок/версии/фазы/статистику дочерних отчётов. Некорректный отчёт, несовпадение корпуса, быстрый неправильный результат и неподдержанный ID не становятся успехом. При отсутствии общего renderer дерева остаётся компонентный резервный путь с явным сообщением.

### Ручной граф

benchmark_interactive.js сохраняет автоматические catalog/execute и добавляет executeInteractive(input,{signal,host,authorize,onProgress,deadline}). Ручной ID — graph.svg.interactive версии1, scope=browser-synthetic-graph-interaction. Он использует те же функции сцены/жестов и синтетический индекс; клики/Enter не открывают рабочие заметки. В каждом повторе после валидного кадра обязательны zoomEvents>0, panGestures>0, nodeDrags>0 и hoverEvents>0. Pan — законченный жест по фону, не drag узла; порог drag4 SVG-единицы сохранён.

Режим помечен renderMode=interactive, interactionDriver=manual, timing=human_interaction_completion. elapsedMs включает монтаж/проверки сцены и ожидание действий пользователя, но не подготовку индекса/модели. Это проверка взаимодействия, не latency события, FPS или скорость отрисовки. Её медиану нельзя сравнивать с автоматическим первым кадром. Три жеста из четырёх не успех; до таймаута — interaction_not_completed. Прогрев тоже требует действий. Для короткой первой проверки задать1 измерение/0 прогрева/30000 ms, не обязательно максимальный набор.

С 424c494 над сценой есть этап/номер прогрева или измерения и список оставшихся действий, в том числе pan по пустому месту. Строка с role=status/aria-live=polite имеет зарезервированную высоту и меняется только при изменении текста. Это не проверенный во всех темах layout. При новом повторе жесты сбрасываются; отмена/закрытие останавливают симуляцию, снимают захват/закрепление узла и удаляют только принадлежащую повтору сцену и подсказки. Ошибка освобождения даёт unconfirmed, а не ложный итоговый ok.

### Серверное право и HTTP-протокол

api/benchmark.ashx — классический BenchmarkHandler; только POST с WebApi.Prepare/Post/RequireUser(write:true), JSON/Origin/CSRF. Неизвестные поля и неверные типы отклоняются; произвольные URL/SQL/код/пути не принимаются. Миграция08 добавляет nullable auth.Users.BenchmarkGrant: NULL — запрет. Администратор выдаёт/отзывает право обычной цели с RowVersion и повторной проверкой своей сессии в транзакции. Выдача — активной неограниченной цели, отзыв — также отключённой/удалённой/ограниченной обычной цели. UI выбирает активные неудалённые записи из первых200 пользователей, текущий флаг права не показывает; после изменения обновляет список. Пароли/сессии/файлы не меняются; RowVersion меняется. Новая выдача создаёт новое поколение и не оживляет старый запуск.

start: repetitions1–100, warmup0–10, sizeKiB1–256, поколение проверяется при регистрации. Один живой запуск на владельца, до32 записей AppDomain, TTL120 секунд. step проверяет владельца/SessionId, действующую сессию/поколение до и после формирования ответа, точный очередной index, минимум50 мс между принятыми шагами. Чужой runId —404. Отзыв проверяется по SQL; принятый до отзыва ответ может уже передаваться по сети.

cancel удаляет только собственную запись той же действующей сессии, допускается после отзыва отдельного права; не purge и не файловое удаление. Запуски в памяти: recycle теряет их, другой IIS worker может дать404; для воспроизводимого прогона нужен один worker. Разрешения остаются в SQL. Просроченные записи убираются при следующем start/cancel или recycle; максимум32. Автовосстановления и слепых повторов нет.

Компоненты и ручной сценарий получают серверную проверку authorize перед работой и перед принятием успеха. После await проверяются отмена/дедлайн; отказ, поздний ответ и смена контекста не должны публиковать успешный замер. Это не регистрация файлового серверного запуска или ослабление обычных проверок заметок.

## Измерение и отчёт

HTTP имеет собственный предел120 секунд, AbortSignal в fetch и последовательные повторы с паузой около50 ms. Реестр дерева+компонентов имеет общий предел120 секунд; ручной запуск также ограничен120 секундами и таймаутом повтора. Эти проверки отбрасывают поздний результат, но не принудительно прерывают синхронный JS/уже отправленный authorize; очистка/вывод могут закончиться позднее. В смешанном UI-запуске HTTP идёт отдельным префиксом: единый бюджет и единый completed/total для всего HTTP+локального набора ещё не обеспечены одним общим реестром.

В HTTP-время входят запрос/получение/JSON/точная проверка тела; start/cancel, межшаговая пауза, callbacks прогресса и вывод таблицы не основные замеры. Отмена fetch не доказывает отсутствие принятого серверного шага. Неопределённая очистка — unconfirmed и итог incomplete; новая сессия не используется для повторного старого запроса. Слепых повторов нет. error/timeout/cancelled/skipped различаются; частичная статистика не означает успех набора.

Времена в ms: сырые samples, фазы warmup/measurement, count/median/min/max/MAD. p95 nearest-rank выдаётся только поддерживающими его runner при минимум100 успешных измерениях; максимум10 компонентных повторов не даёт p95. Конфигурация и версии сохраняются, у компонентных отчётов есть fixtureVersion/fixtureKey/fixtureBytes, условия источника/исключённых подготовок и renderGeometry. Обёртки HTTP-only, смешанного и ручного результата не одинаковы; не обещать одинаковые служебные поля всех ветвей.

У HTTP-core есть runId, у компонентного/ручного запуска — batchId по применимости ветви. environment содержит userAgent, installedBenchmarkVersion=1 и в центральном адаптере benchmarkUIVersion=4; это протокол/интерфейс, не версия всего сайта. sourceMainSha=null означает неизвестный SHA поставки. Полные SHA/название/дата именно тестируемого коммита ещё требуют включения в поставку; не подставлять свежий GitHub HEAD. Геометрия, корпус, параметры, зависимости, среда и режим должны быть сопоставимы до/после.

CPU, память, физический paint, серверные файловые операции/этапы, полный HTTP-индекс и браузеры одновременных пользователей не измеряются нынешними локальными сценариями. unavailable сохраняется явно; нули не подставляются вместо отсутствующего измерения. Фоновая работа обычного редактора не объявлена исключённой. Прогрев не доказательство управляемого состояния кэша.

Экспорт JSON явный, без текстов заметок/токенов/CSRF/абсолютных путей. Русское представление не переводит машинные ключи/ID/коды копируемого или сохраняемого JSON. Постоянного хранилища результатов в БД, пользовательских названий/комментариев, графиков сравнения и автоматического срока хранения пока нет. Экспорты владелец хранит/удаляет вне Git и сайта.

### Внешние независимые сессии

Профиль нагрузки экспортируется для perf_multiuser.mjs на тестовом ПК. Он использует заранее созданные обычные WVBench_* с выданным правом; локальный приватный файл actors с testOnly:true и login/password не загружается в сайт/Git. Профиль выполняет только http.synthetic.read, не создаёт несколько браузеров и не рисует графы. Действующие ограничения входа по IP не отключаются; неудачный вход не повторяется автоматически. Импорт внешнего JSON ограничен2 MiB и проверкой формата/значений/цели, статистика пересчитывается, импорт явно не заверение исполнения. Это не универсальный импорт любых внутренних отчётов и не уже существующая история в БД.

## События прогресса HTTP-runner

WebVaultBenchmarkCore.execute(input,request,signal,clock,onProgress) принимает необязательный пятый аргумент. Старые вызовы из четырёх аргументов и JSON-отчёт сохраняются. События: starting, step-start, step-end, cleanup, finished. Объект события содержит только id, stage, index, phase, status, completed, total; id=http.synthetic.read, phase=warmup/measurement для повторов, index с нуля. Для служебных стадий index/phase равны null. status у step-end и finished отражает результат, иначе null. completed считает только успешно проверенные повторы, включая прогрев; total=repetitions+warmup. Неудачный повтор не увеличивает completed.

step-start вызывается до начала измеряемого интервала; step-end — после фиксации длительности и проверки результата. После step-start повторно проверяются отмена и общий дедлайн. cleanup обозначает переход к очистке, finished отправляется после её попытки и вычисления окончательного статуса. Событие completed=total само по себе не означает успешную очистку или успех всего запуска. Callback синхронный; его исключения изолированы и не отменяют обязательную очистку. Данные ответа, runId, токены и тексты в события не включаются. Контроль актуальности представления и защита от позднего вывода остаются обязанностью подписчика.

Компоненты имеют аналогичный необязательный onProgress; общий реестр добавляет runner-start/runner-finished и имя группы, объединяет completed/total дерева и компонентов. Экран передаёт исходный callback/AbortSignal/authorize, показывает действие и фазу; completed включает проверенные прогревы, не прогнозирует оставшееся время. До финального успешного результата/очистки полоса не достигает100%. Единый счётчик с HTTP-префиксом остаётся отдельным остатком. Во время ручной сцены текущий номер и оставшиеся действия показаны отдельно над SVG.

## Ограничения и следующий объём

Следующее серверное расширение сначала требует проектирования изолированного корня/владельца/ID запуска, API, квот, запретов путей/reparse, верификации результата, отмены и очистки после неопределённого ответа. Оно не разрешает использовать рабочие заметки/DataRoot, менять схему БД во время теста или называть SQL/ФС атомарными. Изменяющие/необратимые действия подтверждаются отдельно.

Открыты также полная готовность редактора/режимов/поиска, большие vault без снятия лимитов, независимый от личного vault центральный синтетический вход, общий HTTP+компонентный бюджет/счётчик, индивидуальные браузерные overrides/подсказки, поставка достоверных метаданных версии и история/импорт/сравнение результатов в БД с правами/квотами/сроком хранения/бэкапом. Нынешний тест не выполняет автоматическую оптимизацию и не обещает процент ускорения.
