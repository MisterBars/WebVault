## Выбор папки и проверка

Импорт из настроек или ПКМ открывается для текущей/контекстной папки; для файла берётся родитель. Обозреватель показывает вложенные папки, В корень, На уровень выше и Выбрать эту папку. Простое открытие папки не меняет выбранное назначение; последняя кнопка переносит путь в поле. Ручной ввод сохранён. Команда ПКМ открывает форму внутри общего A.run без прежней внутренней блокировки showImport по app.isBusy. Доступны только обычная личная учётка без MustChangePassword и созданное хранилище.

Выбрать до100 .md либо один ZIP отдельно, нажать Проверить файлы, сверить назначение и skip/rename, затем Импортировать проверенное. Изменение набора файлов сбрасывает план; owner/epoch/revision защищают от устаревшего результата. Целевая папка проверяется перед записью. Упрощение до одного запуска остаётся будущей задачей, не описанием нынешнего двухшагового интерфейса.

## Импорт .md и ZIP

Для нескольких .md проверяются имена/дубликаты без регистра/размеры/UTF-8, скрытые служебные имена пропускаются с числом в отчёте. ZIP сначала проходит inspectZip по исходным именам и центральному каталогу с проверкой локальных заголовков/имён/границ данных, затем JSZip и ограниченный поток чтения заметок. Не выдавать этот preflight за универсальный аудит всех форматов ZIP.

Поддержаны одиночный обычный ZIP, STORE/DEFLATE и UTF-8 имена. Шифрование, ZIP64, многотомность и symlink не поддержаны. Пути абсолютные/../с backslash/недопустимыми и зарезервированными компонентами и дубликаты отклоняются до записи; используются исходные имена до автоматической очистки библиотекой. Служебные записи и не-.md не импортируются, число пропусков отображается; отдельные вложения пока не переносятся.

| Ограничение | Значение |
| --- | --- |
| Входной ZIP и заявленный распакованный объём всех записей | Каждый до20 MiB. |
| Записи ZIP | До500, включая папки/игнорируемые записи. |
| Переносимые заметки | До100. |
| Одна заметка | До256 KiB и131072 UTF-16 единиц декодированного текста. |
| Относительный путь | До180 символов/16 компонентов/100 в компоненте, сервер дополнительно проверяет полный путь240. |

У каждой распакованной заметки ограничен фактический поток, сверяются размер и CRC с каталогом; checkCRC32 всей библиотеки выключен, проверка выполняется адресно readEntry. CRC не доказательство доверенности содержимого. Устаревшие кодировки/нестандартные ZIP могут отклоняться. JSZip не извлекает файлы напрямую на серверный диск.

Под выбранным назначением создаются допустимые каталоги. Для существующего имени skip оставляет его, rename выбирает первое свободное Name (N).md, сервер ограничивает перебор1000 вариантами; перезаписи нет. Это не правило максимального N+1 для создания новой заметки. Wiki/прочие ссылки в импортируемом тексте автоматически не переписываются; для проверочного набора предпочтительна пустая папка. Импорт пишет исходные UTF-8 байты, включая BOM/CRLF, не прогоняет их через нормализацию save.

Пакет не атомарен: созданные папки и успешные файлы остаются после ошибки. Неопределённый/сетевой/серверный сбой останавливает следующие отправки; ошибки отдельных файлов учитываются, смена учётки прекращает работу. После потери ответа проверить дерево перед повтором rename, иначе можно создать лишнюю копию. Отсутствие итогового успеха не доказывает отсутствие созданных папок/файлов.

## Серверный контракт

POST api/notes/transfer.ashx, JSON с защищённой сессией/CSRF/X-WebVault-User; владелец берётся сервером, не из произвольного ID клиента. Повторные проверки Users/UserSessions/UserVaults и путей, запрет администратора и ограниченной временной сессии дополняют клиентский preflight.

| action | Поля / ответ |
| --- | --- |
| import | folder/name/data(Base64)/conflict(skip или rename); name только имя .md, не путь. Ответ skipped/name и при записи version. |
| export | name —относительный путь .md, version необязательная ожидаемая версия. Ответ name/data(Base64)/version. |

Это маршрут отдельных .md, не серверный ZIP-распаковщик. Проверяются строгий UTF-8,256 KiB/131072 единицы, Base64 до349528 символов; ограничение тела запроса524288. Импорт использует временный файл/Flush/File.Move без перезаписи, SHA-256 версии по байтам. После состоявшегося импорта и сбоя подтверждения возвращается503 import_result_uncertain_refresh с именем: обновить дерево и сверить, не повторять вслепую.

## Экспорт

Открытая/одиночная заметка экспортируется как прежний .md. ПКМ группы или папки → Экспортировать ZIP; в настройках можно выбрать исходную папку через тот же обозреватель. Корень означает всё личное дерево в пределах лимитов. Папка и выбранный потомок не дублируются.

Пути архива —от корня vault, не относительно выбранной папки:например Tests/00.md. Сохраняются пустые видимые папки. Служебные каталоги, история, корзина и вложения не включаются. ZIP собирается локально с STORE; при ошибке чтения/превышении лимита не предлагается как полный. Ограничения обхода:до500 элементов/100 заметок/20 MiB данных, не обещание экспорта произвольного vault.

Перед экспортом сохраняется dirty-документ и временно ставится readOnly. Каждая заметка читается через защищённый маршрут; для открытой передаётся ожидаемая версия, несовпадение даёт409 note_changed_retry_export. Байты экспорта сохраняются без нормализации. Общего атомарного снимка vault нет: другие сессии могут менять файлы между чтениями. Экспорт —копия, не синхронизация и не согласованный бэкап БД/DataRoot. Браузер отвечает за запись предложенного скачивания.

## План проверок и границы

Адресные Node-тесты transfer_zip.test.mjs предназначены для путей/структуры ZIP/CRC/кириллицы/дубликатов/traversal/ограниченного потока. Наличие файла не доказывает запуск; Node не проверяет DOM/IIS/публикацию. Для функционального изменения соблюдать цепочку npm_build.md с LASTEXITCODE и остановкой до build при ошибке.

На безопасной копии проверить:

1. Настройки/ПКМ/обозреватель, выбор назначения отдельно от открытия папки, root/parent/ручной путь и отсутствие старой busy-блокировки.
2. Несколько .md и ZIP с вложенными/пустыми папками, skip/rename, совпадающие имена и повторный импорт, исходные BOM/CRLF/русский UTF-8.
3. Опасные пути/служебные записи/не-.md/повреждённый CRC/размеры/ZIP64/шифрование/symlink/слишком большой архив, лимиты файлов и записей.
4. Потерю сети/ответа после записи, частично созданные папки, смену пользователя/окна/выбора и сохранность уже успешных файлов.
5. Экспорт одного .md/группы/папки/корня, исключение выбранного потомка и служебных каталогов, пустые папки, корневые пути ZIP, отказ неполного архива.
6. Dirty-сохранение/readOnly/версии/другую сессию, обратный импорт и Firefox113. Табличные/списковые флажки и прочие редакторские задачи переносом не принимаются.

Историческая граница исходного note_transfer.md сохраняется: первый .md-комплект был проверен пользователем; ZIP/обозреватель были подготовлены исходниками без отчёта npm install/test/build/браузера. Это не новая приёмка нынешнего HEAD. Исходное руководство доступно на610b180b9cbc03ea1a65cdc58879a987c3993700; история двух событий и это ограниченное свидетельство ещё подлежат централизации в changelog/существующем реестре.
