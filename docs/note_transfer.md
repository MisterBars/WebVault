# Перенос заметок: первый этап .md

Статус: исходники подготовлены; компиляция C#, npm test/build и браузер не проверены. ZIP, импорт папок и групповой экспорт НЕ входят в этот этап.

## Обновление
Сделать бэкап DataRoot, получить исходники. Новых npm-зависимостей и SQL нет. Из tools/cm6 выполнить npm test, затем при успехе npm run build; перенести обновлённый сайт, включая App_Code/NoteTransferHandler.cs, api/notes/transfer.ashx и новый vendor/webvault-cm6.js. Ctrl+F5. Перенос подключён внутри CM bundle через mode_slider.js как временная точка загрузки; без bundle интерфейса переноса нет. Рабочий Web.config не заменять.

## Импорт
Кнопка Импорт .md… в файловой панели; выбрать несколько файлов. Поле назначения — путь от корня, пустое — корень. Папка должна существовать. Режим конфликта: пропустить или выбрать сервером свободное имя вида Name (1).md. Перезаписи нет. До 100 файлов, 256 KiB на файл, 20 MiB суммарно в одном выборе. Сервер также проверяет UTF-8 (с BOM или без) и не более 131072 UTF-16 code units текста, чтобы импортированную заметку можно было сохранять существующим редактором. UTF-16/ANSI не преобразуются автоматически. Слишком длинные/недопустимые имена отклоняются.

Импорт сохраняет байты, включая BOM и переводы строк; не конвертирует YAML/Markdown в HTML. Файлы отправляются последовательно отдельными ограниченными JSON-запросами; пакет не атомарен. Ошибка отдельного проверяемого файла учитывается, неопределённый результат/сетевая/серверная ошибка останавливает следующие отправки. После import_result_uncertain_refresh или потери ответа файл мог уже появиться: обновить дерево и проверить, не повторять переименование вслепую. Нет idempotency-журнала для повторов. Успехи и пропуски не откатываются. Новые заметки после импорта не открываются автоматически.

В этом этапе папки не создаются, вложения и ZIP не принимаются. На втором ПК создать нужную тестовую папку и выбрать её местом назначения.

## Экспорт
Открыть заметку и нажать Экспорт открытой .md либо ПКМ по одиночной заметке → Экспортировать .md. Открытый изменённый документ сначала сохраняется; при ошибке скачивание не начинается. Для открытой экспортируемой заметки сервер сверяет её версию. Для другой выбранной заметки читает текущие байты файла. Размер — до 256 KiB. История/корзина/пользовательские настройки и секреты не включаются. Браузер выбирает место сохранения; сообщение о передаче файла браузеру не доказывает запись на диск. Экспорт — копия, не синхронизация.

## Безопасность и проверки
Только текущий личный пользователь, POST с CSRF/проверкой Origin/X-WebVault-User, повторная проверка действующей сессии в транзакции и блокировки пользователя/хранилища. Пути ограничены своим vault, служебные/зарезервированные сегменты и reparse отклоняются. Base64/JSON ограничены на сервере; штатный глобальный лимит WebApi.Read не ослаблялся, здесь отдельный ограниченный reader. Импорт пишет во временный файл и перемещает без замены существующего; SQL не откатывает файловые изменения после move.

На копиях проверить импорт 00–07, повторный импорт в skip/rename, кириллицу/Unicode, пустую заметку, BOM/CRLF, неверную кодировку, слишком большой файл, недопустимое имя, чужую/истёкшую сессию, потерю сети, экспорт несохранённого/конфликтного документа. Сравнить экспортированные и импортированные байты/хеши. Существующие тесты npm не покрывают новый endpoint/DOM; необходим отдельный браузер/IIS тест.
