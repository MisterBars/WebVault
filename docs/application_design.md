# Единый дизайн всех страниц

Статус: комплект подготовлен, выполнение в браузере не проверено. Предыдущий Obsidian-подобный личный раздел пользователь принял в общем виде. SQL/API/данные не меняются.

## Охват
Вход auth.html, пользователи users.html, учётная запись account.html и диагностика index.html используют общий app.css и ui.js. Через них подключены те же obsidian-tokens.css, что у заметок. Оболочка собирается общим JS вокруг существующего main: верхняя app-header с навигацией, узкая ribbon, боковое меню разделов, прокручиваемое содержимое, нижняя status-bar. Формы/таблицы/подтверждения/первоначальная настройка продолжают использовать прежние обработчики. Изменять каждую HTML-страницу и дублировать каркас не требуется. На workspace.html оболочка повторно не создаётся — там сохраняется специализированная область редактора.

## Роли и навигация
Гость: вход и диагностика. Администратор: пользователи, своя учётная запись, диагностика. Обычная учётка: заметки, своя учётная запись, диагностика. Верхняя навигация и меню подсвечивают текущий раздел. Боковая панель сворачивается кнопкой; на узком экране изначально скрыта. Имя/роль выводятся через textContent, не как HTML. Серверная защита не заменяется скрытием меню.

## Оформление
Сдержанная палитра, шрифты и отступы, компактные поля и кнопки, тонкие разделители вместо крупных синих карточек. Опасные действия выделяются text-error. Тёмный режим по умолчанию; светлые токены ещё не означают наличие пользовательского переключателя. Не заявлять полную совместимость со сторонней темой или плагином Obsidian. Выбор темы/панелей пока не сохраняется в персональных настройках. CSS-контракт заметок описан в theme_compatibility.md; это дополнение расширяет общий визуальный язык на служебные страницы.

## Технические детали
app.css импортирует obsidian-tokens.css локально через @import. Весь комплект работает без CDN. ui.js добавляет классы theme-dark/mod-windows/webvault-page только служебным страницам; существующий theme-light/theme-dark не заменяется. Создание оболочки защищено от повторного вызова. Новая служебная страница должна подключать app.css, иметь nav#navigation и прямой body>main, затем подключать ui.js после разметки. Пользовательские данные не вставлять через innerHTML.
Блокировка кнопок во время запроса теперь восстанавливает исходный disabled, а не включает все кнопки подряд. Совместимость со старым API WebVaultUI сохранена.

## Обновление
Получить файлы с сохранением локальных изменений. SQL и Web.config не менять. Ctrl+F5 на каждой странице либо очистка кеша CSS/JS. При старом дизайне проверить, что app.css/ui.js/obsidian-tokens.css получены без 404. Данные и хранилища не пересоздавать.

## Проверки
- [ ] Все четыре страницы имеют общий каркас и палитру, без горизонтального переполнения на обычном экране.
- [ ] Вход/переадресация по роли/выход не изменились.
- [ ] Завершённая первоначальная настройка по-прежнему скрыта.
- [ ] Список, создание, переименование, мягкое/полное удаление работают.
- [ ] Смена своего пароля и отзыв сессий работают.
- [ ] Диагностические кнопки работают.
- [ ] Скрытие меню, активный раздел, клавиатурный фокус и узкий экран проверены.
- [ ] Личный редактор не получает второй каркас, создание/сохранение и Ctrl+S работают.
- [ ] Обычный пользователь не получает административные операции прямым запросом.

Отдельно остаются файловые операции/папки, Markdown-просмотр, персональные настройки/темы, очистка владельца хранилища и прочие функции плана. Этот комплект только унифицирует UI.
