# WebVault — ТЗ 002: учётки, файловый менеджер и редактор

Статус: требования/план, не реализованные функции. Основание: уточнения пользователя после приёмки единого окна UI v0.2. Реализация по небольшим проверяемым комплектам.

## 1. Неизменяемые требования
Windows 7/.NET Framework 4.5, IIS .ashx и SQL Express 2014, Firefox 113, автономная поставка. Новые системные компоненты на рабочем ПК не устанавливать. Библиотеки редактора при необходимости готовить на домашней машине и включать локальные готовые файлы с лицензиями/версиями, без CDN/npm во время работы сайта. Единый index, модальные вход/настройки; админ не использует личный файловый API; диагностика только администратору. Markdown-файлы — источник текста.

## 2. Административный сброс пароля
В таблице обычных пользователей добавить действие Задать временный пароль. Это отдельная операция от смены собственного пароля и не требует знания старого пароля целевого пользователя. Перед действием требуется повторное подтверждение текущих учётных данных администратора; текущий пароль администратора не передаётся целевому пользователю и не сохраняется в журнале. Конкретная форма повторной проверки реализуется вместе с API.
Права повторно проверяются сервером. Операция над собой/другими администраторами этим модулем запрещена; для своего пароля существует собственная смена. Заблокированные/удалённые пользователи не активируются неявно.
Администратор задаёт временный пароль через модальное окно с повтором. Новый пароль проходит ту же политику, хранится только соль/хеш/параметры. Все прежние сессии целевого пользователя отзываются в одной SQL-транзакции с обновлением пароля. Нужен флаг MustChangePassword и миграция. После входа временным паролем пользователь может только сменить свой пароль/выйти; доступ к заметкам и остальным защищённым действиям блокируется сервером, не только интерфейсом. Пользователь меняет временный пароль на новый, флаг снимается, сессии отзываются, требуется новый вход. Не выводить/восстанавливать старые пароли. Не обещать приватность от администратора ОС или полного доступа к БД.
Сброс/успех не должны неявно снимать IsActive/DeletedUtc. Политику счётчика ошибочных входов зафиксировать в реализации и тестах. Не расширять права приложения до db_owner.

## 3. Свой ник
Под ником принимается DisplayName (отображаемое имя), не Login. В модальных настройках учётки добавить поле имени и сохранение. Только собственная учётка по серверной сессии, CSRF, валидация 1–100 символов после Trim; пользователь не может изменить IsAdmin/IsActive/UserId. Не трактовать HTML. Имя обновляется в шапке/настройках без выхода. Логин, UserId, VaultId, пароль и файлы неизменны. Если потребуется самостоятельная смена логина — отдельное требование.

## 4. Модульная архитектура до роста функций
Разделить application.js на загрузку/оболочку, API/сессию, учётки, файловую навигацию, редактор/буферы, сохранение, реестр команд и контекстное меню. Сохранить работающие функции и единый интерфейс. Избавляться от старых неиспользуемых модулей только после проверки ссылок/регрессии. Реестр команд доступен ядру без включения стороннего JS. Не раздавать плагинам SQL/абсолютные пути.

## 5. Папки и адресация
Вместо корневого имени API принимает относительный путь внутри текущего хранилища. Пользователь/хранилище всегда определяются сервером, чужие userId/VaultId из тела не переключают владельца. Сервер проверяет каждый компонент и итоговое нахождение внутри корня с границей разделителя, запрещает абсолютные/UNC/device-пути, обход .., недопустимые и зарезервированные имена, reparse points на всех уровнях. Старый формат name поддержать на переходе или документировать миграцию клиентов.
Поддержать создание, перечисление и раскрытие папок; раскрывать лениво, без обязательного полного сканирования всего диска при запуске. Сохранить текущие ограничения размера заметок до отдельного решения. Лимиты глубины/числа элементов/времени/длины путей и поведения больших деревьев зафиксировать перед выпуском. Проверить на 32-битном рабочем ПК.
Переименование/перемещение не меняют владельца. Не разрешать перемещение/копирование папки внутрь самой себя или потомка; не обходить чужие хранилища. При совпадении имени по умолчанию отказ с предложением нового имени, без молчаливой перезаписи. Учитывать регистронезависимость Windows. Конкурентность с записью заметки должна быть согласована общим механизмом блокировок.

## 6. Операции и контекстное меню
ПКМ по файлу: открыть, переименовать, копировать, вырезать, переместить, удалить в корзину, скопировать относительный путь.
ПКМ по папке: создать заметку/папку внутри, переименовать, копировать, вырезать, переместить, удалить в корзину.
ПКМ по пустому месту: создать в текущей папке заметку/папку, вставить, обновить. Корень хранилища переименовывать/удалять этим меню нельзя.
Копирование/вырезание файлов использовать внутренний буфер приложения с владельцем и исходным путём, не путать с текстовым буфером редактора. Вставку в чужой сеанс запрещать; проверять наличие и актуальность источника при выполнении. Переименование/перемещение открытого файла обновляет дерево, заголовок, выбранный путь и буфер редактора; сначала согласовать несохранённые изменения, не терять их. Копирование создаёт независимую заметку/дерево. Не обещать автоматическое обновление всех wikilinks до реализации отдельного механизма.
Меню: корректные координаты и границы окна, закрытие по клику вне/Escape, фокус и управление клавиатурой, открытие Shift+F10/ContextMenu, разделители, disabled для недоступной вставки, подтверждение удаления непустых папок. Не реализовывать действия обходными манипуляциями DOM.

## 7. Расширение меню плагинами
Определить API регистрации дескрипторов команды: стабильный namespaced id, источник/core или plugin id, label, icon, group/order, contexts(file/folder/empty/editor), visible/when, enabled, execute. Возвращать disposer для удаления регистрации. Контекст — текущий пользователь, тип/относительный путь выделения, родитель и состояние интерфейса; без SQL/секретов/абсолютного пути.
Пункты ядра и будущих плагинов проходят один реестр; отдельный renderer строит меню. Обработчик при запуске повторно проверяет актуальность выделения. Скрытие/disabled не заменяет права сервера. Ошибка плагина не должна ломать меню/терять буфер. Нет обещания изоляции стороннего JS без отдельной песочницы. Сейчас реализовать контракт и тестовую внутреннюю команду; загрузчик и каталог плагинов остаются следующим этапом.

## 8. Корзина, версии и удаление владельца
Пользовательское удаление файла/папки по умолчанию обратимое: корзина вне обычного дерева с метаданными исходного пути, владельца и времени. Полное уничтожение/очистка корзины — отдельные явно подтверждаемые операции. История версий должна сохранять связь с заметкой после переименования/перемещения; нынешних случайных .md без имени недостаточно. Потребуется формат метаданных/стабильная идентификация и согласованная миграция, без удаления старой истории.
БД и файловая система не имеют общей транзакции: предусмотреть журналируемые стадии и восстановление незавершённых операций, не выдавать частичную копию/удаление за успех. История/корзина не заменяют резервную копию. Полное удаление пользователя с хранилищем остаётся заблокированным до отдельного безопасного удаления каталога/корзины/истории/реестра.

## 9. Автосохранение
Реальное время здесь означает редактирование в браузере и автоматическую запись без кнопки, не совместное посимвольное редактирование несколькими людьми. Предлагаемый старт: 700 мс паузы, плюс ограничение ожидания около 5 секунд при непрерывном вводе; значения уточнить измерениями и позднее сделать личными настройками.
На заметку один выполняющийся запрос и одна актуальная ожидающая версия текста. Ответ обновляет только подтверждённую версию и отправленный снимок, не затирает новый ввод. Ctrl+S немедленно сбрасывает очередь. Статусы: изменено/сохраняется/сохранено/ошибка/конфликт. Ретраи ограничены, не бесконечные; 401 останавливает запись и открывает вход, 409 останавливает автозапись и предлагает сравнить/сохранить копию. Не использовать last-writer-wins. Не считать закрытие вкладки гарантированным моментом завершения сети: предупреждать при неподтверждённых изменениях.
При смене файла сохранить предыдущий буфер или явно согласовать незавершённую запись; не отправлять старый снимок в новый путь/аккаунт. Переименование/перемещение/удаление синхронизируются с очередью сохранения. Ошибка сети не очищает текст. Сохранение не переприсваивает значение редактора и не сбрасывает undo. Историю файлов не раздувать бессмысленной полной копией на каждый символ; политику снимков согласовать отдельно. Существующая SHA-256 проверка версии сохраняется. Внешние писатели Obsidian/синхронизаторы пока не поддерживаются одновременно.

## 10. Undo/redo
Ctrl+Z отменяет текстовую правку текущей заметки, Ctrl+Y/Ctrl+Shift+Z возвращают её. История независима для каждого открытого документа; автосохранение не является правкой документа и не очищает историю. Undo/redo сами создают изменение для автосохранения. Переход между заметками должен сохранять документальное состояние в пределах текущей сессии вкладки; после перезагрузки история может быть потеряна, это явно указать.
Undo текста не отменяет файловое перемещение/удаление: для них корзина/журнал. Не навешивать глобальный Ctrl+Z поверх паролей/полей форм и не подменять поведение браузера в модалках. CodeMirror с history рассматривается как целевой редактор; точная версия/расширения/локальная сборка, лицензии и поддержка Firefox 113 проверяются отдельно. Не выдавать textarea с декоративными cm-классами за CodeMirror или Live Preview.

## 11. Порядок кодовых комплектов
1. Временный пароль от администратора и свой DisplayName, миграция MustChangePassword/серверные ограничения, UI и тесты.
2. Выделение модулей без изменения поведения.
3. Папки и безопасная адресация, дерево, создание/чтение/запись внутри папок.
4. Реестр команд/контекстное меню, переименование/копирование/перемещение/корзина, согласование с открытой заметкой.
5. Редактор с независимой undo/redo историей и локальной поставкой.
6. Очередь автосохранения, конфликты, интеграция undo и файловых операций.
7. Регрессия, тесты сбоев/доступа и перенос на рабочий ПК; затем продолжение настроек/тем/плагинов.
Не отмечать комплект реализованным до записи кода и отдельно подтверждённым до проверки пользователя.

## 12. Приёмка
- Админ не узнаёт старый пароль; сброс отзывает сессии; временный вход ограничен до смены.
- Смена ника не меняет логин/ID/каталог и не позволяет изменить чужую учётку.
- Нельзя обойти корень/использовать junction/копировать в потомка/работать с чужим vault.
- Меню отличается по контексту, доступно клавиатурой и расширяется тестовой командой через реестр.
- Переименование/перемещение/корзина не теряют несохранённый текст и историю.
- Автосохранение не создаёт параллельных записей одной заметки, не затирает новый ввод и не сбрасывает Ctrl+Z.
- Две вкладки вызывают обнаруживаемый конфликт; недоступная сеть/401/потерянный ответ не очищают текст.
- Undo/redo не смешиваются между файлами/аккаунтами и не перехватывают формы паролей.
- Стандартная автономная установка Windows 7/Framework 4.5/Firefox 113 не требует скачивания компонентов.
