# WebVault — ТЗ 002: учётки, файловый менеджер и редактор

Документ определяет требования к аккаунтам, файлам и редактору; это не утверждение, что весь объём отсутствует или полностью реализован. Актуальные контракты — предметные руководства, очередь/границы проверки — [next_steps.md](../next_steps.md), история — [changelog](../../CHANGELOG.md). Исторический порядок комплектов ниже не запускает функциональную очередь при ревизии документации.

## 1. Неизменяемые требования
Windows 7/.NET Framework 4.5, IIS .ashx, SQL Express 2014, Firefox 113, автономная поставка. Новые системные компоненты на рабочем ПК не устанавливать. Библиотеки редактора готовить на подходящем сборочном ПК и поставлять локально с лицензиями/версиями, без CDN/npm при работе сайта. Единый index, модальные вход/настройки; админ не использует личный файловый API, диагностика только администратору. Markdown — источник текста.

## 2. Административный сброс пароля
Требование реализованного контракта описано в [session_policy.md](../session_policy.md#административный-временный-пароль): отдельное действие временного пароля активной обычной цели, не собственная смена и не знание её старого пароля. Модальное окно с повтором нового пароля и повторной проверкой текущего пароля администратора. Пароль администратора не передаётся цели и не журналируется.
Права/цель/сессия повторно проверяются сервером; себя/администраторов этим модулем менять нельзя. Отключённые/удалённые не активируются неявно, IsActive/DeletedUtc не снимаются. Новый пароль проходит политику; сохраняются только соль/хеш/параметры. Все прежние сессии цели отзываются транзакционно с обновлением пароля, MustChangePassword=1 и аудитом миграции 06. Исходное требование миграции не команда повторно выполнить уже применённый SQL.
Ограниченный вход допускает me/собственную смену/logout, не заметки/прочие защищённые операции; запрет серверный, не только модалка. После собственной смены временного пароля флаг снимается, текущий SessionId сохраняется с вращением токенов, другие сессии отзываются. Старое обязательное повторное вхождение после любой собственной смены заменено этой политикой; CreatedUtc/AbsoluteExpiresUtc не сбрасываются. Потеря ответа после commit может потребовать вход уже новым паролем.
Не выводить/восстанавливать старые пароли; не обещать приватность от администратора ОС/полного доступа к БД. Политика счётчиков/лимитов и журнал без секретов — в руководстве и проверках. Не выдавать db_owner. Документация контракта не новая runtime-проверка.

## 3. Свой ник
DisplayName, не Login. Собственное имя в модальных настройках: серверная сессия/CSRF, 1–100 после Trim, запрет управляющих символов, HTML не исполняется. Нельзя выбрать чужую учётку или менять IsAdmin/IsActive/UserId. Шапка/настройки обновляются без выхода; логин/UserId/VaultId/пароль/файлы не меняются. Собственная текущая сессия сохраняется, остальные отзываются; rowVersion-конфликт не перезаписывается вслепую. Самостоятельная смена логина — отдельное требование. [Текущий контракт](../session_policy.md#свой-ник).

## 4. Модульная архитектура до роста функций
Разделить application.js на загрузку/оболочку, API/сессию, учётки, файловую навигацию, редактор/буферы, сохранение, команды и контекстное меню. Сохранить функции/единый UI. Неиспользуемые модули удалять после сверки ссылок/регрессии. Реестр ядра доступен без стороннего JS; плагины не получают SQL/абсолютные пути. Это архитектурное требование, не отчёт о завершённом разделении всех модулей.

## 5. Папки и адресация
API принимает относительный путь текущего vault; владелец/хранилище всегда серверные, чужие userId/VaultId не переключают доступ. Проверять каждый компонент и итоговый корень с границей разделителя; запрещать absolute/UNC/device/.., недопустимые/зарезервированные имена и reparse points на всех уровнях. Старый name поддержать на переходе либо документировать миграцию клиентов.
Создание/перечисление/раскрытие папок — ленивые, без обязательного полного сканирования диска при старте. Ограничения размера заметок сохранить до отдельного решения. Лимиты глубины/элементов/времени/длины путей/больших деревьев зафиксировать до выпуска, проверить на 32-битном ПК.
Rename/move не меняют владельца. Папку нельзя move/copy в себя/потомка или обходить чужие vault. Совпадение имени — отказ и новое имя, не молчаливая перезапись; учесть Windows case-insensitive. Конкуренция с записью согласуется общими блокировками.

## 6. Операции и контекстное меню
- Файл: открыть/переименовать/копировать/вырезать/переместить/в корзину/относительный путь.
- Папка: создать заметку/папку внутри, rename/copy/cut/move/trash.
- Пустое место: создать в текущей папке заметку/папку, вставить, обновить. Корень этим меню не переименовывать/удалять.
Внутренний файловый буфер хранит владельца/исходный путь, не текстовый clipboard. Чужая сессия не вставляет, наличие/актуальность источника проверяются при действии. Rename/move открытого файла обновляет дерево/заголовок/путь/буфер после согласования несохранённых правок. Copy создаёт независимую заметку/дерево; обновление всех wiki — отдельный механизм, не обещать автоматически.
Корректные координаты/границы окна, закрытие вне/Escape, фокус/клавиатура/Shift+F10/ContextMenu, разделители, disabled недоступной вставки, подтверждение непустой папки. Без обходных DOM-манипуляций.

## 7. Расширение меню плагинами
API дескрипторов: стабильный namespaced id, source/core или plugin id, label/icon/group/order, contexts(file/folder/empty/editor), visible/when/enabled/execute; disposer удаления регистрации. Контекст — пользователь, тип/относительный путь выделения, родитель/состояние UI, без SQL/секретов/абсолютного пути.
Ядро/будущие плагины используют один реестр и отдельный renderer. При запуске повторно проверять выделение; hidden/disabled не серверные права. Ошибка плагина не ломает меню/буфер; изоляция стороннего JS без песочницы не обещается. Начальный объём — контракт и внутренняя тестовая команда, загрузчик/каталог плагинов отдельно.

## 8. Корзина, версии и удаление владельца
Удаление файла/папки по умолчанию обратимо: корзина вне обычного дерева, метаданные исходного пути/владельца/времени. Полное уничтожение/очистка — отдельно с явным подтверждением. История сохраняет связь после rename/move: стабильная идентификация/метаданные и безопасная миграция без удаления старой истории, не случайные безымянные .md как достаточное решение.
SQL/ФС не общая транзакция: журналируемые стадии/recovery, частичную copy/delete не выдавать за успех. История/корзина не бэкап. Старый SQL-purge не удаляет файловое хранилище и не должен обходить FK/реестр. Отдельный purge_user с необратимыми/частичными сбоями и повтором описан в [folders_and_purge.md](../folders_and_purge.md); раннее условие блокировки до безопасной очистки не является нынешним общим запретом этого маршрута. Путь берётся из реестра, не браузера. Наличие процедуры не отчёт о её полной проверке.

## 9. Автосохранение
Редактирование в браузере/автозапись, не совместное посимвольное редактирование людьми. Предложение старта: 700 ms паузы и около 5 секунд при непрерывном вводе; измерить и позднее сделать личными настройками, не считать подтверждёнными текущими параметрами.
Один выполняющийся запрос/один актуальный ожидающий снимок на заметку. Ответ обновляет подтверждённую версию/отправленный снимок, не новый ввод. Ctrl+S сбрасывает очередь. Статусы изменено/сохраняется/сохранено/ошибка/конфликт; ограниченные ретраи. 401 останавливает запись/открывает вход, 409 — автозапись/сравнение или копия. Не last-writer-wins. Закрытие вкладки не гарантия сети, предупреждать о неподтверждённых правках.
При смене файла сохранить прежний буфер либо явно согласовать запись; старый снимок не отправлять в новый путь/аккаунт. Rename/move/delete согласованы с очередью. Сеть не очищает текст, сохранение не присваивает заново editor.value и не сбрасывает Undo. Не создавать полную копию на символ, политику снимков отдельно. SHA-256 версия сохраняется; одновременные внешние писатели Obsidian/синхронизаторы не обещаются.

## 10. Undo/redo
Ctrl+Z отменяет текст текущей заметки, Ctrl+Y/Ctrl+Shift+Z возвращают. Независимая история каждого открытого документа; autosave не правка/не очистка истории, Undo/Redo создают изменение для autosave. Требование сохранения документального состояния при переходах в пределах сессии вкладки остаётся; нынешняя потеря при reopen не его выполнение. После reload потеря истории допустима, должна быть явно описана.
Undo текста не файловой move/delete: для них корзина/журнал. Не глобальный Ctrl+Z поверх паролей/форм/модалок. Целевой редактор CodeMirror/history с отдельно проверенными версиями/расширениями/локальной сборкой/лицензиями/Firefox113. Textarea с декоративными cm-классами не CodeMirror/Live Preview.

## 11. Порядок кодовых комплектов
Историческая последовательность зависимостей, не текущая очередь реализации с нуля:
1. Временный пароль/DisplayName, MustChangePassword, серверные ограничения/UI/тесты.
2. Выделение модулей без смены поведения.
3. Безопасные папки/адресация/дерево/read/write.
4. Реестр команд/меню, rename/copy/move/trash и открытая заметка.
5. Редактор с независимой историей и локальной поставкой.
6. Autosave/конфликты, интеграция Undo и файлов.
7. Регрессия/сбои/доступ/целевая среда, затем настройки/темы/плагины.
Наличие реализации и фактический охват проверки различать. Текущие открытые работы — [backlog](../next_steps.md); документационная очередь D не запускает P.

## 12. Приёмка
Это критерии проверки, не отчёт о выполнении:
- Админ не узнаёт старый пароль; reset отзывает сессии цели, временный вход ограничен до собственной смены.
- Ник не меняет Login/ID/каталог и чужую учётку.
- Нельзя обойти корень/junction/копировать в потомка/чужой vault.
- Контекстное клавиатурное меню расширяется внутренней командой через реестр.
- Rename/move/trash не теряют несохранённый текст/историю.
- Autosave без параллельных записей заметки/потери нового ввода/сброса Ctrl+Z.
- Конфликт вкладок обнаруживается; сеть/401/потерянный ответ не очищают текст.
- Undo/Redo изолированы по файлам/аккаунтам, не перехватывают пароли.
- Автономная Windows7/Framework4.5/Firefox113 без скачивания компонентов.
