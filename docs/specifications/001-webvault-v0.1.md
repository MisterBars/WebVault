# WebVault — техническое задание v0.1

Статус: исходный согласованный план. Дата: 2026-10-19. Реализация ещё не начата.

## 1. Назначение
Автономное приложение заметок с веб-интерфейсом. Первое размещение — сайт IIS на рабочем ПК Windows 7 без интернета. Последующее — сервер локальной сети для нескольких пользователей. Не является полной копией Obsidian.

## 2. Ограничения среды
- Классический ASP.NET / .NET Framework, C#, обработчики .ashx, общие классы App_Code.
- HTML, CSS, JavaScript; библиотеки включены в поставку, без CDN.
- MS SQL Express 2014 — основная служебная БД.
- Не требовать ASP.NET Core, Node.js, npm, Docker или установки системных компонентов на рабочем ПК.
- Версии Framework, компилятора C#, IIS и браузера уточнить до выбора библиотек.
- Access — только возможная будущая альтернатива служебной БД для локального использования; сейчас не реализуется.

## 3. Архитектура и данные
Браузер -> API .ashx -> C#-сервисы -> SQL Server и файловая система.
Markdown-файлы — источник истины для текста заметок. БД хранит пользователей, сессии, настройки, привязку хранилищ и восстанавливаемые индексы.
Личные файлы располагаются вне публичной папки сайта. Чтение заметок и вложений — только через API с проверкой доступа. SQL изолирован в слое доступа к данным, не в обработчиках. Будущий Access не должен требовать переписывания файловой логики; второй провайдер сейчас не нужен.

## 4. Пользователи
- Одноразовая инициализация первого администратора с последующим запретом повторного запуска.
- Вход, выход, смена пароля, тайм-аут сессии, блокировка учётной записи.
- Регистрация разрешается или запрещается администратором.
- Пароли не хранятся открытым текстом; алгоритм и параметры выбираются после проверки Framework.
- Каждый пользователь получает своё хранилище и настройки. Владелец определяется серверной сессией, а не userId из запроса.
- Администратору не предоставляется автоматический просмотр чужих заметок через интерфейс.
- Общие папки и совместное редактирование не входят в первую версию.
- Авторизация не защищает от прямого доступа администратора ОС к диску. Шифрование хранилища — отдельная будущая задача.

## 5. Хранилища
Каталоги vaults/<VaultId>, history и backups находятся в отдельном каталоге данных. Идентификаторы каталогов не зависят от логинов.
Поддерживаются русские имена, новые заметки UTF-8, исходная структура импортируемых папок. Неизвестная разметка и YAML-поля не удаляются. Конфигурация WebVault отделена от .obsidian. Содержимое .obsidian не исполняется и автоматически не перезаписывается.
Начальный импорт — подготовленная копия каталога с индексацией. Загрузка ZIP через браузер может быть добавлена позднее.

## 6. Основные функции
Дерево файлов и папок; создание и открытие заметок; Markdown-редактор и предпросмотр; ручное и автоматическое сохранение; переименование и перемещение; удаление с восстановлением; поиск по названию и тексту; загрузка и просмотр вложений.
Состояния сохранения: изменено, сохраняется, сохранено, ошибка, конфликт. Ошибка не очищает редактор. Перед заменой сохраняется предыдущая версия. API проверяет версию/хеш файла. Конфликт не приводит к молчаливому перезаписыванию: загрузка актуального текста либо сохранение конфликтной копии.
История версий не заменяет резервное копирование. Нужны согласованное резервирование БД и файлов и проверка восстановления.

## 7. Совместимость с Obsidian
Первый уровень: .md, сохранение YAML frontmatter, обычные Markdown-ссылки, [[Заметка]], пути и отображаемые имена wikilinks, изображения и вложения, сохранение неизвестных блоков. Неоднозначные ссылки требуют выбора.
Следующие этапы: подсказки ссылок, обратные ссылки, встраивания, заголовки и блоки, обновление ссылок при переименовании, редактор свойств, шаблоны и периодические заметки.
Не гарантируются исполнение плагинов Obsidian, Dataview/DataviewJS, Templater, Canvas и произвольного JavaScript в заметках. Неподдерживаемые блоки сохраняются как текст. Проверка выполняется на безопасной копии реального хранилища; личные заметки не коммитятся в исходный код.

## 8. Темы
Общий каталог пакетов тем на сервере; ручное добавление и обновление администратором. Пакет: manifest.json, theme.css, локальные ресурсы. Личный выбор темы, светлого/тёмного режима и акцента, возврат к встроенной теме.
Использовать документированный набор CSS-переменных. Произвольные темы Obsidian могут требовать адаптации и не считаются автоматически совместимыми. Не использовать обязательные внешние шрифты или изображения.

## 9. Индивидуальные настройки
В БД с привязкой к пользователю: оформление, шрифт, размер и межстрочный интервал; переносы и отступы; автосохранение; панели и их размеры; стартовая заметка; горячие клавиши; включённые расширения и их параметры.
Состояние вкладок и рабочей области хранить отдельно от общих предпочтений. Локальное хранилище браузера не является единственным источником настроек. Системная конфигурация отделена от пользовательской.

## 10. Расширения
После стабилизации ядра: администратор устанавливает пакеты, пользователь включает доступные и сохраняет личные параметры. Манифест содержит идентификатор, версию и совместимость с API. Нужен безопасный режим запуска без расширений.
Начальный API: команды, кнопки, панели, события открытия/сохранения, операции с заметками через проверяемый API, собственные настройки. Произвольные серверные DLL и команды ОС не поддерживаются. Совместимость с готовыми плагинами Obsidian не обещается.
Сторонний JS рассматривается как доверенный код; декларация разрешений сама по себе не является изоляцией.

## 11. Безопасность
Проверять владельца во всех операциях, включая поиск, вложения, историю и резервные копии. Ограничивать пути корнем хранилища, запрещать обход каталогов. Не публиковать папку данных. Предусмотреть защиту изменяющих запросов от CSRF и безопасное отображение Markdown без исполнения встроенных скриптов. Параметризованные SQL-запросы. Секреты, реальные заметки и локальная конфигурация не входят в Git. Перед сетевым развёртыванием определить HTTPS и настройки cookies.

## 12. Приёмка первой стабильной версии
- Полная работа без интернета.
- Два пользователя имеют раздельные заметки и настройки; прямые запросы не обходят доступ.
- Создание, сохранение, повторное открытие и восстановление удалённой заметки работают.
- Конфликт двух вкладок обнаруживается без потери текста.
- Вложения доступны только владельцу.
- Поиск и базовые ссылки работают.
- Смена темы одного пользователя не влияет на другого.
- Проверено восстановление файлов и БД из резервной копии.
- Подготовлена инструкция локального и сетевого развёртывания.

## 13. Порядок изменений
Реализованные и запланированные возможности отмечаются отдельно. Изменения требований фиксируются в новых спецификациях docs/specifications; статус реализации — в docs/project_overview.md.
