# Сноски: синтаксис footnote-syntax-20b

25.10.2026. Дополняет footnotes_20a.md и текущую передачу; прежние задачи/статусы не переписываются. Пользователь подтвердил полный набор 339/339 после восстановления завершающей скобки footnote_model.js (e732dae). Это база перед этим этапом, а не тестирование ещё не добавленных правил.

## Область
Добавлены readers определений/named/inline ссылок и opt-in расширение Lezer. createSourceMarkdown(findFrontmatter,{footnotes:true}) включает WVFootnoteDefinition/WVFootnoteReference/WVInlineFootnote с дочерними label/body/mark узлами. По умолчанию footnotes=false: текущий editor.js не включает новую грамматику, Markdown-it/DOM renderer не меняются. На сайте сноски ещё не отображаются новым способом; MD-FOOTNOTES-01 остаётся открытой. До подключения отображения пересборка/публикация сайта не требуются.

Определения распознаются eager block parser перед LinkReference только у корня Document, с корректным завершением предшествующего leaf. Frontmatter, fenced/indented/inline code и escape защищены контекстом исходной грамматики, не поиском regexp по всей заметке. Вложенные определения в list/blockquote и сноски внутри обычных ссылок/изображений этим первым этапом не поддержаны. %% comments ещё не реализованы общей грамматикой и отдельно не объявляются защищёнными данным комплектом.

## Тело определения и карты
Root definition: до 3 начальных пробелов, [^label]: и необязательный один пробел/tab после colon. Продолжение требует четырёх колонок отступа (spaces/tab). Пустые строки принадлежат телу только при последующем отступном продолжении; хвостовые пустые строки перед следующим блоком/определением не поглощаются. Дополнительный отступ после первых четырёх колонок сохраняется для кода внутри сноски. Это не правило слияния любых отступных code blocks.

Возвращаются body и bodyMap сегментов {from,to,bodyFrom,bodyTo}; каждый текстовый/EOL сегмент связан с исходными UTF-16 диапазонами. Удаление структурного отступа относится только к отдельной строке body для будущего разбора, не к исходному документу. LF/CRLF сохраняются helper-слоем, пустые строки и внешний текст не переписываются. В CodeMirror сборщик использует state.doc.toString(), то есть диапазоны именно текущего CM-документа.

Named labels следуют буквальному контракту 20a. Inline ^[...] сейчас однострочный, до 8192 UTF-16 единиц, с балансом скобок до глубины 32, escape и literal inline code; незавершённые/пустые/превышающие ограничения конструкции остаются исходным текстом. Вложенные footnotes внутри body не собираются как отдельные notes. Форматирование body сохраняется строкой, но его богатое отображение — следующий этап.

collectFootnoteSyntax(text,tree) обходит только созданные грамматикой узлы, сверяет их диапазоны с readers и передаёт события resolveFootnotes. Возвращает также definitionSources с картами; при дубликатах брать карту по исходному from выбранного определения, не только по label. Никаких DOM IDs из пользовательских меток, сетевых запросов или изменений EditorState/selection тут нет.
