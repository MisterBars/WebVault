## Первая панель свойств
Существующий frontmatter сверху: поле имени и типизированное значение. Dynamic — редактирование текста, чисел, boolean, дат, локального datetime без часового пояса, простых строковых списков/tags. Read — те же поля без редактирования. Source — исходный YAML. Списки показываются chips, Изменить открывает редактор по строке на значение, commit при change/уходе фокуса; Ctrl+S коммитит активное поле перед сохранением. Числа/даты проверяются.

Это первая версия, не весь Properties UI Obsidian: добавление/удаление/переименование свойств, изменение их типов, общая схема типов и автодополнение пока через исходник/будущие настройки. Отсутствующий frontmatter не создаётся автоматически. Сложные карты/списки с комментариями/aliases/anchors/tags, null, большие целые и ошибки YAML доступны без потерь в исходнике, панель их не переписывает. До 100 полей/16 KiB YAML. Нестандартные значения даты/времени остаются текстом.

Изменение проходит через транзакцию CM и автосохранение, не через присваивание всего value. Меняется диапазон только значения, не весь документ. Кавычки/стиль изменённого значения могут нормализоваться в JSON-совместимый YAML; остальные свойства и тело остаются как были. Повторный разбор проверяет результат. Native undo внутри активного input и undo документа после commit различаются. Проверить клавиатуру/фокус/IME; node-тесты не доказывают работу DOM.

## Кнопки и корзина
В CM скрыты обычные Сохранить/Перечитать, но обработчики остаются для совместимости; Ctrl+S/автосохранение/повтор при ошибке сохранены. При конфликте сначала скопировать несохранённый текст, не перезагружать вслепую; диалога разрешения конфликтов ещё нет. Без CM резервный textarea сохраняет старые ручные действия.

Существующая кнопка корзины переносится красной SVG-иконкой в самый низ ribbon (order1000), для личного пользователя. Число — записи корзины, не рекурсивное количество файлов. После trash/restore/purge/clear запрашивается список и обновляется badge/tooltip; устаревшее сообщение о последней группе с быстрым восстановлением скрыто. При ошибке счётчик ?, не ложный 0. Таблица корзины/серверные операции не меняются.

После этого продолжить флажки задач/матрицы с датой и прочие Markdown-задачи — этим комплектом они не реализованы.

## Дополнение 22.10.2026: создание свойств, кандидат properties-add-04
Предыдущая панель chips/ссылок/автодополнения сохранена. Новый локальный кандидат добавляет строку-кнопку «＋ Добавить свойство» в dynamic/reading, в том числе у заметки без frontmatter. Форма предлагает стандартные tags/aliases/cssclasses (списки) и известные имена личного индекса со значками, позволяет ввести новое имя и начальный тип. Подсказки имён до 30 вариантов, каталог до 1000 имён; повторяющиеся имена текущей заметки исключаются из меню и проверяются перед записью без учёта регистра. Конфликт типов в разных заметках не разрешается автоматически: форма предупреждает, тип выбирается для новой записи. Общая схема типов для всего хранилища этим не реализована.

Типы создания: текст, простой строковый список, число, флажок, дата, локальные дата/время. Для даты/времени требуется начальное значение, системный picker пока сохранён; тематический календарь остаётся задачей. Пустой список создаётся как []; значение текста, распознаваемое текущим parser как дата, не выдаётся молча за текст: нужно выбрать подходящий тип. Типы уже существующих свойств пока не изменяются. cssclasses можно создать/хранить; применение CSS-классов к заметке не входит в комплект.

Запись через propertyAddChange и существующую транзакцию CM, с текущими защитами пользователя/заметки/буфера. Изменение вставляется перед закрывающей границей YAML; существующие поля, комментарии и тело не сериализуются. Если frontmatter нет, создаётся в начале с сохранением BOM и исходного тела. Незавершённый/ошибочный YAML, дубликаты, превышение лимитов и опасные числа отклоняются; результаты повторно разбираются. Undo документа после commit проверять в source. Несохранённую форму добавления перед сменой режима нужно завершить или отменить; другие черновики списков предварительно подтвердить.

В dynamic без YAML используется синтетический block-widget нулевой длины: он не заменяет текст, не получает фиктивный исходный номер и не входит в atomicRanges. Унаследованы лимиты и ошибки личного индекса/графа; при недоступности индекса стандартные имена и ручной ввод остаются.
