# Панель свойств и корзина внизу ribbon

## Обновление
Дома из tools/cm6: npm install (yaml 2.8.1), npm test, затем при успехе npm run build; перенести bundle, Ctrl+F5. Сохранить lock, node_modules не коммитить. SQL/Web.config не меняются.

## Первая панель свойств
Существующий frontmatter сверху: поле имени и типизированное значение. Dynamic — редактирование текста, чисел, boolean, дат, локального datetime без часового пояса, простых строковых списков/tags. Read — те же поля без редактирования. Source — исходный YAML. Списки показываются chips, Изменить открывает редактор по строке на значение, commit при change/уходе фокуса; Ctrl+S коммитит активное поле перед сохранением. Числа/даты проверяются.

Это первая версия, не весь Properties UI Obsidian: добавление/удаление/переименование свойств, изменение их типов, общая схема типов и автодополнение пока через исходник/будущие настройки. Отсутствующий frontmatter не создаётся автоматически. Сложные карты/списки с комментариями/aliases/anchors/tags, null, большие целые и ошибки YAML доступны без потерь в исходнике, панель их не переписывает. До 100 полей/16 KiB YAML. Нестандартные значения даты/времени остаются текстом.

Изменение проходит через транзакцию CM и автосохранение, не через присваивание всего value. Меняется диапазон только значения, не весь документ. Кавычки/стиль изменённого значения могут нормализоваться в JSON-совместимый YAML; остальные свойства и тело остаются как были. Повторный разбор проверяет результат. Native undo внутри активного input и undo документа после commit различаются. Проверить клавиатуру/фокус/IME; node-тесты не доказывают работу DOM.

## Кнопки и корзина
В CM скрыты обычные Сохранить/Перечитать, но обработчики остаются для совместимости; Ctrl+S/автосохранение/повтор при ошибке сохранены. При конфликте сначала скопировать несохранённый текст, не перезагружать вслепую; диалога разрешения конфликтов ещё нет. Без CM резервный textarea сохраняет старые ручные действия.

Существующая кнопка корзины переносится красной SVG-иконкой в самый низ ribbon (order1000), для личного пользователя. Число — записи корзины, не рекурсивное количество файлов. После trash/restore/purge/clear запрашивается список и обновляется badge/tooltip; устаревшее сообщение о последней группе с быстрым восстановлением скрыто. При ошибке счётчик ?, не ложный 0. Таблица корзины/серверные операции не меняются.

## Проверки
00: все типы, списки aliases/tags/related, enabled; read не пишет; source видит сохранённое; Ctrl+Z/автосохранение/Ctrl+S активного поля; ошибки YAML/чисел/дат, комментированные/сложные значения; смена пользователя; корзина снизу при графе/заметке, очистка/восстановление меняют счётчик, forced password/admin не получают доступ. После этого продолжить флажки задач/матрицы с датой и прочие Markdown-задачи — этим комплектом они не реализованы.
