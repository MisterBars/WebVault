# Новая установка WebVault: ПК, ноутбук, рабочее место

Это инструкция для новой пустой БД. При восстановлении существующей БД пользователи и хеши паролей уже присутствуют: первоначальную настройку не запускать. Код проекта не содержит личных данных и не синхронизирует их между установками. Новые независимые БД — независимые пользователи и будущие заметки.

## 1. Подготовить файлы
На машине с интернетом получить репозиторий. На изолированный ПК переносить разрешённым способом. IIS должен обслуживать только src/WebVault.Web, не корень репозитория с .git/docs/database. Путь может отличаться; ниже пример D:\project\WebVault. Системные компоненты на рабочем ПК не скачивать.

## 2. IIS
Создать WebVaultPool: CLR v4.0, Integrated, Identity ApplicationPoolIdentity. Создать сайт WebVault: путь D:\project\WebVault\src\WebVault.Web, пул WebVaultPool, локальная HTTP-привязка 127.0.0.1:8085, имя узла пустое. После создания открыть основные параметры сайта и повторно проверить назначенный пул: DefaultAppPool не подходит.
Пулу нужен доступ чтения/выполнения. Из административного PowerShell:

```powershell
icacls 'D:\project\WebVault\src\WebVault.Web' /grant 'IIS AppPool\WebVaultPool:(OI)(CI)RX'
```

Не выдавать запись к исходникам и Everyone Full Control. Файловое хранилище заметок пока не подключено.

## 3. SQL Server
Этот сценарий предполагает SQL Server и IIS на одном компьютере. В SSMS под администратором выполнить целиком и по порядку:
1. database/install/00_database.sql
2. database/install/01_grant_apppool_access.sql
3. database/install/02_auth.sql

Используются отдельная БД WebVault и IIS APPPOOL\WebVaultPool. Не изменять БД/пул ВВТ и не выдавать db_owner. На другой машине имена пула должны совпадать со скриптом или быть согласованно заменены.

## 4. Локальный Web.config
При первой установке скопировать Web.config.example в Web.config рядом. Если Web.config уже есть, не заменять целиком — объединять новые настройки. Server должен указывать на экземпляр этой машины; Database=WebVault; Integrated Security=True. Не переносить домашнее имя компьютера как обязательное значение.
Внутри configuration должна быть одна секция appSettings:

```xml
<appSettings>
  <add key="AdminSetupEnabled" value="false" />
  <add key="AdminSetupKey" value="" />
</appSettings>
```

## 5. Проверить каркас
Открыть http://127.0.0.1:8085/index.html. Обе проверки должны вернуть HTTP 200; SQL — database=ok. Открыть api/auth/me.ashx без входа: ожидается 401 unauthenticated. Ошибка компиляции вместо JSON требует исправления до следующих действий.

## 6. Сгенерировать временный ключ
На самой машине выполнить PowerShell:

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
[Convert]::ToBase64String($bytes)
```

Результат — строка Base64 длиной 44 символа. Это временный ключ первоначальной настройки, не пароль пользователя. Не отправлять в чат, не сохранять в Git. Для независимой новой установки генерировать новый.

## 7. Временно включить настройку
В действующем Web.config, не в .example, изменить AdminSetupEnabled на точное значение true маленькими буквами. В AdminSetupKey вставить сгенерированную строку. Сохранить. Не создавать вторую секцию appSettings.

## 8. Создать первого администратора
На этом же компьютере открыть http://127.0.0.1:8085/auth.html, раскрыть первоначальную настройку, ввести тот же ключ, логин, имя и пароль с повтором. Логин: 3–64 символа латиницы/цифр/точки/дефиса/подчёркивания. Пароль: 15–128 символов. Имя можно по-русски. Дождаться сообщения об успехе.

## 9. Обязательно выключить настройку
Сразу вернуть AdminSetupEnabled=false и AdminSetupKey пустую строку. Сохранить Web.config, затем войти. Повторное создание первого администратора запрещается при наличии любого пользователя. Не удалять пользователей из БД ради повторного setup.

## 10. Проверить вход и дополнительные учётные записи
На auth.html выполнить вход, проверку сессии, обновление страницы и выход. После выхода me должен возвращать 401. Под администратором открыть users.html: создать второго обычного пользователя. Проверить его вход отдельно; доступ к api/admin/users.ashx должен быть запрещён с 403.

## Типовые ошибки
- setup_disabled: AdminSetupEnabled не точное true либо ключ короче 40 символов. Проверить действующий Web.config и физический путь сайта.
- setup_key_rejected: ключ в форме не совпадает с конфигурацией.
- already_initialized: БД уже содержит пользователя, нужно входить, а не создавать первого.
- SQL отказ для DefaultAppPool: сайту не назначен WebVaultPool.
- 429 rate_limited: сработал временный лимит попыток входа/настройки, ждать истечения. Не отключать защиту наугад.
- login_exists: логин уже занят без учёта регистра.

## Перенос существующей установки
Не путать с установкой с нуля. Нужны согласованный бэкап/восстановление БД, будущего файлового хранилища и локальных настроек; подробный регламент резервирования ещё не реализован. После восстановления БД заново привязать Windows login/пользователя пула на целевой машине и проверить доступ. Не предполагать, что пользователи Windows автоматически перенеслись с резервной копией БД. Старые сессии перед использованием перенесённой БД следует отозвать. Первоначальную настройку оставить выключенной.

## Ограничения
Пока проверено пользователем создание администратора и работа авторизации дома в общем виде; отдельные негативные проверки и рабочий Framework 4.5 не подтверждены. Не публиковать сайт в интернете. Удалённый вход по HTTP запрещён кодом; локальная сеть потребует отдельного HTTPS-развёртывания.
