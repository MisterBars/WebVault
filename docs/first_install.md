# Новая установка WebVault: ПК, ноутбук, рабочее место

Инструкция для новой пустой БД. При восстановлении существующей БД администратора заново не создавать. Независимые установки имеют независимые БД и пользователей; код сам их не синхронизирует.

## 1. Файлы и IIS
Получить исходники на ПК с интернетом, на изолированную машину перенести разрешённым способом. IIS публикует только src/WebVault.Web, не .git/docs/database.
Создать пул WebVaultPool: CLR v4.0, Integrated, ApplicationPoolIdentity. Создать сайт с этим пулом; повторно проверить назначение, не оставлять DefaultAppPool. Пример пути D:\project\WebVault\src\WebVault.Web, привязка HTTP 127.0.0.1:8085, имя узла пустое. Порт свободен.
Пулу дать чтение/выполнение, не запись исходников. Административный PowerShell:

```powershell
icacls 'D:\project\WebVault\src\WebVault.Web' /grant 'IIS AppPool\WebVaultPool:(OI)(CI)RX'
```

## 2. SQL
IIS/SQL на одной машине. В SSMS под администратором выполнить целиком по порядку:
1. database/install/00_database.sql
2. database/install/01_grant_apppool_access.sql
3. database/install/02_auth.sql
4. database/install/03_user_lifecycle.sql
5. database/install/04_user_management.sql

Отдельные WebVault и IIS APPPOOL\WebVaultPool, без db_owner. Не менять ВВТ. На существующей установке перед новыми миграциями бэкап; уже применённые скрипты повторять не требуется.

## 3. Конфигурация
На новой установке скопировать Web.config.example в Web.config рядом. При обновлении не перезаписывать существующий файл целиком. Server в строке подключения — локальный SQL-экземпляр этой машины, Database=WebVault, Integrated Security=True. Конфигурацию и секреты в Git не добавлять.
В configuration одна секция:

```xml
<appSettings>
  <add key="AdminSetupEnabled" value="false" />
  <add key="AdminSetupKey" value="" />
</appSettings>
```

## 4. Проверки до настройки
index.html: ASP.NET и SQL HTTP 200. Без входа api/auth/me.ashx: 401 unauthenticated. Ошибку компиляции сначала устранить. Использовать один адрес origin, например везде 127.0.0.1:8085.

## 5. Ключ и первый администратор
Сгенерировать на машине PowerShell:

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
[Convert]::ToBase64String($bytes)
```

Результат — 44 символа Base64; это временный ключ, не пароль. Не присылать его в чат и не коммитить. Для новой независимой установки новый ключ.
В действующем Web.config установить AdminSetupEnabled=true (точно маленькими буквами), AdminSetupKey=полученная строка. Сохранить. Открыть http://127.0.0.1:8085/auth.html локально. Форма настройки появится только при включении, корректной длине ключа и пустой таблице пользователей.
Ввести тот же ключ, логин (3–64 латинских символа/цифры/точка/дефис/подчёркивание), имя (можно русское), пароль 15–128 символов и повтор. После успеха форма исчезает. СРАЗУ вернуть AdminSetupEnabled=false и очистить AdminSetupKey. Сохранить, затем войти.

## 6. Разделы и тест
Администратор попадает в users.html, создаёт обычную личную учётку. Обычный пользователь — workspace.html (пока каркас, не редактор). Навигация и выход есть на страницах. Проверить отдельной учёткой запрет административного API. Полные проверки авторизации в TEST_CHECKLIST.md, новых действий в user_management.md.

## Ошибки
setup_disabled — включение не true или ключ короче 40; setup_key_rejected — ключ формы другой; already_initialized — нужно входить в существующую учётку; SQL DefaultAppPool — проверить назначение пула; login_exists — логин занят (мягкое удаление не освобождает); user_changed_reload_list — обновить список; 429 — лимит попыток, не отключать защиту.

## Существующая установка на другой машине
Это не новая настройка: нужны согласованные копии БД, будущих файлов и локальной конфигурации. После восстановления заново проверить login/user пула SQL на целевой машине и отозвать старые сессии. setup оставить выключенным. Полный регламент бэкапа/переноса данных ещё предстоит реализовать.

## Ограничения
Рабочий Framework 4.5 и новые изменения отдельно проверяются. Не публиковать в интернете. Удалённый HTTP-вход запрещён; локальная сеть потребует HTTPS и отдельной проверки. Системные компоненты на рабочем ПК не скачивать. Полное удаление пока удаляет только учётку/сессии; заметки ещё не реализованы.
