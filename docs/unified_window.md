# Единое окно WebVault — UI v0.2

Статус: код подготовлен, не проверен в браузере/IIS. Этот документ заменяет прежнюю модель отдельных страниц из application_design.md. Нового SQL/Web.config нет: схема 00–05/DataRoot сохраняются.

## Устройство
Единственная рабочая страница index.html. Вход и настройки — native dialog.showModal(), без iframe и динамического исполнения HTML страниц. application.js управляет клиентским состоянием, ролями и API; общий ui.js старых страниц больше не загружается в новой оболочке. Старые auth/workspace/users/account HTML — только перенаправления. Старые CSS/JS сохранены в Git как неиспользуемый код для последующей очистки.
Гость видит пустой фон без личных данных и модальный вход. Закрыть вход можно крестиком/Escape: останется пустой фон и кнопка входа. Вошедший пользователь видит только свой список файлов, исходный редактор, отдельную область ribbon для будущих ярлыков плагинов (пока пустая), настройки внизу и выход. Администратор вместо файлов имеет меню пользователей, диагностики и настроек; личный файловый API ему по-прежнему запрещён. Настройки обеих ролей — единая модалка с отдельной навигацией; реализован пока только раздел учётки/пароля. Остальные разделы не имитируются неработающими кнопками.

## Вход и сессия
Вход использует прежние login/me/setup API; серверное условие показа setup сохранено. Все формы отменяют стандартную отправку, пароли не помещаются в URL. Native dialog блокирует фон, удерживает фокус; стандартный Escape и закрытие доступны, во время операции Escape блокируется. Проверить клавиатуру и возврат фокуса отдельно. Не считать модальное окно средством авторизации: доступ проверяется сервером.
При обнаружении 401 личные панели скрываются, открывается вход. Черновик заметки остаётся только в памяти этой вкладки, скрыт и может продолжиться после входа той же учёткой. Обновление/закрытие страницы его потеряет; localStorage не используется. Вход другой учёткой очищает буфер. При явном выходе после подтверждения несохранённый буфер очищается. Уже запущенный сторонний код/XSS и доступ администратора ОС не входят в эту защиту. Это не шифрование памяти или диска.
Универсальное автоматическое опрашивание сессии пока не добавлено: истечение обнаруживается следующим защищённым действием. На бездействующем экране ранее показанное содержимое само по таймеру не исчезает. Проверка смены аккаунта перед действием предотвращает продолжение в обнаруженной другой сессии; полноценное межвкладочное управление ещё не реализовано.

## Диагностика
Ссылок для гостя/обычного пользователя нет. GET api/health.ashx требует действующую административную сессию и локальный запрос. Без входа 401, обычной учётке 403 administrator_required. Удалённый HTTP отклоняется общим https_required; даже по HTTPS удалённая диагностика пока local_only. Проверка роли выполняется до метрик. Если сама БД недоступна, проверка сессии может вернуть 503 с общим errorId — анонимного обхода ради диагностики нет. Локальную начальную установку до создания администратора проверять через IIS/SSMS и публичный setup_status, а не через health.

## Сохранённые функции
Создание/чтение/ручное сохранение заметок, версии/конфликт, фильтр имени и Ctrl+S/Ctrl+O. Вкладка одна, только корневые файлы, нет папок/Live Preview/автосохранения. Admin users: создание, переименование, два удаления, показ мягко удалённых. Полное удаление владельца хранилища остаётся защищено FK, не обходить. Свой пароль — с текущим паролем и отзывом всех сессий, после успеха открывается модальный вход, черновик той же учётки остаётся в памяти.

## Обновление
Сохранить несохранённые заметки перед обновлением. Получить код без принудительного сброса локальных изменений. Особое внимание локально изменённому health.ashx: серверная защита администратора обязательна, не оставлять старый анонимный обработчик. SQL/данные не пересоздавать. Открыть index.html, Ctrl+F5. На новой машине сначала применить 00–05 и DataRoot; инструкция first_install.md обновлена.
