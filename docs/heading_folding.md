# Сворачивание разделов заголовков — headings-fold-11

[Контракт оформления](theme_contract.md) · [Changelog](../CHANGELOG.md) · [Задачи](next_steps.md).

## Область комплекта
Кандидат FOLD-HEADINGS-01 и FOLD-UI-02. В dynamic/reading у отрисованных заголовков с содержимым добавлена SVG-кнопка. Она сворачивает раздел до следующего заголовка того же или более высокого уровня; дочерние разделы сохраняют собственные флаги. Пустой раздел без блоков не получает фиктивную стрелку. Заголовки распознаются по токенам markdown-it, включая Setext; заголовки внутри кода/списка/цитаты отдельными верхними разделами не считаются.

Обычный клик по стрелке не раскрывает Markdown и не редактирует заметку. После раскрытия заголовок временно остаётся отрисованным даже при прежней позиции курсора, пока пользователь явно не переместит его/не кликнет по тексту. Клик по тексту свёрнутого заголовка в dynamic раскрывает раздел для редактирования исходника. В reading тело остаётся read-only.

## Состояние и source
Состояние разделов хранится в EditorState, согласуется между dynamic/reading и штатными source fold/unfold для заголовков. Позиции переносятся при изменениях выше, удалённые заголовки не передают collapse-флаг соседним. Попытка перевести выделение внутрь скрытого содержимого раскрывает раздел; atomicRanges не оставляет обычный курсор внутри скрытого виджета. Новая загрузка заметки создаёт новое состояние: collapse не записывается в YAML/SQL/на сервер.

При переключении режимов native fold replacements очищаются, чтобы не пересекаться с блочными виджетами; source восстанавливает диапазоны разделов из общего состояния. Native fold-состояние прочих контейнеров (списки/код/таблицы) в этом комплекте между режимами не переносится: их визуальное сворачивание — следующий отдельный этап. Штатное сворачивание кода в source не отключается глобально.

## YAML
source_markdown.js добавляет явный верхний синтаксический узел WVFrontmatter для полного YAML-блока, используя существующий findFrontmatter. У него foldNodeProp возвращает null; он не становится ошибочным Setext-заголовком. Убирается источник ошибочного folding, а не просто скрываются все стрелки CSS. Enter/Backspace и прочая поддержка markdown() остаются штатными. Подсветка полноценного YAML-языка не добавлена. Неполные разделители не угадываются как валидный frontmatter. Панель свойств и её редакторы не заменяются details.

## Сохранность данных
Toggle отправляет только эффекты/при необходимости положение курсора с addToHistory:false, без docChanged/input. Для view-only кнопок общий click-gate автосохранения не форсирует сохранение; уже запланированное автосохранение обычного ввода продолжает работать. Если есть незавершённый ввод/форма свойств, сначала завершить или отменить его: reading не должен потерять черновик при перестройке DOM. Команды Undo/Redo заметки не превращаются в историю UI-сворачивания.

## Исправление кандидата 11b: замена native-эффекта
Первый пользовательский запуск: базовые 23 теста прошли; из дополнительного набора 42 прошёл 41. Проверка native heading fold без native overlap нашла сохранённый native диапазон при уже установленном rendered-флаге. Кандидат не был принят/закоммичен, сборка остановлена.
В 11b transactionFilter явно заменяет исходные fold/unfold заголовка эффектом rendered-состояния, не оставляя foldEffect заголовка в итоговом spec. Посторонние эффекты, изменения и аннотации сохраняются; native replacements внутри закрываемого раздела очищаются. Source и native fold кода вне этого преобразования не отключаются. Исходный тест с foldedRanges.size===0 не ослаблен; добавлены 4 проверки аннотаций/посторонних эффектов, обычного code fold, очистки дочернего native fold и одновременного изменения текста/истории.
Ассистент проверил только синтаксис фрагмента и новых тестов; реальные интеграционные тесты CodeMirror в своей среде не запускал. Нужен повтор всего тестового набора и затем браузерная проверка. Метка основного комплекта headings-fold-11 сохранена, дополнительная window.__WV_FOLD_FIX_TEST='native-fold-rewrite-11b'. До приёмки задачи не закрыты.
