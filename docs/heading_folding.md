## Область и статус

Описанный контракт разделов и YAML-folding имеет ограниченную ручную приёмку 22.10.2026; раннее «кандидат» относится к первоначальному отчёту до исправления, не к отсутствию принятой функции. Подробные исторические свидетельства вынесены в npm_build.md; эта редактура согласует сохранённые документы/ограничения, не новый полный аудит JS или Node/CM/DOM/Firefox/IIS-прогон.

В dynamic/reading заголовок с содержимым получает SVG-кнопку, скрывающую раздел до следующего заголовка того же или более высокого уровня. Дочерние разделы сохраняют флаги; пустому разделу без блоков фиктивная стрелка не добавляется. Ранний отрисованный путь распознавал заголовки markdown-it, включая Setext; код/списки/цитаты не становились отдельными верхними разделами.

Обычные ATX/Setext-заголовки dynamic позднее получили нативный CM-путь, описанный в live_preview_blocks.md. Его fold-кнопка — отдельный inline-widget, закрытый заголовок остаётся редактируемым; это не возврат к цельному виджету. Сведения раннего отрисованного пути не подменяют поздний нативный контракт. Reading остаётся read-only.

## Ранний отрисованный путь

Обычный клик стрелки не раскрывал Markdown и не редактировал заметку. После раскрытия заголовок временно оставался отрисованным при прежнем курсоре до явного перемещения/клика по тексту. Клик текста свёрнутого заголовка dynamic раскрывал раздел для редактирования исходника. Это сохранённое описание первоначального пути, не универсальное правило клика современных нативных заголовков.

## Состояние и source

Состояние разделов хранится в EditorState, согласуется dynamic/reading и штатными source fold/unfold заголовков. Позиции переносятся при изменениях выше; удалённые заголовки не передают collapse-флаг соседним. Попытка переместить выделение внутрь скрытого содержимого раскрывает раздел; atomicRanges не оставляет обычный курсор внутри скрытого виджета. Reopen создаёт новое состояние: collapse не пишется в YAML/SQL/на сервер.

При смене режима native fold replacements очищаются во избежание пересечений с блочными виджетами; source восстанавливает диапазоны разделов из общего состояния. Перенос native fold-состояния списков/кода/таблиц этим контрактом не реализован. Штатный code folding source не отключается глобально; все контейнеры не считаются покрытыми одним heading-folding.

transactionFilter заменяет исходные fold/unfold заголовка эффектом rendered-состояния, не оставляя исходный foldEffect заголовка в итоговом spec. Сохраняет посторонние эффекты/изменения/аннотации, очищает native replacements внутри закрываемого раздела. Source и native code fold вне этого преобразования не отключаются. Это описанное исправление конфликта native/rendered, не ослабление проверки отсутствия overlap.

## YAML

source_markdown.js создаёт явный верхний узел WVFrontmatter для полного блока через findFrontmatter. foldNodeProp возвращает null: YAML не ложный Setext-заголовок. Исправляется источник ошибочного folding, не глобальное скрытие стрелок CSS. Enter/Backspace и прочая поддержка markdown() остаются штатными; полноценный YAML language highlighter этим не добавлен. Неполные разделители не угадываются как frontmatter; панель свойств/редакторы не заменяются details.

## Сохранность данных

Toggle отправляет эффекты и при необходимости положение курсора с addToHistory:false, без docChanged/input. View-only кнопки не форсируют save общим click-gate; уже запланированное autosave ввода продолжает работу. Незавершённые поля/формы свойств сначала завершить или отменить, чтобы reading-перестройка не потеряла черновик. Undo/Redo документа не история UI-сворачивания.

## Темы и диагностика

.wv-heading-fold-host, button.wv-heading-fold-button[aria-expanded], data-wv-heading-fold/data-wv-view-only; style id wv-heading-fold-style. SVG currentColor, --wv-heading-fold-offset с fallback -24px; text-muted/normal, background-modifier-hover, interactive-accent, radius-s. Номера gutter остаются исходными; его размещение — editor_gutters.md. Селекторы позднего native path — live_preview_blocks.md.

Метки window.__WV_FOLD_TEST='headings-fold-11' и window.__WV_FOLD_FIX_TEST='native-fold-rewrite-11b' относятся к исполняемым диагностическим веткам, не релизу/публикации/пройденным тестам.

## План проверки и обновление

На копии проверить parent/child/соседние разделы, кнопки/клавиатуру, отсутствие непредусмотренного сырого Markdown после стрелки, отдельный нативный заголовок, состояния между режимами, YAML без ложных стрелок при работающем code folding, неизменность текста/Undo/свойств/календаря/gutter. Reopen и постоянное хранение collapse не смешивать с переключением режима. Это план, не выполненная этой редактурой регрессия.

Для функционального изменения выбирать адресные heading-fold/Markdown/CM проверки; сохранять строгое foldedRanges.size===0 для исключения native/rendered overlap, посторонние эффекты/аннотации, обычный code fold, очистку дочернего native fold и одновременное изменение текста/истории. Затем test:all → build после успеха → отдельная публикация → браузер по npm_build.md. Конкретный состав публикации определять по изменению; первоначальная инструкция сохранена со свидетельствами, не как доказательство выполненной публикации. Docs-only не требует install/build/публикации.

## Исторические свидетельства и дефект

Первоначальный кандидат, выявленный overlap, исправление и ограниченная ручная приёмка содержательно перенесены в [npm_build.md](npm_build.md#folding-и-сохранность-исходников). Там сохранены исходные числа и незапущенные проверки, остановленная сборка, строгая проверка и четыре регрессии; поздняя ручная приёмка не заменяет полный повторный набор. Событие — в месячной истории. Подробные результаты здесь больше не дублируются.
