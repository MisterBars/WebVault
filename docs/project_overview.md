# WebVault — состояние проекта

## Подтверждено пользователем
Единая оболочка d522846 выглядит как нужно. Ранее основные домашние сценарии авторизации/учёток, первых заметок и оформления приняты в общем виде. Не считать это подтверждением всех негативных/конкурентных тестов или проверки рабочего Framework 4.5.

## Новый этап — только требования
Зафиксировано specifications/002-editor-files-and-accounts.md: административный временный пароль с обязательной сменой; свой DisplayName; папки; контекстное меню и реестр команд будущих плагинов; операции файлов и корзина; независимый undo/redo; очередь автосохранения. Эти возможности ещё НЕ реализованы этим коммитом. Ник трактуется как отображаемое имя, не смена логина.

## Порядок реализации
1. Учётки: административный временный пароль, MustChangePassword/защищённый ограниченный вход, свой DisplayName, модальные формы и тесты.
2. Разделить application.js на модули, сохранить поведение.
3. Папки/относительные пути/дерево.
4. Реестр команд и ПКМ, переименование/копирование/перемещение/корзина.
5. Настоящий редактор с undo/redo, проверенная автономная сборка.
6. Автосохранение и интеграция с конфликтами/файловыми операциями.
7. Регрессия и рабочий ПК.
Все API сопровождать UI/инструкциями. Не расти одним монолитным application.js и не вводить автозапись одновременно с непроверенным перемещением файлов.

## Что существует сейчас
index.html, вход/настройки dialog, меню администратора вместо файлов, диагностика только локальному администратору с серверной проверкой. Обычная учётка работает с корневыми .md через textarea и ручное сохранение, SHA-256 конфликты, история-копии без полноценного UI. storage.UserVaults, схема 00–05 и DataRoot. Папки/файловая корзина/автосохранение/реестр плагинов отсутствуют. Собственный пароль менять можно, административного сброса пока нет. DisplayName пользователь сам пока не меняет.

## Ограничения
Владельцы хранилища защищены FK от полного удаления. Внешние писатели Obsidian/синхронизаторы одновременно не использовать. Нет автоматической блокировки бездействующего окна по таймеру; 401 открывает вход при действии. Черновик только в памяти вкладки, после входа другой учёткой/выхода очищается, после перезагрузки теряется. Самостоятельная регистрация/роли/восстановление пароля/полные логи/бэкап/темы/исполнение плагинов в плане.

## Документы и среда
unified_window.md и first_install.md актуальны для единого окна; новое ТЗ 002 расширяет план, не меняет работающую установку. Этот коммит не требует SQL/Web.config/обновления браузера. Разработка D:\project\WebVault, цель Windows 7/.NET Framework 4.5/Firefox 113, IIS/SQL Express 2014 вместе, WebVaultPool/Integrated Security, данные отдельно. Системные компоненты на работе не скачивать, все клиентские библиотеки поставлять локально. Администратор ОС вне модели приватности; изолированные установки сами не синхронизируются.
