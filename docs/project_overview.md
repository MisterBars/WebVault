## Границы развития

Одна шапка вкладки не система документов/split. pluginShortcuts и WebVaultCore не готовый loader/стабильный внешний API расширений. Сохранение заметки не восстанавливает историю после reopen/reload; несколько native drafts — отдельная работа. Папки/корзина/Live Preview/autosave уже имеют реализации: старые отрицательные статусы ниже не возвращают их в очередь создания с нуля.

Полная трассировка обоих ТЗ/backlog, инвентаризация всех HTTP-маршрутов, аудит серверных границ и оставшаяся архитектурная сверка открыты. Полные требования/ID — [next_steps.md](next_steps.md); очередь D не запускает P. Эта карта не закрывает требования одним наличием руководства.

Ниже сохранён ранний снимок вокруг 26a0007 и последующего изменения сессий, не текущая очередь. Комплект — ник и административные временные пароли — по исходному сообщению работал дома. ## Последующее изменение сессий и UX

Сохранённое описание: AccountHandler при собственном нике отзывает остальные сессии; собственный пароль сохраняет текущий SessionId с вращением session/CSRF токенов, снимает MustChangePassword и отзывает остальные. Административный reset отзывает все сессии цели. UserManagementHandler при административном rename отзывает все сессии цели, включая изменение только ника. Клиент подставляет временный пароль только из выполненного login, фокусирует новый и после собственной смены продолжает без нового входа. Канонический текущий контракт — session_policy.md; серверные ветки этим архитектурным пакетом заново не проверялись.

## Применение раннего комплекта

Исходная процедура: сохранить заметки, получить код, Ctrl+F5; требовалась уже существующая миграция 06, новых SQL/Web.config в том комплекте не было. Проверять на независимых браузерных профилях, не путать общие cookies вкладок с разными сессиями. Это исторический состав, не текущий полный регламент обновления.

## Тогдашний следующий приоритет

Полное удаление пользователя вместе с каталогом заметок, историей и связью storage.UserVaults: отслеживаемая очистка/повтор после сбоев, без обхода FK и без ложного успеха. В раннем комплекте операция для владельца хранилища была заблокирована и тем изменением не реализовывалась. Это не текущий запрет отдельного purge_user: процедура — folders_and_purge.md. Тогдашние направления — модульный рефакторинг, папки/ПКМ/команды, undo/redo и autosave по ТЗ 002 — сохранены для трассировки, не автоматическая очередь P.

## Система в раннем снимке

index.html с модальными входом/настройками; административное меню вместо файлов и защищённая локальная диагностика. Личная учётка: корневые .md, textarea, ручное сохранение, конфликты SHA-256. Папки/корзина/реестр плагинов/Live Preview/autosave назывались отсутствующими тогда, не сейчас. NormalizedLogin уникален на уровне БД, DisplayName нет. Ранний текст называл журнал AccountEvents с ID/временем без паролей; это имя не текущий контракт БД: подтверждённый reset-аудит auth.PasswordResetEvents описан в session_policy.md.
