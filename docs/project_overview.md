## Границы развития

Одна шапка вкладки не система документов/split. pluginShortcuts и WebVaultCore не готовый loader/стабильный внешний API расширений. Сохранение заметки не восстанавливает историю после reopen/reload; несколько native drafts — отдельная работа. Папки/корзина/Live Preview/autosave уже имеют реализации: старые отрицательные статусы ниже не возвращают их в очередь создания с нуля.

Тематические матрицы обоих ТЗ и карта9+9 исходных критериев приёмки уже составлены; они не закрывают построчную связь каждого требования/ID с реализацией/подключением/доказательствами. Инвентаризация файлов внутри api завершена в указанном API-контрактом охвате; поведенческая ревизия остальных handlers, HTTP-входы вне api, серверные границы и остальная архитектура ещё открыты. Полные требования/ID — [next_steps.md](next_steps.md); очередь D не запускает P. Карта ответственности не закрывает требования одним наличием руководства.

## Последующее изменение сессий и UX

Сохранённое описание d0dd685: AccountHandler при собственном нике отзывает остальные сессии; собственный пароль сохраняет текущий SessionId с вращением session/CSRF токенов, снимает MustChangePassword и отзывает остальные. Административный reset отзывает все сессии цели. UserManagementHandler при административном rename отзывает все сессии цели, включая изменение только ника. Клиент подставляет временный пароль только из выполненного login, фокусирует новый и после собственной смены продолжает без нового входа. Канонический текущий контракт — session_policy.md; серверные ветки этим архитектурным пакетом заново не проверялись. Событие изменения сессий уже отражено в месяце20 октября; повторно добавлять его по дате этой документальной сверки не нужно.

## Тогдашний следующий приоритет

Полное удаление пользователя вместе с каталогом заметок, историей и связью storage.UserVaults: отслеживаемая очистка/повтор после сбоев, без обхода FK и без ложного успеха. В раннем комплекте операция для владельца хранилища была заблокирована и тем изменением не реализовывалась. Это не текущий запрет отдельного purge_user: процедура — folders_and_purge.md. Тогдашние направления — модульный рефакторинг, папки/ПКМ/команды, undo/redo и autosave по ТЗ002 — сохранены для трассировки, не автоматическая очередь P.
