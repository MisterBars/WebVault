# WebVault — состояние проекта

## Подтверждено пользователем
Комплект 26a0007 — ник и административные временные пароли — работает дома. Пользователь уточнил UX временного пароля и политику отзыва. Единая оболочка/прежние заметки приняты в основных сценариях; негативные/конкурентные тесты и рабочий Framework 4.5 не подтверждены.

## Новый комплект — сессии/UX, требует проверки
AccountHandler: собственный ник отзывает остальные сессии; собственный пароль сохраняет текущий SessionId с вращением session/CSRF токенов, снимает MustChangePassword и отзывает остальные. Административный reset по-прежнему отзывает все сессии цели. UserManagementHandler: административный rename всегда отзывает все сессии цели, включая изменение только ника. Клиент подставляет временный пароль только из выполненного login, фокусирует новый и после собственной смены продолжает без нового входа. session_policy.md имеет приоритет над старыми правилами выхода в документах/ТЗ.

## Применение
Сохранить заметки, получить код, Ctrl+F5. Нужна прежняя миграция 06; новых SQL/Web.config нет. Проверить на независимых браузерных профилях, не путать общие cookies вкладок с разными сессиями.

## Следующий приоритет
Полное удаление пользователя вместе с каталогом заметок, историей и связью storage.UserVaults: отслеживаемая очистка/повтор после сбоев, без обхода FK и без ложного успеха. Пока эта операция для владельца хранилища заблокирована; изменение данного комплекта её не реализует. После этого — модульный рефакторинг, папки/ПКМ/команды, undo/redo и автосохранение по ТЗ 002.
