# WebVault — состояние проекта

## Подтверждено пользователем
- ASP.NET и подключение к WebVault дома: HTTP 200.
- Сайту назначен WebVaultPool вместо DefaultAppPool.
- Применён 02_auth.sql, созданы Users/UserSessions.
- После изменения AdminSetupEnabled с false на true первоначальная настройка/авторизация заработала. Детальные негативные проверки не подтверждены.

## Новый подготовленный комплект, ещё не проверен
- first_install.md: повторяемая инструкция для ПК/ноутбука/рабочего места, генерация ключа, создание администратора, выключение настройки.
- deployment.md: актуальные ссылки и порядок SQL-установки.
- WebApi.cs: общие проверки новых защищённых API.
- AdminUsersHandler.cs и api/admin/users.ashx: список и создание обычных пользователей администратором.
- users.html и users.md: интерфейс, ограничения, проверки.

## Действия пользователя
1. Убедиться, что в локальном Web.config AdminSetupEnabled=false, ключ пустой.
2. Обновить проект без потери локальных изменений. Новый SQL не требуется.
3. Войти как администратор, открыть users.html, создать второго пользователя и проверить его вход/запрет административного API.
4. После подтверждения реализовать самостоятельную смену пароля с отзывом сессий, затем личные хранилища.

## Среда
Разработка дома/на ноутбуке; D:\project\WebVault. Цель: Windows 7, Framework 4.5, Firefox 113.0, IIS + SQL Express 2014 на одной машине. Integrated Security, WebVaultPool. Не устанавливать новые системные компоненты на рабочем ПК.

## Ещё не реализовано
Самостоятельная регистрация, смена/сброс пароля, управление блокировкой/ролями, личные файловые хранилища, редактор, поиск, темы, расширения, полноценное журналирование и регламент бэкапа/восстановления. Данные разных независимых установок автоматически не синхронизируются.

## Замечания
AuthHandler и новый WebApi пока имеют отдельные вспомогательные проверки; объединить при дальнейшей доработке авторизации. Работа текущей схемы не является гарантией приватности от администратора ОС. Возврат временной подробной диагностики health.ashx к общему ответу и выключение setup локально пока не подтверждены; перед обновлением проверять git diff.
