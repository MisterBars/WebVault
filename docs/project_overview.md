# WebVault — состояние проекта

## Подтверждено
Пользователь дома проверил ASP.NET/SQL, создание администратора, создание обычного пользователя и ограничения административного доступа. После предыдущего обновления интерфейса сообщил «отлично», но подробные результаты удаления/миграции 03 отдельно не перечислены. Проверку 03 перед новым комплектом не пропускать.

## Требования
Админ для управления пользователями и правами; отдельная личная учётка для заметок. Функции сразу связывать с интерфейсом/кнопками. Setup скрывать после настройки. Добавить переименование и разделить мягкое/полное удаление.

## Новый комплект, не проверен в IIS
UserManagementHandler и api/admin/user_manage.ashx: список с мягко удалёнными, переименование логина/имени, мягкое и полное удаление. users.html обновлён: редактор, переключатель удалённых, отдельные кнопки, ввод логина перед полным удалением. Миграция 04 разрешает DELETE на auth.Users. Полное удаление пока только учётка/сессии; файлового модуля нет. При внедрении хранилищ требуется согласованная очистка и обновление предохранителя. Логин после purge освобождается, UserId не переиспользовать вручную.

## Обновление
Бэкап БД; получить код без сброса локальных изменений; выполнить 03 если ещё нет, затем 04; Ctrl+F5; проверить действия на отдельной тестовой учётке. Существующих пользователей ради теста не удалять. Файлы проекта сами БД не изменяют. Инструкции: first_install.md, deployment.md, user_management.md.

## Далее
Самостоятельная смена пароля с отзывом сессий, затем личные файловые хранилища, редактор, настройки/темы. Самостоятельная регистрация, роли, восстановление, полноценные логи и бэкап/восстановление пока не реализованы. Старые API создания/списка/мягкого удаления сохранены для совместимости; новые операции интерфейс отправляет в user_manage.

## Среда
D:\project\WebVault. Цель Windows 7/.NET Framework 4.5/Firefox 113.0, IIS и SQL Express 2014 вместе, WebVaultPool, Integrated Security. Новые системные компоненты на работе не устанавливать. Независимые установки не синхронизируются. Возврат временной подробной health-диагностики и выключение setup локально по-прежнему не подтверждены явно. Объединение AuthHandler/WebApi остаётся задачей рефакторинга. Администратор ОС вне модели приватности.
