# WebVault — состояние проекта

## Подтверждено пользователем
- Диагностический сайт запускается дома: ASP.NET и БД возвращают HTTP 200.
- Сайт переведён с DefaultAppPool на WebVaultPool.
- Применён 02_auth.sql: созданы Users и UserSessions в схеме auth.

## Подготовлен код, ещё не проверен выполнением
- App_Code/AuthCrypto.cs: PBKDF2-HMAC-SHA256 через Windows CNG, случайные токены и SHA-256.
- App_Code/AuthHandler.cs и setup/login/me/logout: начальный цикл авторизации.
- auth.html: создание администратора, вход, проверка сессии, выход.
- Web.config.example: выключенная по умолчанию первоначальная настройка.
- API_OVERVIEW.md и TEST_CHECKLIST.md: запуск, ограничения и проверки.

Наличие файлов не означает готовую или протестированную авторизацию. Схема в db_schema.md актуальна; ранее неопределённый алгоритм теперь выбран: PBKDF2-HMAC-SHA256, 600000, версия 1. Проверка на рабочем ПК ещё не выполнена.

## Среда
Разработка дома/на ноутбуке, репозиторий D:\project\WebVault. Цель: Windows 7, Framework 4.5, Firefox 113.0, IIS и SQL Express 2014 на одной машине, Integrated Security и WebVaultPool.

## Следующие действия
1. Получить код и вручную дополнить локальный Web.config, не теряя подключение.
2. Создать первого администратора с локальным случайным ключом настройки.
3. Выключить настройку и удалить ключ.
4. Проверить вход/me/logout и негативные сценарии по TEST_CHECKLIST.md.
5. После подтверждения перейти к пользователям и личным хранилищам; регистрацию и смену пароля реализовать отдельно.

## Не реализовано
Управление пользователями, регистрация, смена пароля, файловые хранилища, редактор, темы, поиск и расширения. Файловые права каталога данных, полноценное журналирование, бэкап, восстановление и сетевое HTTPS-развёртывание пока не проверены.

## Локальные изменения
Пользователь временно менял health.ashx для диагностики; возврат к общему ответу пока не подтверждён. Перед обновлением смотреть git diff, не сбрасывать изменения принудительно.
