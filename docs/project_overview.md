# WebVault — состояние проекта

## Подтверждено ранее
Основные домашние сценарии единого окна, учёток, паролей, заметок приняты в общем виде. Последний комплект d0dd685 меняет текущую сессию/подстановку временного пароля; пользователь перешёл к следующей задаче без подробного отчёта всех тестов. Рабочий Framework 4.5 и негативные/конкурентные тесты отдельно не приняты.

## Новый комплект — 07, не выполнен в IIS/SQL ассистентом
Полное удаление с файлами: storage.PurgeJobs и AssertPurgeSchema, PurgeUserHandler, маршрут purge_user, явное подтверждение UI. Очищаются каталог заметок/вложенных папок и история конкретного GUID, потом сессии/реестр/учётка. Повторяемое задание при сбое, не обещать откат файлов. Старый purge в user_manage оставлен как несовместимый с владельцем хранилища legacy; новый UI использует новый маршрут.
VaultHandler теперь поддерживает вложенные относительные пути, mkdir и ленивое перечисление одного каталога. folder_features.js добавляет создание папок, переходы и путь в панели; application.js сохраняет заметки в текущую папку. Это не полное дерево раскрытых веток и не готовое ПКМ/копирование/перемещение/корзина.

## Применение
Бэкап БД И DataRoot, получить код, выполнить 07 после 00–06, Ctrl+F5. Web.config/DataRoot прежние. На отдельных тестовых данных проверить вложенные заметки и полное удаление владельца, включая блокировку файла и повтор. Не использовать единственную копию настоящих заметок. Подробности/ограничения/тесты folders_and_purge.md.

## Следующие шаги
Приёмка 07; расширяемый реестр команд/ПКМ, переименование/копирование/перемещение/корзина и история; модульный редактор/undo; очередь автосохранения. ТЗ 002 актуально, эти функции не выдавать за реализованные. История пока случайные .md без метаданных исходного имени/восстановления.

## Политики
Свой ник/пароль сохраняют текущую сессию и отзывают остальные; пароль вращает токены. Админские изменения отзывают все сессии цели. NormalizedLogin уникален, ник нет. Модальные вход/настройки, диагностика только локальному админу. Временный пароль обязателен к смене; UI допускает предзаполнение только из выполненного входа. Сетевое размещение требует HTTPS, внешних писателей в файлы одновременно не использовать.

Журналы PasswordResetEvents/PurgeJobs и бэкапы не удаляются вместе с учёткой. Администратор ОС вне модели приватности; независимые установки не синхронизируются.
