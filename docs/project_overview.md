# WebVault — состояние проекта

## Подтверждено пользователем дома
ASP.NET/SQL, администратор/пользователи, ограничения, переименование и мягкое/полное удаление. После этапа смены пароля пользователь сообщил «отлично идём дальше»: основной сценарий считаем принятым, отдельные негативные/конкурентные проверки и рабочий Framework 4.5 не подтверждены.

## Новый комплект, требует применения и тестирования
05_user_vaults.sql — storage.UserVaults, один Guid-каталог на владельца, FK без каскада. VaultHandler/API — инициализация, список корневых .md, создание, чтение и ручное сохранение. workspace.html/workspace.js — первый текстовый редактор, проверка версии, сохранение несохранённого текста при ошибках. Web.config.example — DataRoot. file_vault.md — настройка, границы и тесты. Код не запускался в IIS ассистентом.

## Изменённое ограничение удаления
Полное удаление пользователя с хранилищем блокируется FK/user_has_dependencies. Аккаунты без хранилища удаляются как прежде. Мягкое удаление сохраняется. Следует отдельно реализовать согласованную очистку каталога/истории/реестра перед возобновлением полного удаления владельцев; не обходить FK.

## Порядок развития
После проверки первой записи: дерево папок, операции заметок/корзина и восстановление истории; полноценное удаление владельца; Markdown-предпросмотр/ссылки; автосохранение; настройки и темы; затем расширения. Самостоятельная регистрация/роли/восстановление пароля/полные логи/бэкап остаются в плане. AuthHandler/WebApi нуждаются в рефакторинге.
