## Поведение
В настройках учётки есть собственный ник (DisplayName), 1–100 после Trim, без управляющих символов. Логин/ID/VaultId/пароль не меняются; вход не сбрасывается. При конфликте RowVersion profile_changed_reload — закрыть/снова открыть настройки и проверить актуальное имя.
У активного обычного пользователя в административной таблице есть Временный пароль. Диалог запрашивает текущий пароль администратора и новый временный с повтором. Себя, других администраторов, отключённых и удалённых этим действием менять нельзя. Если цель изменилась со времени списка, 409 user_changed_reload_list — обновить список, открыть диалог заново. После успеха пароль обновлён, FailedLoginCount=0/LockoutUntilUtc=NULL, MustChangePassword=1, все сессии цели отозваны; IsActive/DeletedUtc не снимаются. Админ не узнаёт прежний пароль. Временный пароль не имеет отдельного срока годности в этой версии.
После входа временным паролем сервер допускает только me, собственную смену пароля и logout. В me передаётся mustChangePassword, клиент сразу показывает обязательную смену в настройках, без загрузки заметок. Крестик/Escape не закрывают её, но кнопка выхода доступна. Это ограничение дополнительно проверяется WebApi, не только модальным окном. После смены флаг снимается и все сессии отзываются; войти новым паролем.
Первоначальное создание обычного пользователя пока сохраняет прежнюю политику (без автоматического MustChangePassword); обязательный режим включается административным сбросом.

## API и реализация
- GET api/auth/me.ashx теперь AccountHandler, возвращает rowVersion/mustChangePassword и прежние поля.
- POST api/auth/profile.ashx: displayName/rowVersion. Владелец из сессии, переданный userId игнорируется. CSRF обязателен.
- POST api/admin/reset_password.ashx: userId/rowVersion/adminPassword/newPassword/confirmPassword. Админ, CSRF, повторная проверка пароля, транзакционная проверка цели/сессии.
- POST api/auth/change_password.ashx теперь AccountHandler, тот же JSON currentPassword/newPassword/confirmPassword, допускает ограниченную сессию, снимает флаг.
WebApi.RequireUser по умолчанию запрещает MustChangePassword=1 с 403 password_change_required. Разрешающий параметр используется только новым me/собственной сменой; logout остаётся старым AuthHandler и допускается. Старый PasswordChangeHandler и приватная Me в AuthHandler больше не маршрутизируются соответствующими .ashx; удалить при следующем рефакторинге после регрессии.
Административный сброс и собственная смена имеют общий временный лимит 5 корректно сформированных запросов на действующего пользователя за период, продлеваемый принятой попыткой на 10 минут, и один вычисляющий запрос на процесс. Лимит в памяти, не распределённый, сбрасывается перезапуском/вытеснением. Неверная повторная проверка администратора не блокирует его вход навсегда, возвращает admin_reauthentication_failed.
Успешный сброс фиксируется в auth.PasswordResetEvents: только ActorUserId/TargetUserId/UTC, без паролей/токенов, в одной транзакции с паролем и отзывом сессий. Роли приложения дан только INSERT в журнал. Нет FK, чтобы удаление учётки не уничтожало запись и не блокировалось ею. Просмотра журнала в UI/политики очистки пока нет; полное удаление учётки не удаляет журнал и бэкапы.
Клиентский account_features.js — доверенный модуль ядра, загружается локально до запуска приложения. WebVaultCore/registerUserAction — внутренняя интеграция учёток, НЕ объявленный API сторонних плагинов/песочница. Сохранены единая страница, модалки и текущие файловые операции.
