## Текущий механизм сохранения

После input ставится таймер1000 мс. При занятости приложения или текущем сохранении auto повторно проверяет возможность работы через300 мс; это ожидание занятой операции, не сетевой retry. Сохранение идёт последовательно через app.run/saveNote и серверную SHA-256 версию. Во время фонового запроса обычный ввод не блокируется; новые изменения остаются dirty и планируют следующий запрос. Сохранение не присваивает editor.value, не перечитывает документ и само по себе не очищает CM Undo.

При ошибке failed останавливает автоповторы до явного сохранения; текст остаётся в редакторе, появляется кнопка повторного сохранения. Ctrl+S вызывает тот же контроллер, работает при личной открытой заметке и без открытого dialog. Это не гарантия сохранения неподтверждённого native-поля/табличного черновика: их правила —в руководствах свойств/таблиц.

Кнопочное действие при dirty перехватывается, перед ним сохраняется документ при временном readOnly. Повторный click допускается только после успешного сохранения, отсутствия новых dirty-изменений, при той же user/note identity, подключённой и доступной кнопке. При failed или занятости действие не выполняется автоматически: сначала сохранить/дождаться и повторить. View-only кнопки с data-wv-view-only исключены из этого перехвата. Файловые группы дополнительно используют свои save/guards.

При409 note_changed_reload_or_copy нет принудительной перезаписи. До разрешения конфликта сохранить копию своего текста; отдельный удобный диалог сравнения/разрешения ещё нужен. Ошибка не доказывает отсутствие серверной записи при потерянном ответе. Смена заметки/пользователя сбрасывает таймер/статус failed; старое состояние не должно переноситься на новую identity.

Модуль не записывает дисковый браузерный черновик. Сеть при закрытии вкладки не гарантирована, предупреждение beforeunload сохраняется. Это не синхронизация с внешними писателями и не полная будущая очередь с политикой ограниченных сетевых ретраев/конфликтов.

## Резервный просмотр и современный редактор

Старый editor_features.js создаёт отдельный просмотр: ATX-заголовки, простые ненакладывающиеся списки без полноценной вложенности, цитаты, fenced code, HR, inline code, strong/em и внешние http/https/mailto ссылки. Текст строится DOM/textContent без innerHTML; это не Live Preview и не полный CommonMark. Ограничения этого резервного parser нельзя описывать как отсутствие таблиц/wiki/Live Preview во всём проекте.

В CodeMirror mode_slider.js скрывает старую кнопку markdownToggle, editor.js устанавливает source/dynamic/reading и свой renderer. В markdown_renderer.js есть таблицы, wiki-токены/переходы, задачи, сноски и ограниченный callout; конкретные ограничения сохранены в профильных руководствах. Image-токен в сверенном renderer выводится текстовой заглушкой вложения, не картинкой; это не утверждение об отсутствии всех будущих способов работы с вложениями. Произвольный HTML отключён, отдельное безопасное правило BR не включает произвольный HTML.

Вкладки/split, файловый undo и F2 не реализуются этим модулем. В частности, F2 уже предусмотрен деревом файлов: отсутствие этой функции в editor_features.js не означает её отсутствие в приложении. Автосохранение не заменяет корзину и журнал файловых операций.

## План проверки

Сначала безопасная копия заметок; следующие сценарии не выполнялись при этой редактуре:

- Ввод/пауза1000 мс, ввод во время запроса, сохранение нового dirty-снимка и отсутствие сброса Undo после сохранения.
- Ctrl+S/повтор после ошибки, busy-ожидание, потеря сети/ответа,409 из другой сессии и сохранность текста без слепой перезаписи.
- Dirty-переход к заметке/rename/move/кнопке, readOnly на время перехода, отмена автоматического повторного действия после смены identity или нового ввода.
- Logout/login другой учёткой без старого preview/таймера; закрытие вкладки без обещания гарантированного сохранения.
- Резервный DOM-preview отдельно от опубликованного CodeMirror: HTML/javascript-ссылки, source/dynamic/reading, таблицы/wiki/свойства и взаимодействие черновиков с автосохранением.

Для функциональных правок —адресные тесты → test:all → build после успеха → отдельная публикация → браузер по npm_build.md с LASTEXITCODE. Node не тестирует сервер/IIS, docs-only не требует сборки.
