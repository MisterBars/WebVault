## Текущий механизм сохранения

Input ставит таймер1000 мс. Busy/saving повторно проверяется через300 мс: это ожидание занятой операции, не сетевой retry. Последовательная запись идёт через app.run/saveNote с серверной SHA-256 версией. Во время фонового запроса обычный ввод не блокируется, новый текст остаётся dirty для следующей записи. Save не присваивает editor.value, не перечитывает документ и сам не очищает CM Undo.

Ошибка устанавливает failed и останавливает автоповторы до явного сохранения. Текст остаётся, доступна кнопка повтора. Ctrl+S вызывает тот же контроллер для личной открытой заметки без открытого dialog. Это не сохранение неподтверждённых native-полей/табличных черновиков: действуют [правила свойств](properties_panel.md) и [таблиц](tables.md).

Кнопочное dirty-действие перехватывается с временным readOnly. Повторный click разрешён после успешной записи при отсутствии нового dirty, той же user/note identity, подключённой и доступной кнопке. Failed/busy требуют сохранить/дождаться и повторить действие. data-wv-view-only исключён; файловые группы используют дополнительные save/guards. Это не универсальный перехват клавиатурных маршрутов: [переключатель режимов](mode_slider.md#переключение-история-и-черновики) различает прямой choose и click.

При409 note_changed_reload_or_copy нет принудительной перезаписи. До разрешения конфликта сохранить копию текста; удобный диалог сравнения/разрешения ещё нужен. Потерянный ответ не доказывает отсутствие серверной записи. Смена пользователя/заметки сбрасывает таймер/failed; прежнее состояние не должно переноситься на новую identity.

Дисковый браузерный черновик не создаётся. beforeunload предупреждает, но сеть при закрытии не гарантирована. Это не синхронизация внешних писателей и не вся будущая очередь с ограниченными сетевыми ретраями/конфликтами. Предложения ТЗ700 мс/около5 секунд не текущие параметры1000/300 мс.

## Резервный просмотр и современный редактор

Резервный editor_features.js строит отдельный DOM-preview: ATX, простые ненакладывающиеся списки без полноценной вложенности, цитаты, fenced code, HR, inline code, strong/em, http/https/mailto ссылки. DOM/textContent без innerHTML; это не Live Preview/полный CommonMark и не отсутствие таблиц/wiki во всём проекте.

mode_slider.js скрывает markdownToggle, editor.js задаёт CM-режимы/renderer. markdown_renderer.js содержит таблицы, wiki/переходы, задачи, сноски, ограниченный callout; ограничения — в профильных руководствах. Image-токен сверенного renderer даёт текстовую заглушку вложения, не изображение. Произвольный HTML выключен; безопасный BR его не включает. Это не утверждение о всех будущих способах вложений.

Вкладки/split, файловый Undo и F2 не реализуются этим модулем. F2 уже предусмотрен деревом: отсутствие в editor_features.js не отсутствие в приложении. Autosave не заменяет корзину/журнал файловых операций.

## План проверки

На безопасной копии заметок; это сценарии, не новый прогон:

- Пауза1000 мс, ввод во время запроса, следующий dirty-снимок и сохранность Undo.
- Ctrl+S/повтор, busy300 мс, сеть/потеря ответа/409 второй сессии без потери текста и слепой перезаписи.
- Dirty-переход/rename/move/кнопка, временный readOnly и отмена replay после новой identity/ввода; клавиатурные маршруты отдельно.
- Logout/login другой учёткой без старого preview/таймера; закрытие без гарантии сети.
- Безопасность HTML/javascript-ссылок резервного DOM-preview отдельно от опубликованного CM, три режима/таблицы/wiki/свойства и native-черновики.

Для функциональной правки: адресные → test:all → build после успеха → отдельная публикация → браузер по [npm_build.md](npm_build.md) с LASTEXITCODE. Node не тестирует IIS, docs-only не требует сборки.
