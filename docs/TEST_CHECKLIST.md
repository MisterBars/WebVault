# Проверка авторизации

Все пункты ниже — план, не отчёт об успешном тестировании. Проверять дома, затем на рабочем Framework 4.5.

- [ ] me без cookies: 401 JSON, не перенаправление.
- [ ] Настройка без включения: 403 setup_disabled.
- [ ] Неверный ключ: 403, пользователи не создаются.
- [ ] Правильные данные: 201, один администратор в auth.Users.
- [ ] Два одновременных корректных запроса setup не создают двух пользователей.
- [ ] Повторный setup при оставленном включении: 409.
- [ ] Настройка выключена, ключ удалён из локального Web.config.
- [ ] Неверный пароль: 401 без cookies сессии.
- [ ] Правильный пароль: 200, me показывает пользователя.
- [ ] Обновление страницы сохраняет вход; секреты не попадают в URL/localStorage.
- [ ] В БД нет исходного пароля/токена сессии/CSRF-токена.
- [ ] POST без X-WebVault-Request, с чужим Origin или неверным типом содержимого запрещён.
- [ ] Logout без/с неверным X-CSRF-Token запрещён; с верным отзывает сессию.
- [ ] После logout старая сессия не принимается.
- [ ] IsActive=0 запрещает me и новый вход. Вернуть IsActive=1 после теста.
- [ ] Пять ошибок пароля блокируют вход на 15 минут; после истечения возможен вход. Не путать с отдельным IP-лимитом 429.
- [ ] Истечение по бездействию, абсолютный срок и RevokedUtc проверяются.
- [ ] HTTP с другой машины не допускает авторизацию; сетевое размещение пока не принимать без HTTPS-проверки.
- [ ] Права пула остаются без db_owner.
- [ ] Диагностика health.ashx по-прежнему работает; временные подробности локально убраны.

Новый SQL-скрипт для этого комплекта не требуется. Не вставлять пользователя вручную.
