# API авторизации v0.1

Код подготовлен; компиляция и выполнение в IIS пока не проверены. Требуется применённый 02_auth.sql.

## Общие правила
Маршруты относительно сайта: api/auth/*.ashx. JSON, UTF-8, no-store. Все POST требуют Content-Type application/json и X-WebVault-Request: 1. Если Origin присутствует, он должен совпадать с origin сайта. CORS не включать. Для удалённой авторизации требуется прямой HTTPS, HTTP разрешён только локально. Не использовать за обратным прокси без отдельной проверки определения локальности/HTTPS.

- POST setup.ashx: JSON login/password/displayName и заголовок X-Setup-Key. Только локально, AdminSetupEnabled=true и ключ длиной минимум 40 символов в Web.config. Проверка отсутствия пользователей и вставка выполняются под транзакционной блокировкой; повторная инициализация при наличии любого пользователя запрещена.
- POST login.ashx: JSON login/password. Успех устанавливает две HttpOnly session cookies, возвращает ok=true.
- GET me.ashx: проверяет активность пользователя, отзыв и сроки сессии, продлевает срок бездействия атомарно, возвращает user и csrfToken. Без действительной сессии 401.
- POST logout.ashx: JSON {}, заголовок X-CSRF-Token из me; отзыв текущей сессии и удаление cookies.

## Пароли и сессии
Логин: 3–64 символа ASCII A-Z/a-z/0-9/точка/дефис/подчёркивание, регистронезависимый. Пароль администратора: 15–128 символов .NET string, без обрезки. Имя: 1–100 после Trim.
PBKDF2-HMAC-SHA256, 600000 итераций, соль 32 байта, результат 32 байта, версия 1. Используется встроенный Windows CNG BCryptDeriveKeyPBKDF2 (Windows 7+), а не новая перегрузка Framework. Самопроверка по известному вектору выполняется перед первым хешированием. Сбой CNG приводит к отказу без ослабления алгоритма. Требуется проверка на целевой машине.
Случайные токены: 32 байта, SHA-256 в БД. Cookies HttpOnly, Secure при HTTPS, область текущего приложения, без persistent Expires. SameSite не задаётся через API из-за целевого Framework 4.5; защита POST не полагается на SameSite.
Сессия: 30 минут бездействия, максимум 8 часов. В этой версии активность продлевает только me; будущий файловый API должен использовать общий механизм проверки/продления.
После 5 неудачных попыток существующий активный пользователь блокируется на 15 минут. Ответ не раскрывает наличие/блокировку учётной записи. Временное ограничение по IP: максимум 20 попыток за период, продлеваемый каждой принятой попыткой на 10 минут; хранится в памяти и сбрасывается при перезапуске/вытеснении кеша. Не более двух параллельных вычислений пароля на процесс IIS. Это не распределённый rate limiter.
Изменение пароля, регистрация, управление пользователями и отзыв всех сессий ещё не реализованы. Оболочка auth.html демонстрирует цикл, но не является редактором.

## Ошибки
400 — неверный формат; 401 — вход/сессия; 403 — ключ настройки, CSRF, origin или HTTPS; 409 — уже инициализировано; 429 — ограничение попыток/занято; 500 — серверная ошибка с errorId. Подробности исключений в ответ не выдаются. Trace пишет тип исключения и идентификатор, полноценное журналирование ещё предстоит настроить.

## Запуск
Не заменять локальный Web.config целиком: сохранить строку подключения. В configuration добавить appSettings с AdminSetupEnabled=false и AdminSetupKey пустым, затем временно включить и задать случайный ключ. Генерация ключа в PowerShell:

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
[Convert]::ToBase64String($bytes)
```

Ключ не присылать в чат и не коммитить. Для инициализации value AdminSetupEnabled установить true, ключ вставить в AdminSetupKey и соответствующее поле auth.html. Открыть http://127.0.0.1:8085/auth.html, создать администратора. Сразу после успеха вернуть false и очистить ключ; затем войти. Отключение настройки — ручной шаг. Страница setup остаётся в коде, но сервер запрещает повторное создание при наличии пользователя.
Для запрета встраивания страницы также перенести блок system.webServer/httpProtocol/customHeaders из примера, не дублируя существующие секции.

Источники проектного решения: OWASP Password Storage Cheat Sheet (PBKDF2-HMAC-SHA256 600000); Microsoft BCryptDeriveKeyPBKDF2 (минимум Windows 7).
