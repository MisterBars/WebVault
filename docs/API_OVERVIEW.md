## Область и текущие канонические контракты

## Базовые маршруты и общие правила

Маршруты относительно сайта: api/auth/*.ashx. Исходный общий контракт: JSON/UTF-8/no-store; POST с Content-Type application/json и X-WebVault-Request: 1. При наличии Origin требуется совпадение с origin сайта; CORS не включать. Для удалённой авторизации нужен прямой HTTPS, локальный HTTP допускается политикой приложения. Обратный прокси требует отдельной проверки определения локальности/HTTPS. Точные исключения и серверные проверки каждого маршрута сверять с реализацией, не только этой сводкой.

- POST setup.ashx: login/password/displayName, X-Setup-Key; локальный запрос, AdminSetupEnabled=true, ключ не короче 40. Отсутствие пользователей и вставка проверяются под транзакционной блокировкой; повторный setup при любом пользователе запрещён.
- POST login.ashx: login/password; исходный успешный ответ устанавливал две HttpOnly session cookies и ok=true. Текущее продолжение при mustChangePassword — по session_policy.md.
- GET me.ashx: действительность пользователя/сессии, сроки/отзыв, user/csrfToken; без действительной сессии 401. Текущий AccountHandler также обслуживает ограниченный вход; не сводить ответ только к ранним полям.
- POST logout.ashx: JSON {}, X-CSRF-Token из me; отзыв текущей сессии и удаление cookies.

## Пароли и сессии: сохранённые параметры первого комплекта

Ниже параметры раннего описания, не новая полная сверка AuthHandler/WebApi/AuthCrypto или отчёт целевого ПК. Изменения последующих маршрутов имеют приоритет в профильных руководствах; особенно нельзя переносить раннюю параллельность login на AccountHandler/CreateSlot.

Логин: 3–64 ASCII A-Z/a-z/0-9/точка/дефис/подчёркивание, без учёта регистра. Пароль администратора: 15–128 единиц .NET string, без обрезки. Имя: 1–100 после Trim; различия валидации создания/rename/profile описаны отдельно.

PBKDF2-HMAC-SHA256, 600000 итераций, соль 32 байта, результат 32 байта, версия 1; Windows CNG BCryptDeriveKeyPBKDF2 для Windows 7+, не новая перегрузка Framework. Самопроверка известным вектором перед первым хешированием; отказ CNG без ослабления алгоритма. Нужна отдельная проверка целевой машины.

Токены: случайные 32 байта, в БД SHA-256. Cookies HttpOnly, Secure при HTTPS, scope приложения, без persistent Expires. Ранний код не задавал SameSite через API Framework 4.5, защита POST на него не полагалась. Сессия в исходном описании: 30 минут бездействия, максимум 8 часов. Тогда продление относилось только к me; это не утверждение, что текущий файловый API отсутствует или не проверяет сессию. Текущая политика собственной/административной смены и сохранения SessionId — session_policy.md.

Первоначальная login-защита: 5 неудачных попыток активной существующей учётки — блокировка на 15 минут, ответ не раскрывает наличие/блокировку. IP-лимит — максимум 20 попыток за период, продлеваемый принятой попыткой на 10 минут, в памяти процесса с потерей после restart/вытеснения. Раннее ограничение не более двух параллельных вычислений на процесс IIS не является общей квотой всех позднейших обработчиков. Это не распределённый rate limiter.

## Ошибки и диагностика

Исходная сводка: 400 — формат; 401 — вход/сессия; 403 — setup-ключ/CSRF/Origin/HTTPS; 409 — уже инициализировано; 429 — лимит/занятость; 500 — серверная ошибка с errorId. Новые действия имеют дополнительные коды/причины в профильных контрактах, включая password_change_required и rowVersion-конфликты. Подробности исключений не выдавать клиенту. Ранний Trace писал тип исключения и ID; это не отчёт о настроенном полноценном журналировании установки.

## Установка и первоначальный администратор

Следовать [first_install.md](first_install.md): новая установка использует SQL 00–07, не только ранний 02_auth.sql. Обновление — только подтверждённо неприменённые миграции после бэкапа БД/DataRoot. Рабочий Web.config не заменять; не дублировать appSettings/customHeaders. Текущий вход для setup — index.html, не историческая отдельная auth.html.

Сохранённый способ генерации временного ключа:

```powershell
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
[Convert]::ToBase64String($bytes)
```

Ключ не присылать в чат/Git. Обычно AdminSetupEnabled=false, AdminSetupKey пусто; для новой пустой тестовой установки включение true временное, после создания сразу false/очистка ключа. Сервер запрещает повторный setup при пользователях даже при забытом включении; видимость формы не защита. Историческая инструкция также требовала переноса защитных system.webServer/httpProtocol/customHeaders из примера без дублирования секций; актуальную конфигурацию сверять отдельно, не заменять рабочую шаблоном.

Источники исходного проектного решения: OWASP Password Storage Cheat Sheet (PBKDF2-HMAC-SHA256 600000), Microsoft BCryptDeriveKeyPBKDF2 (Windows 7). Эта редактура не новая внешняя проверка этих источников, не запуск C#/SQL/IIS и не полная ревизия всех API.
