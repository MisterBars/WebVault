# WebVault — схема служебной БД

Статус: схема авторизации подготовлена в 02_auth.sql, применение пользователем ещё не подтверждено. Цель — SQL Server Express 2014. БД WebVault. Файлы заметок не хранятся в этих таблицах.

## Установка
1. Создать IIS-пул WebVaultPool.
2. Выполнить database/install/00_database.sql.
3. Выполнить database/install/01_grant_apppool_access.sql.
4. Выполнить database/install/02_auth.sql.

02_auth.sql выполняется в транзакции, создаёт отсутствующие таблицы и выдаёт права. Повторный запуск не удаляет данные и не обновляет структуру существующих таблиц; это не универсальный механизм миграций. Первого администратора скрипт не создаёт.

## auth.Users
| Поле | Назначение |
|---|---|
| UserId | Внутренний идентификатор пользователя |
| Login | Отображаемый логин, максимум 64 символа |
| NormalizedLogin | Уникальный ключ логина; нормализация будет выполняться C#-кодом, сравнение в БД бинарное |
| DisplayName | Имя в интерфейсе; email не требуется |
| PasswordHash | Результат функции выработки ключа, не открытый пароль |
| PasswordSalt | Индивидуальная криптографически случайная соль |
| PasswordAlgorithm | Точное имя алгоритма и PRF, задаваемое реализацией |
| PasswordIterations | Параметр трудоёмкости |
| PasswordVersion | Версия формата проверки пароля |
| IsAdmin | Администратор приложения, не SQL Server |
| IsActive | Признак разрешённого входа; проверять и при использовании существующей сессии |
| FailedLoginCount | Число неуспешных попыток для политики блокировки |
| LockoutUntilUtc | Временная блокировка, NULL если отсутствует |
| CreatedUtc | Создание записи, UTC |
| UpdatedUtc | Последнее изменение записи; обновляется кодом, автоматического триггера нет |
| PasswordChangedUtc | Последняя установка пароля |
| LastLoginUtc | Последний успешный вход, NULL до первого входа |
| RowVersion | Маркер конкурентного изменения; не дата и не время |

Конкретный алгоритм и параметры пароля будут зафиксированы вместе с C#-реализацией под Framework 4.5. SQL не вычисляет хеши. Поля алгоритма и версии предназначены для будущего обновления формата.

## auth.UserSessions
| Поле | Назначение |
|---|---|
| SessionId | Внутренний идентификатор, не секретный токен |
| UserId | Владелец, FK на auth.Users без каскадного удаления |
| TokenHash | SHA-256 от случайного токена сессии; исходный токен не сохранять в БД или журнале |
| CsrfTokenHash | SHA-256 от отдельного случайного CSRF-токена |
| CreatedUtc | Создание сессии |
| LastSeenUtc | Последняя зарегистрированная активность |
| ExpiresUtc | Текущее истечение по бездействию |
| AbsoluteExpiresUtc | Максимальный срок независимо от активности |
| RevokedUtc | Отзыв сессии, NULL если не отозвана |

Наличие строки не означает действительность сессии. Сервер должен проверять отзыв, оба срока и активность пользователя при каждом защищённом запросе. Продление ExpiresUtc не должно превышать AbsoluteExpiresUtc. Продление выполняется атомарным UPDATE с проверкой сроков и отзыва. Смена пароля должна отзывать старые сессии. Эти правила предстоит реализовать в API.

## Индексы и права
Уникальные индексы: NormalizedLogin и TokenHash. Дополнительные индексы сессий: UserId и ExpiresUtc.
Роль webvault_app: SELECT/INSERT/UPDATE на auth.Users; SELECT/INSERT/UPDATE/DELETE на auth.UserSessions. Нет db_owner, создания таблиц и удаления пользователей. Разделение обычного пользователя и администратора реализуется серверной проверкой прав, не отдельными SQL-логинами.
