# Первое локальное развёртывание

Статус: начальный каркас, не готовая система заметок. Файлы требуют проверки на домашнем и рабочем ПК. Не публиковать в интернет.

## 1. IIS
Создать отдельный пул WebVaultPool: CLR v4.0, Integrated, Identity=ApplicationPoolIdentity. Не менять пул ВВТ.
Создать сайт WebVault с физическим путём D:\project\WebVault\src\WebVault.Web и пулом WebVaultPool. Для локального теста привязать HTTP к 127.0.0.1, порту 8085, без имени узла. Порт должен быть свободен.
Пулу нужен доступ чтения/выполнения к папке сайта, но не право изменения исходников. Пример команды из административного PowerShell:

```powershell
icacls 'D:\project\WebVault\src\WebVault.Web' /grant 'IIS AppPool\WebVaultPool:(OI)(CI)RX'
```

Не предоставлять Everyone полный доступ.

## 2. Конфигурация
Скопировать src/WebVault.Web/Web.config.example в Web.config рядом с ним. Заменить Server=.\SQLEXPRESS на реальный экземпляр SQL Server. Не добавлять Web.config в Git. Целевая версия — Framework 4.5.

## 3. База данных
IIS и SQL Server для этого сценария находятся на одной машине. Подключиться в SSMS с административными правами. Выполнить по порядку:
1. database/install/00_database.sql
2. database/install/01_grant_apppool_access.sql

Создаётся WebVault, схемы auth/notes/settings, Windows login IIS APPPOOL\WebVaultPool, пользователь и роль webvault_app. Таблиц пока нет. Роль имеет только CONNECT; для SELECT DB_NAME() этого достаточно. db_owner не выдаётся. Если используется другое имя пула, заменить его во всём скрипте. Не выполнять скрипты в БД ВВТ.

## 4. Проверка
Открыть на самом сервере http://127.0.0.1:8085/index.html.
Проверка ASP.NET: HTTP 200, ok=true, database=not_checked.
Проверка SQL: HTTP 200, ok=true, database=ok.
HTTP 503 означает ошибку подключения, конфигурации или несоответствие БД. Диагностика не выдаёт строки подключения и подробности исключения в браузер. Удалённый запрос к health.ashx получает 403.
Если IIS запрещает запрос до выполнения обработчика, он может вернуть собственный код ошибки.
Проверка не создаёт файлов, пользователей или таблиц. Каталог пользовательских данных и права записи добавляются на следующем этапе.

## 5. Перенос
На целевой машине повторить создание пула, сайта, БД и локального Web.config. Не переносить имя домашнего SQL-экземпляра как обязательную настройку. Не включать реальные заметки или секреты в репозиторий.

## Границы этапа
Нет регистрации, авторизации, редактора, файлового API и резервного копирования. Успешный запуск дома не заменяет проверку на рабочем Framework 4.5.
