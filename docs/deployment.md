## Основной регламент

Каноническая пошаговая установка — first_install.md: IIS-пул WebVaultPool, Integrated Security при IIS/SQL на одной Windows-машине, SQL 00–07, DataRoot вне сайта, локальный рабочий Web.config, генерация ключа и создание администратора. На обновлении применять только подтверждённо неприменённые миграции после бэкапа БД и DataRoot. Не заменять рабочую конфигурацию шаблоном, не выдавать приложению db_owner и не отключать FK.

Ранний порядок 00–04 неполон для текущего сайта. 03 добавляет DeletedUtc; 04 разрешает DELETE на auth.Users; 05 вводит реестр хранилищ, 06 — безопасность аккаунтов/аудит reset, 07 — отдельную очистку владельца с файлами. Установочные скрипты сами пользователей/файлы не удаляют. Точный порядок и назначение — в first_install.md, не в конкурирующей копии установочной инструкции.

## Сборка и граница первоначального комплекта

[cm6_setup.md](cm6_setup.md) сохраняет историческое описание первого комплекта файловых операций и CM6. Его команды npm install/build, отсутствие lock/bundle и ранние отрицательные статусы функций не являются действующим регламентом или отчётом текущего HEAD. Актуальные файлы/корзина — в [file_vault.md](file_vault.md), редактор — в [live_preview_blocks.md](live_preview_blocks.md).

Для функциональных изменений выполнять адресные проверки, затем test:all, build только после успеха, отдельную публикацию и браузерную проверку по [npm_build.md](npm_build.md). Не устанавливать и не обновлять зависимости автоматически; если lock отсутствует или не соответствует manifests, остановиться и согласовать исправление. Исходники, тесты, build, публикация и браузерная приёмка имеют раздельные статусы. Этот документальный пакет ни один из этих запусков не выполняет.

## Публикация и вход

Публиковать только согласованный состав src/WebVault.Web с нужными JS/CSS/handlers и отдельно проверенным bundle, не корень Git/.git/docs/database/tools/node_modules. Node/npm нужны на сборочном ПК, не для запуска сайта. Сборка не публикует сайт автоматически; docs-only не требует публикации.

Основной вход — index.html с единой рабочей областью и модальными входом/настройками. users.html — совместимая переадресация на index.html?view=users. Прежнее описание index как одной диагностики, workspace как пустого каркаса и набора самостоятельных страниц относится к раннему этапу, не к актуальному способу работы. Setup после инициализации скрыт; всё равно выключить AdminSetupEnabled и очистить ключ. Видимость интерфейса не заменяет серверные права.

## Проверки и границы

Сохранить заметки/локальные изменения перед обновлением; после функциональной публикации выполнить Ctrl+F5 и отдельно проверить целевую Windows 7/.NET Framework 4.5/IIS/SQL Express 2014/Firefox 113. Наличие файлов или успешная SQL-миграция не доказывают работу редактора, HTTPS, файловых операций и резервного восстановления.

Создание/rename/мягкое удаление и старый purge — user_management.md; собственный ник/пароль, reset и сессии — session_policy.md; очистка файлов владельца с частичными сбоями/повтором — folders_and_purge.md. Эти операции не смешивать. Историческая домашняя проверка первоначального создания/серверного запрета административного API не является полной проверкой нынешнего комплекта или рабочей среды; файловые хранилища и резервирование не объявляются проверенными этим ранним наблюдением. Шесть установленных событий аккаунтов 19–20 октября UTC и границы ранних наблюдений перенесены в [канонический changelog](changelog/2026-10.md#2026-10-19); полная реконструкция остальных ранних функций ещё продолжается.
