# Смена собственного пароля

Статус: код подготовлен, выполнение в IIS не проверено. До этого комплекта пользователь сообщил, что переименование и два режима удаления работают дома.

## Обновление и запуск
Новая SQL-миграция/настройка Web.config не нужна. Требуется существующая схема 00–04. Получить код, обновить страницу Ctrl+F5. Войти под обычным пользователем или администратором, нажать в навигации «Учётная запись». Ввести текущий пароль, новый 15–128 символов и повтор. Новый должен отличаться от текущего; пробелы не обрезаются. После успеха все сессии пользователя отзываются, cookies текущей удаляются, страница предлагает войти заново. Пароли/токены не присылать в чат.

## API
POST api/auth/change_password.ashx, JSON currentPassword/newPassword/confirmPassword. Действующая сессия, X-WebVault-Request: 1, X-CSRF-Token из me. HTTPS для удалённого доступа, локально допускается HTTP. UserId берётся только из проверенной сессии; переданный клиентом userId не используется. Доступно и обычному пользователю, и администратору для собственной учётки. Сброс чужого пароля не реализован.
В транзакции повторно проверяются активность/неудалённость пользователя, срок и отзыв сессии, текущий пароль. Обновляются соль/хеш/алгоритм/число итераций/версия и PasswordChangedUtc/UpdatedUtc, сбрасываются FailedLoginCount и LockoutUntilUtc. Все неотозванные сессии этого пользователя отзываются в той же транзакции. Перед записью срок сессии проверяется снова. При неверном старом пароле откат, пароль/сессии не меняются. Криптография та же: PBKDF2-HMAC-SHA256, 600000, новая соль 32 байта.

## Защита и ограничения
Пять запросов с корректным форматом на пользователя за период, продлеваемый каждой принятой попыткой на 10 минут; лимит включает успешные попытки и неудачные старые пароли, хранится в памяти процесса и сбрасывается при перезапуске/вытеснении кеша. Это не распределённая защита и не блокировка входа в БД. Допускается одно параллельное вычисление этого обработчика на процесс; при занятости 429. Предыдущий механизм лимитов login остаётся отдельным.
Ошибки: 400 — формат/повтор/новый совпал со старым; 403 current_password_incorrect — неверный текущий пароль; 401 — сессия недействительна; 429 password_change_rate_limited или server_busy. Ошибки CSRF/Origin/HTTPS проверяются общим слоем. Автоматического входа после смены нет. Другие вкладки теряют доступ при следующем защищённом запросе, не удаляют уже отображённые данные автоматически. Если ответ после успешной транзакции потерялся, проверить вход новым паролем, не выполнять SQL-сброс наугад.

## Проверки
- [ ] Навигация ведёт в account.html для обеих ролей.
- [ ] Без входа страница отправляет на вход, API возвращает 401.
- [ ] Неверный текущий пароль не меняет данные и сессии.
- [ ] Несовпадающий повтор/короткий/одинаковый новый пароль отклоняются на сервере.
- [ ] Успех: PasswordChangedUtc и соль/хеш обновлены, старый пароль не работает, новый работает.
- [ ] Все ранее открытые сессии отозваны, включая текущую.
- [ ] Изменение не затрагивает другую учётку.
- [ ] Обычная учётка не может менять пароль администратора через userId в JSON.
- [ ] Нет изменений при неверном CSRF и чужом Origin.
- [ ] Удалённая/отключённая учётка не меняет пароль.
- [ ] Старые создание/переименование/удаление и вход/выход работают.
- [ ] Политика лимитов выдаёт 429 без утечки паролей.
