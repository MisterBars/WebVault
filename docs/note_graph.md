# Первый индекс связей и граф заметок

[README](../README.md) · [Все инструкции](index.md) · [Сборка npm](npm_build.md). Статус: исходники подготовлены, npm install/test/build и браузер не запускались.

## Применение
Дома из tools/cm6: npm install (новая локальная зависимость d3-force 3.0.0), npm test, при успехе npm run build. Сохранить lock, не коммитить node_modules. Перенести новый webvault-cm6.js, Ctrl+F5. SQL/Web.config/серверные маршруты не меняются.

## Индекс
Клиентский индекс по запросу, не серверная служба/SQL-таблица. Читает только личное хранилище через существующие защищённые list/read; скрытые каталоги/корзина/reparse исключаются текущим серверным listing. В памяти текущего окна, без localStorage/IndexedDB и без текста заметок в кеше: пути, версии, извлечённые ссылки. При обновлении всё дерево читается снова; parser повторно работает только для новых/изменённых версий. Это не полная инкрементальная синхронизация: внешние изменения/другая сессия видны после обновления. Ошибка чтения/лимита не публикует частичный новый индекс.

Поддержаны wiki и обычные Markdown-ссылки на .md; inline/fenced code и комментарии %%/HTML исключаются при извлечении ссылок. Свойства YAML/aliases, теги, вложения, ссылки вида ../ или ./ пока не индексируются/не разрешаются. Суффикс # учитывается как связь с заметкой без перехода к конкретному заголовку. Самоссылки не рисуются. Resolver: та же папка, корневой путь, однозначное basename/суффиксное совпадение; несколько кандидатов — ambiguous без произвольного выбора. Граф и wiki-переходы редактора используют этот resolver. Извлечение комментариев пока не меняет их визуальное отображение редактором.

Лимиты: 300 заметок/300 папок, 20 MiB прочитанного текста, 600 узлов с неразрешёнными целями и 2000 уникальных направленных связей; до 1000 ссылок в заметке. Сервер сохраняет собственные лимиты размера файла/ширины папки. До завершения построения полной картины обещать нельзя; большие vault требуют серверного/worker-индекса позже.

Публичная первая основа: window.WebVaultNoteIndex.ensure(), invalidate(), getFiles(), getBacklinks(path). Это НЕ Obsidian API/MetadataCache и не поддержка произвольных плагинов. Контроль пользователя проверяется при доступе, кеше и каждом запросе. Изменения через экспортированный protectedApi и ввод редактора помечают индекс устаревшим; не все старые приватные маршруты имеют события. Общего атомарного снимка нескольких HTTP-запросов нет.

## Граф
Кнопка Граф заметок в файловой панели. При открытии строится/обновляется индекс. Общий или локальный граф активной заметки, глубина 1/2 по входящим и исходящим связям. Фильтр имени/пути, неразрешённых целей и изолированных заметок; фильтры образуют подграф. Колесо масштабирует у указателя, фон перетаскивается, узлы перемещаются. Наведение подсвечивает соседей; клик/Enter/Space открывает существующую заметку в текущей рабочей области после сохранения. Missing/ambiguous не создают файлы, показывают сообщение. Цвета из темы; полный Obsidian UI/физика не копируются.

Закрытие останавливает симуляцию и отменяет следующие шаги построения; уже выполняющийся fetch может завершиться, но не должен публиковать чужой/отменённый результат. Смена пользователя очищает индекс и видимый граф.

## Проверки
Node-тесты: ссылки/код/комментарии, пути, ambiguity, повторные связи/backlinks, свойства. Не запускались здесь; не заменяют DOM/IIS тесты. Проверить 00–07, два одноимённых файла в разных папках, отсутствующую цель, обычную .md-ссылку, комментарии/код, общий/локальный граф, зум/pan/drag, сохранение перед переходом, Ctrl+Z, rename/trash/restore/import и обновление графа, две учётки/истёкшую сессию, закрытие во время индексации, лимиты и производительность Firefox113/Windows7. После графа вернуться к согласованным задачам Markdown; импорт/экспорт этим комплектом не упрощается.
