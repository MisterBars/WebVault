## Индекс

Клиентский индекс по запросу, не серверная служба/SQL-таблица. Обходит личное хранилище через защищённые list/read; серверный listing исключает скрытые каталоги/корзину/reparse. В памяти текущего окна, без localStorage/IndexedDB в этом модуле. Кэш хранит пути, версии, извлечённые ссылки, а также имена и значения поддержанных свойств; полные тексты заметок в cache.notes не сохраняются. Поэтому прежнее описание «только пути/версии/ссылки» неполно. Значения свойств также личные данные и не должны попадать в публичные отчёты.

При обновлении дерево и тексты читаются снова; refs повторно извлекаются для новых/изменённых версий. propertyValues могут переиспользоваться при той же версии, propertyNames собираются из разобранных свойств. Это не полная инкрементальная синхронизация: внешние изменения/другая сессия требуют обновления. Новый cache публикуется после полного построения и guard; ошибка чтения/лимита не публикует новый частичный индекс. Общего атомарного снимка нескольких HTTP-запросов нет.

### Связи и свойства — разные объёмы

extractReferences читает wiki и обычные Markdown-ссылки из токенов, исключая code и скрытые %%/HTML comments. Resolver различает недопустимые/игнорируемые/разрешённые/missing/ambiguous цели. Граф и wiki-переходы используют общую модель resolver; несколько кандидатов не выбираются молча. Корневой wiki-путь обрабатывается отдельно от старых коротких ссылок. Правила путей и текущие переходы —wiki_links.md.

Суффикс # может дать связь с заметкой, но не реализует picker/прокрутку к заголовку. Самоссылки не рисуются; повторные направленные связи объединяются со счётчиком. Исключение комментариев при извлечении не полное скрытие комментариев в редакторе/folding/индексе заголовков.

inspectProperties/collectPropertyNames/collectPropertyValues уже формируют propertyNames/propertyValues для подсказок свойств. Это не означает YAML-связи/aliases/теги как рёбра графа, индекс вложений или глобальную схему типов. Прежнее «YAML вообще не индексируется» нужно ограничивать именно отсутствующим объёмом связей, а не отрицать реализованный каталог имён/значений. Относительные пути ./ и ../ не обещаны как поддержанные цели; не путать их с корневой адресацией wiki.

### Лимиты и API

INDEX_LIMIT:300 заметок/300 посещённых папок, включая корень;20 MiB перекодированного UTF-8 прочитанного текста;600 узлов с неразрешёнными целями;2000 уникальных направленных связей;до1000 извлечённых ссылок одной заметки. Серверные лимиты файла/ширины папки действуют отдельно. Большие vault требуют развития индекса, а не обещания полной картины после частичного обхода.

window.WebVaultNoteIndex:ensure(), invalidate(), getFiles(), getBacklinks(path). getFiles возвращает путь/версию, getBacklinks —входящие пути/счётчики из текущего cache с проверкой пользователя. Это не Obsidian API/MetadataCache и не поддержка произвольных плагинов.

Контроль пользователя действует при доступе к кэшу, обходе и каждом запросе. Ввод редактора и успешные create/save/mkdir/init/move/rename/trash/restore/purge/import через перехваченный protectedApi инвалидируют индекс; non-save операции дополнительно посылают событие каталога. Не все старые приватные маршруты обязаны проходить через этот экспортированный wrapper. Смена пользователя очищает кэш/pending и инвалидирует старую generation; завершившийся чужой/отменённый запрос не должен публиковать результат.

## Граф

Кнопка «Граф заметок» создаётся в ribbon, не в старой файловой панели. При открытии строится/обновляется индекс после сохранения dirty-буфера; readOnly временно защищает редактор. Выход возвращает к заметке в той же рабочей области, не создаёт вкладку или split view.

В исходниках уже предусмотрены:

- Общий граф и локальный граф активной заметки глубины1/2 по входящим и исходящим связям. Без открытой заметки локальный режим сообщает об этом.
- Фильтр имени/пути, переключатели missing/ambiguous целей и изолированных заметок; результат —подграф, не полный набор фильтров Obsidian.
- Масштаб колесом у указателя с пределами0.2–4, pan фона, drag узла; симуляция d3-force с link/charge/center/collide.
- Подсветка соседей наведением, различение resolved/missing/ambiguous и цвета из темы. Группы/пользовательские правила цвета этим не реализованы автоматически.
- Клик/Enter/Space открывает существующую заметку после сохранения; missing/ambiguous показывают сообщение и не создают файл.

Закрытие представления останавливает симуляцию и отменяет следующие шаги построения через epoch/AbortController; уже выполняющийся fetch может завершиться. Смена пользователя очищает индекс, видимый граф и сохранённые позиции; старый результат не должен попасть в новую сессию. Сообщение об устаревшем индексе требует явного обновления, не обещает live-синхронизацию.

## Проверки

План, не новый отчёт:note_index.test.mjs для ссылок/code/comments/путей/ambiguity/повторных связей/backlinks/свойств; Node не заменяет DOM/IIS. На безопасном наборе00–07 проверить:

1. Одноимённые файлы в разных папках, missing/ambiguous, wiki/обычную .md-ссылку, корневой путь и fragment без ложного обещания позиционирования.
2. Code/comments/YAML, отдельный сбор propertyNames/propertyValues и отсутствие обещания YAML-связей/aliases/тегов; личные данные не публиковать.
3. Общий/локальный граф1/2, фильтры, zoom/pan/drag/подсветку/клавиатуру, расположение ribbon и возврат к заметке.
4. Сохранение перед переходом, Undo после save, rename/trash/restore/import и явное обновление индекса, частичный/ошибочный обход.
5. Две учётки/истёкшую сессию, закрытие во время индексации, старый async-результат, лимиты и производительность Firefox113/Windows7.

## Дальнейшее развитие и историческая граница

Доработка фильтров/групп/цветов/узлов/подписей/связей/раскладки не новая реализация уже существующего общего/локального графа с нуля. Перед расширением сверять актуальный интерфейс оригинала; точная копия Obsidian не обещана и не должна блокировать Markdown. Серверный/worker-индекс, полные события, YAML-связи/aliases/теги и безопасный совместимый API остаются отдельным объёмом backlog.
