# Слой совместимости тем Obsidian → WebVault

## Реализованная основа note-theme-12
Семантические роли --wv-ui-font, --wv-note-font, --wv-editor-font, --wv-code-font, --wv-code-size, --wv-selection-background/text, --wv-markup-color/weight, --wv-active-line-background опираются на базовые переменные Obsidian. Defaults помещаются в ранний obsidian-tokens.css, не навязываются поздним body-стилем поверх импортируемой темы. В CM используется явный non-fallback tagHighlighter с классами wv-md-* / wv-syntax-*, вместо светлого defaultHighlightStyle.

Текстовая/рисованная selection разделены: .cm-selectionBackground получает цвет роли; native input/textarea внутри CM явно переопределяют системный Highlight!important. Прозрачное native выделение самих CM-строк, нужное drawSelection, не отменяется. UI-поля имеют interface-шрифт, проза — text, редактор — editor с fallback на text, код — monospace; font-code обрабатывается как размер. Изменение body class/style и завершение загрузки локальных шрифтов запрашивает повторное измерение CM, не меняя документ.

## Дальнейший адаптер — проект, не готовый loader
1. Прочитать manifest, лицензию, CSS через AST; собрать custom properties, зависимости var, условия, ресурсы и требуемые browser features.
2. Переносить поддержанные значения и сопоставления ролей. Не угадывать тип переменной по слову font. Не обещать наличие отсутствующего локального шрифта.
3. Применять только явные mapping rules к реальному DOM: маркеры, заголовки, ссылки, свойства и собственный календарь. Не добавлять фиктивные классы Obsidian для активации неизвестного layout.
4. Разделять палитру/типографику и компоновку. Gutter/sizer/scroll, native desktop/Electron-поведение и сторонние плагины не переносить автоматически.
5. Учитывать theme-dark/light и поддержанные состояния. CSS :has для Firefox113 заменять явно поддержанными классами/правилами, а не считать работающим. Оpaque/e-ink selection требует отдельного foreground/secondary-selection решения.
6. Проверять @import/url/шрифты/лицензии, поставлять необходимые допустимые ресурсы локально; не делать CDN/интернет обязательными.
7. Отчёт: применено, сопоставлено, пропущено и почему; версия исходной темы и установленного профиля. Полная обратная совместимость со всеми плагинами не заявляется.

## Что пока НЕ реализовано
Загрузка theme.css, менеджер тем/персональный выбор, выполнение Style Settings/Minimal Theme Settings, CSS-compiler всех селекторов, автозагрузка шрифтов и полная поддержка всех цветовых вариантов. Аудит Minimal является входными данными, не исполняемой темой.


## Уточнение 12b: фон токенов и переносы
CM selection рисуется ниже текста: непрозрачный background у wv-md-code недопустим для подсветки самих исходных символов. В 12b он transparent, в HTML reading/live-rendered CODE/PRE фон --code-background сохраняется. Будущий адаптер должен различать фон поверхности/слоя и фон inline декорации; opaque/e-ink остаётся отдельной задачей. Цвет --text-selection не меняется этим исправлением.
Один исходный softbreak выводится как настоящий BR, не зависящий от white-space:normal; тема не должна молча скрывать семантический BR. Это политика отображения WebVault, не добавление пробелов/новых строк в Markdown-файл и не изменение code fence LF.
