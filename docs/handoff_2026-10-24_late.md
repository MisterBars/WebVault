## Текущая архитектура и ограничения
- native_text.js/native_text_model.js: текст/код/обычные заголовки остаются в CM; декорации скрывают только разметку. Escape скрывает slash, Entity получает локальный текстовый span. Скрытие не dispatch selection/changes.
- Нативные заголовки: inline fold-кнопка отдельно от текста, свёрнутое тело отдельно от заголовка; согласованные replace/atomic диапазоны. Reading/fold model сохраняются.
- HR остаётся BlockWidget, но его gutter marker пустой. Исходная строка/номер в source сохранены; соседние номера не скрывать. Геометрию не считать измеренной по факту скрытия цифры.
- mark_highlight.js: отдельный слой для WVHighlight, в том числе source, без скрытия текста/курсорных команд. Selection исключается из этого нового фонового слоя; остальные фоновые слои тем этим не исправлены.
- Wiki/обычные ссылки, HTML BR и изображения ещё могут направить абзац/заголовок в fallback. Точный первый клик там НЕ объявлен полностью исправленным. Inline-списки имеют отдельный принятый путь. Не ломать ранее принятые переходы по ссылкам, picker, подписи и точные пути.
- Не считать неподтверждённую здесь table-axis-delete-18h принятой по одному коммиту; статус сверять отдельно.

## Следующий технический комплект: test-all-19j
До изменения parser для сносок добавлена отдельная команда npm run test:all. Прежний npm test сохранён без изменения: он охватывает только четыре перечисленных в package.json файла.

run_all_tests.mjs находит обычные файлы *.test.mjs непосредственно в tools/cm6, сортирует имена и передаёт абсолютные пути текущему process.execPath с --test --test-concurrency=1. Раскрытие shell-glob не требуется, shell не запускается. Это проверяет переносимость механизма запуска, а не обещает поддержку любых старых Node. Для команды нужны поддерживаемые установленным Node параметры --test/--test-concurrency. Вложенные каталоги, другие расширения тестов и браузерные проверки автоматически не включаются.

Ошибка обнаружения/пустой набор/ошибка запуска/сигнал дают ненулевой код, код ошибки Node сохраняется. Не пропускать падающие тесты и не ослаблять assertions ради зелёного результата. Отдельно отличать устаревшее ожидание после согласованного изменения требований от регрессии реализации.

У ассистента прошли 10 изолированных проверок runner/discovery/exit-policy, включая реальные временные Node fixture suites с успешным и намеренно падающим тестом. Это НЕ запуск полного репозитория. Новый test_all.test.mjs подготовлен; полный npm run test:all на реальном WebVault здесь не выполнен. Пользовательские выводы полной регрессии в этой беседе не предоставлены.

После pull из tools/cm6:

```powershell
npm run test:all
```

Для этого комплекта npm install/build, перенос bundle и приёмка сайта не нужны: зависимости и исполняемый код сайта не изменены. package-lock.json не удалять/не обновлять автоматически — изменён только scripts в package.json, зависимости те же. При ошибке сохранить первый провал и итоговую сводку; не собирать следующую функциональную версию поверх неизвестного результата. Будущие функциональные комплекты: полный test:all, затем build после успеха и отдельный короткий браузерный чек-лист.
