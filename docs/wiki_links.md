## Комплект 1: ссылки
После [[ в документе source/dynamic открывается CM completion по имени и пути личных заметок. Стрелки/Enter/Tab/мышь выбирают, Escape закрывает. HTML completion не заменяется: источник добавлен через languageData. В коде, полном frontmatter, escaped/embed и скрытых комментариях target-popup не активируется; #heading/^block пока не предлагаются. Списковые native input свойств в этот CM источник не включены.

Выбор сохраняется как [[/Folder/Note.md|Подпись]]: / здесь означает строго корень личного хранилища, НЕ filesystem/серверный путь. Файл берётся только из авторизованного каталога. %, # и квадратные скобки в реальном имени кодируются, чтобы не превратиться в разделители. Подпись после | сохраняется при замене адресата; без подписи используется имя файла без .md. Закрывающие ]] не дублируются. Это однозначный адрес, не нестабильный номер массива/графа. Старые короткие ссылки не переписываются и сохраняют прежние правила resolver. Перенос/переименование файла не переписывает все источники автоматически; строгая старая ссылка станет missing, а не откроет другую одноимённую заметку. Совместимость префикса / с внешними инструментами проверять отдельно, полное тождество Obsidian не обещается.

Обычный клик по отрисованной ссылке в dynamic переходит, не раскрывая весь блок. Alt+клик сохраняет путь к редактированию исходника (в этом первом комплекте ещё всего блока). В reading клик обычный. Подписи [[target|text]] и Markdown [text](path.md) renderer уже поддерживал; этот комплект сохраняет их и связывает с выбором/переходом. Ссылки #/^ пока открывают заметку без прокрутки к фрагменту.

## Каталог и безопасность
link_catalog.js строит путь-каталог только GET list по папкам, не читает тексты и не строит граф. Лимиты первой версии: 300 файлов/300 папок. Печать в заметке и обычный save не сбрасывают каталог на каждую клавишу. Ctrl+Space внутри [[ принудительно обновляет каталог, чтобы увидеть изменения другого клиента; WebVaultLinks.status()/refreshCatalog() дают диагностическую проверку без текста заметок. Create/move/rename/trash/restore/import и смена пользователя инвалидируют кэш/закрывают старую подсказку. Async-ответ и apply проверяют пользователя, путь/режим, актуальность snapshot и текущий [[...]] диапазон. Старое меню не вставляет чужой/удалённый адрес. Root-qualified lookup не делает basename fallback. ../, backslash, control/drive/scheme/двойные slash не превращаются в запрос произвольной ФС. Серверные auth/CSRF/DataRoot проверки не меняются.

Переход сохраняет текущий документ через прежний app.saveNote и блокируется при незавершённых native свойствах/формах. Чтение адресата идёт по выбранному пути из каталога через штатный protected API. @codemirror/autocomplete уже был транзитивным; теперь объявлен прямым ^6.0.0, сохранить lock после npm install --ignore-scripts. Undo завершённой вставки — отдельный input.complete шаг через isolateHistory.

## Не закрыто этим комплектом
Пункты пользователя 4–6 требуют inline-декораций списка: не block-widget всего списка и не раскрытие целого li. Маркер/флажок/ссылка должны иметь собственные диапазоны, а текст строки оставаться редактируемым. Настоящие checkbox в dynamic/reading и UTC timestamp — следующий связанный комплект; сейчас статические флажки не объявляются готовыми.

## Проверки и дизайн
Метка window.__WV_LINKS_TEST='wiki-links-13'. Меню — штатные .cm-tooltip-autocomplete, .cm-completionLabel/Detail, li[aria-selected=true]; style wv-wiki-completion-style использует background-secondary, background-modifier-border/active-hover, text-normal/muted, font-ui-small/smaller и --wv-ui-font. Это реальные CM элементы, новые фиктивные Obsidian классы не добавлены. Source popup, strict root и lookup не меняют текст массово.

Ассистент проверил синтаксис новых файлов/фрагмента editor и 14 изолированных тестов модели/resolver/catalog; все 13 прошли. 4 интеграционных теста реальных CM completion подготовлены, здесь не запускались.
