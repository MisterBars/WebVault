# Оформление рабочей области и совместимость тем

Статус: новый интерфейс подготовлен, в Firefox/IIS ещё не проверен. Изменений API/БД/формата заметок нет. Применять после установки файлового модуля 05 и DataRoot.

## Цель
Знакомая Obsidian-подобная рабочая область вместо диагностической веб-формы. Ориентир пользователя — Minimal (выбрана в MyVault/.obsidian/appearance.json). Стили WebVault написаны самостоятельно; CSS/код Minimal или оригинального приложения в этот комплект не скопированы. Не обещать полную совместимость по визуальному сходству.

## Сделано
Полноэкранный личный раздел, левая ribbon-панель с реальными кнопками, сворачиваемый список файлов, фильтр по имени, форма создания из кнопки, одна вкладка текущего файла, заголовок и центрированная область текста, строка состояния, активный файл, индикатор изменений и число UTF-16 единиц текста (пользовательская подпись «символов», не точный подсчёт графем). Ctrl+S сохраняет, Ctrl+O фокусирует фильтр имени; эти клавиши перехватывают стандартные действия браузера на этой странице. Нет фиктивных кнопок графа/плагинов. Вкладка пока одна: переключение файлов, не система нескольких открытых вкладок.
Область ввода блокируется на время открытия/перечитывания, чтобы не затереть текст, введённый во время запроса. При ошибке сохраняется прежний буфер. Сохранение допускает дальнейший ввод: ответ помечает чистым только отправленный текст.

## CSS-контракт v0.1
Порядок: assets/css/obsidian-tokens.css (наши значения по умолчанию) -> assets/css/workspace.css (наша компоновка) -> в будущем проверенная адаптированная тема/персональные параметры. Общий app.css административных страниц не подключается к заметкам, чтобы его жёсткие цвета и формы не мешали.
body: theme-dark или theme-light, mod-windows, is-readable-line-width, webvault-workspace. Пока тёмный режим по умолчанию; переключателя и сохранения пользовательского выбора ещё нет. Набор светлых токенов — заготовка для следующего этапа, не скрытая настройка.
Используемые группы переменных:
- background-primary/primary-alt/secondary/secondary-alt, background-modifier-border/hover/active-hover/form-field;
- text-normal/muted/faint/accent/error/selection, text-on-accent;
- interactive-normal/hover/accent/accent-hover;
- font-interface-theme/font-text-theme/font-monospace-theme и разрешённые font-interface/font-text/font-monospace;
- font-text-size/font-ui-small/font-ui-smaller, line-height-normal, file-line-width;
- ribbon-width/header-height/tab-height/status-bar-height, radius-s/m/l, input-height/input-radius;
- nav-item-color/nav-item-color-active/nav-item-background-active.
Это поддерживаемое подмножество, не полный каталог Obsidian. Не все переменные уже используются каждым элементом. В рабочем CSS цвета и основные размеры опираются на токены; точная структура и поведение оригинала не воспроизводятся.

Близкие DOM-узлы: .app-container, .workspace, .workspace-ribbon, .workspace-split.mod-left-split/.mod-root-split, .workspace-tabs, .workspace-tab-header-container, .workspace-tab-header.is-active, .workspace-leaf, .workspace-leaf-content[data-type=file-explorer/markdown], .nav-header, .nav-files-container, .nav-file, .nav-file-title.is-active, .nav-file-title-content, .view-header/.view-content, .markdown-source-view, .inline-title, .status-bar.
Собственные узлы имеют webvault-префикс. Заголовок inline-title отображает имя файла; пока не редактируется и не входит в текст .md.

## Матрица совместимости
- Темы на стандартных переменных цветов/типографики: проще адаптировать, не гарантированно без изменений.
- Селекторы общей рабочей области: частичная структурная близость, требуется проверка темы.
- .markdown-preview-view/.markdown-rendered: пока не реализованы, режима чтения нет.
- .cm-editor/.cm-content/.cm-line и токены CodeMirror: не реализованы, не добавлены фиктивно на textarea.
- Live Preview, подсветка синтаксиса, CSS для задач/callout/таблиц: пока отсутствуют.
- Minimal Settings, Style Settings и другие плагины: их настройки/классы не исполняются. Полная тема Minimal на этом этапе не заявлена совместимой.
- Автоматическая загрузка тем из .obsidian/themes и персональный менеджер тем: пока не реализованы.

Нельзя просто подключить любой theme.css и обещать тот же результат. До менеджера тем документируем устойчивую структуру, затем проверяем конкретные темы на копии. Не исполнять JS из темы, не подключать внешние шрифты/CDN на рабочем ПК. Будущий выбор темы должен храниться для каждого пользователя отдельно, не глобально на сервере.

## Обновление и проверки
Новый SQL и конфигурация не нужны. Получить файлы, Ctrl+F5, войти личной учёткой. Проверить создание/чтение/ручное сохранение/конфликт двух вкладок, русские имена, активный файл, фильтр, скрытие панели, навигацию/выход и адаптацию ширины. При показе старого интерфейса проверить загрузку новых CSS/JS через сеть браузера. Не удалять данные/реестр хранилищ ради обновления внешнего вида.

## Следующий этап
Функциональное дерево папок и операции файлов; затем настоящий редактор/режим чтения с согласованным DOM, локально поставляемыми библиотеками и безопасным Markdown-рендерингом. Только после этого можно оценивать совместимость сложных тем редактора. Выбор библиотеки и её версия фиксируются отдельно; Live Preview не следует путать с обычным textarea или отдельным предпросмотром.

Основание: официальная документация Obsidian About styling/CSS variables и Views and editing mode.

## Дополнение 22.10.2026: приёмка свойств и кандидат автодополнения
Пользователь принял properties-chips-reading-01 по семи браузерным пунктам и properties-wikilinks-02 по четырём: списки и ссылки работают в dynamic/reading, крестик не открывает ссылку, изменения сохраняются. Смешанные chips и ссылки отдельно подтверждены. Старые статусы кандидата выше сохранены как история. Вывод полной npm-сборки/тестов пользователем не предоставлен.

Следующий локальный кандидат: properties-autocomplete-03. Подсказки для списковых полей поступают из одноимённых (без учёта регистра имени) свойств других личных заметок, включая простые строковые значения. Текущая заметка исключена, выбранные точные значения не предлагаются. Поиск подстроки без учёта регистра; до 20 вариантов. В YAML сохраняется полное значение, включая [[target|alias]], не только подпись. Скалярные поля не получают меню в этом комплекте.

Данные добавлены в существующий личный note_index при его чтении заметок без отдельного прохода запросов. Используются существующие лимиты 300 заметок/20 MiB и лимиты графа; ошибка графа/индекса может сделать подсказки недоступными, но свободный ввод сохраняется. До 1000 простых значений на заметку, до 1024 символов в значении; большие/сложные значения пропускаются. Первое открытие может ждать построения индекса; после изменений существующая invalidation заставляет перестроить его при следующем запросе. Локальные несохранённые изменения других вкладок не видны. Дополнительный серверный API не добавлен.

Меню открывается по фокусу/вводу; по умолчанию ни один пункт не выбран. Стрелки выбирают; Enter/Tab подтверждают выбранный пункт и добавляют его. Без выбора Enter добавляет введённый текст. Escape закрывает меню без очистки, следующий Escape очищает ввод по прежнему правилу. Клик выбирает вариант. IME не должен преждевременно подтверждаться. Смена заметки/пользователя/режима проверяется перед выдачей, потеря фокуса и удаление поля закрывают меню; события изменения индекса закрывают уже открытые варианты. Ошибка индекса показана в title поля, ручной ввод остаётся доступным.

CSS-контракт дополнен реальными собственными классами: .wv-property-suggestions (fixed listbox в body, не внутри обрезаемой колонки) и .wv-property-suggestion[aria-selected=true]. Ввод имеет role=combobox, aria-expanded/controls/activedescendant. Стиль wv-property-suggestions-style использует background-primary, background-modifier-border/hover/box-shadow, text-normal, font-ui-small/font-interface, radius-m/s. Цвет тени имеет запасное значение; совместимость тем не заявляется полной.
