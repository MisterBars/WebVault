Сейчас выполняется очередь D. Очередь P сохраняется для следующего функционального этапа; её пункты не запускаются автоматически при редактуре документов.

База этого входа: 702aed18cbaf27640f38a86c5ca2248cbd7ea2ea, MisterBars/WebVault, main. Перед любой новой записью проверять фактический HEAD.

Сведены основные требования из передач [22 октября](handoff_2026-10-22.md), [24 октября](handoff_2026-10-24.md), [поздней передачи 24 октября](handoff_2026-10-24_late.md) и [25 октября](handoff_2026-10-25.md), с учётом [исправления сведений о backlog и runner](test_all_19j_fix.md). ## Очередь P — проект

Ниже сохранён контекст функциональной очереди, не полный backlog и не утверждение об отсутствии реализации. Порядок внутри новых пакетов предварительный; окончательные зависимости определить после D-05. Проверку уже реализованного отличать от новой реализации.

### P-01. Markdown и редактор

- MD-BR-01: проверить HTML BR в dynamic/reading без изменения исходника; BR/ссылки/изображения могут оставаться fallback-контекстами.
- MD-MARK-SOURCE-01: сверить source ==mark== с реализацией 19g; не смешивать mark с selection. Наличие старого checkbox не доказывает, что функция отсутствует.
- MD-FOOTNOTES-01: сверить named/repeat/inline/multiparagraph сноски и форматирование с 20a–20f; локальные переходы, обратные ссылки, подсветка, размещение у конца раздела первого упоминания и раскрытие групп определений. Не просить повторно уже предоставленный пример. Полную готовность parser/DOM не выводить из модельных тестов.
- MD-BLOCK-BOUNDARIES-01: проверить разделённые пустой строкой отступные блоки с четырьмя пробелами и blockquote; сохранить отдельные блоки и промежуток. Не смешивать code block, blockquote и footnote.
- MD-COMMENTS-01: inline/multiline %% и HTML comments; заголовки внутри многострочного комментария не должны попадать в обычное отображение, folding или индекс.
- Завершить native fallback для ссылок/BR/изображений, не возвращая нативные текст/код/обычные заголовки к BlockWidget или принудительной парковке курсора. Сохранить folding, source ranges/номера, Undo/Redo, автосохранение и guards.
- Сверить статусы таблиц, включая table-axis-delete-18h; наличие коммита не подтверждает браузерную проверку. Сохранить задачи checkbox/UTC времени включения, списков, callout icons и folding прочих контейнеров.

### P-02. Боковая панель и файловые операции

- SIDEBAR-TABS-01: отдельные вкладки Файлы, Поиск, Закладки.
- SIDEBAR-RESIZE-01: изменение ширины перетягиванием края.
- FILES-TOOLS-01: создание файла/папки, сортировка, включаемое автоматическое раскрытие пути, указание текущей заметки, раскрытие/сворачивание всех папок.
- FILES-DROP-01: drop внутри области целевой папки, не только на заголовок; однозначная цель и серверные проверки.

### P-03. Поиск, теги, закладки и ribbon

- SEARCH-OPTIONS-01: кнопка настроек поиска и учёт регистра; полный состав настроек требует сверки с исходным примером, в доступном handoff скриншота нет.
- SEARCH-SUGGEST-01: подсказки и история при обращении к поиску; дополнительные правила подсказок требуют уточнения до реализации.
- TAGS-SEARCH-01: округлые chips; клик открывает боковой поиск, подставляет тег и запускает поиск заметок. Буквальное совпадение текста не равно семантическому поиску тега.
- BOOKMARKS-01: именованные ссылки на файлы и собственные каталоги закладок; не перемещение/копирование реальных файлов.
- RIBBON-ORDER-01: перетаскивание и перестановка иконок узкой панели.

### P-04. Остальной функциональный backlog

При полной сверке сохранить как минимум следующие группы, не считая этот перечень исчерпывающим:

- Граф: фильтры, группы/цвета, узлы/подписи/связи, силы/раскладка, локальный граф; развитие индекса и безопасного API без обещания полной совместимости с Obsidian.
- Свойства: глобальная схема типов, ограничения YAML и безопасных преобразований, cssclasses; не повторно реализовывать уже существующие операции панели.
- Файлы: упрощение импорта/экспорта, max N+1 имени с серверной защитой от гонки, настройка папки новых заметок, pending recovery корзины и Ctrl+A дерева.
- Навигация: текущая вкладка по обычному клику, Назад/Вперёд по успешным открытиям с сохранением и изоляцией сессии, затем несколько документов/вкладки и split view.
- Темы: AST/профили адаптера, Firefox113 capabilities, локальные ресурсы/шрифты и лицензии, opaque/e-ink и вторичные выделения; аудит Minimal не равен подключению темы.
- CHANGELOG-UI-01/02/03: локально поставляемая безопасная публичная история установленного комплекта, генерация ленты и корректная версия/дата; без live GitHub/CDN и публикации технических архивов.
- Требования ТЗ: безопасные вложения/поиск, история версий после rename/move, copy/cut/paste, независимая история документов, очередь autosave/конфликты, бэкап/восстановление, модульность/реестр команд, личные настройки, API расширений/safe mode и безопасность на целевой среде. Точный состав и статусы извлечь из ТЗ.
- DataviewJS и дополнительные встроенные инструменты упомянуты в ранней передаче как неподтверждённый контекст: объём/приоритет требуют сверки, не обещать совместимость сторонних плагинов.

## Правила выполнения и отчётности

- Все изменения через GitHub-коммиты/push с подтверждением точного payload. Один коммит — связанный этап; код не смешивать с документационной редактурой. Перед заменой читать полный актуальный файл; после записи проверять фактические файлы и diff.
- Не выполнять reset --hard, clean, force push или автоматическое сокрытие локальных правок. Не коммитить DataRoot, заметки/вложения, бэкапы, секреты, рабочий Web.config и node_modules. Не менять lock/SQL/зависимости без отдельного основания.
- Целевая среда: Windows7, .NET Framework4.5, IIS, SQL Express2014, Firefox113; классический ASP.NET, не Core. Node нужен для сборки, не для запуска сайта. Публиковать сайт отдельно, не корень Git/docs/tools.
- Node-команды из D:\project\WebVault\tools\cm6. npm test охватывает четыре файла; полный набор — npm run test:all. Runner обнаруживает верхнеуровневые *.test.mjs, не включает автоматически вложенные тесты и браузер.
- Функциональные изменения: адресные тесты → npm run test:all → только после успеха npm run build → отдельная публикация bundle и браузерная проверка. В PowerShell проверять $LASTEXITCODE; ошибки и assertions не обходить.
- Docs-only: проверять ссылки/якоря/пути/команды, Markdown и сохранность требований; сборку/публикацию без необходимости не требовать. Не заявлять непроведённые проверки.
- После каждого push: SHA, фактический состав, проверки и ограничения, остаток очереди; обязательно команды безопасного получения изменений на ПК и просмотра результата. При локальных изменениях сначала сверка и согласованный способ сохранения, не слепой pull.
