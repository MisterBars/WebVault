## Техническая база и проверки

Windows7/.NET Framework4.5, классический ASP.NET/IIS .ashx, SQL Express2014, Firefox113; не ASP.NET Core. Node на сборочном ПК, не зависимость запуска сайта. Публиковать только сайт, не Git/docs/tools/node_modules.

Нативные текст/код/обычные заголовки не возвращать в BlockWidget и не парковать курсор. Сохранять folding, ranges/номера, selection/Undo/Redo/autosave и guards сессии/заметки/readOnly/черновиков. Ссылки/BR/изображения могут оставаться fallback; mark не selection, HR скрывает только собственный отрисованный номер. Полная регрессия сносок/таблиц не доказана модельными тестами.

nativeText.extension восстановлен коммитом 702aed18cbaf27640f38a86c5ca2248cbd7ea2ea, не незакоммиченная правка. Обещанные footnote_dynamic.test.mjs/docs/footnotes_dynamic_20e.md не вошли в фактический двухфайловый push — не считать существующими/прошедшими. Текущий bundle и его публикация не подтверждаются синхронизацией Git; старые числа тестов не текущий HEAD.

Node-команды только из D:\project\WebVault\tools\cm6. npm test — четыре файла, полный набор — npm run test:all, верхнеуровневые *.test.mjs без shell glob; вложенные тесты/браузер автоматически не включены. Для функциональных изменений адресные тесты → test:all → build только после успеха → отдельная публикация bundle → браузер. Проверять LASTEXITCODE, не пропускать провалы/не ослаблять assertions. [Контракт runner](npm_build.md#самопроверка-runner-и-защита-от-ложного-успеха). Docs-only: статические проверки и сохранность, без обязательных build/публикации.

## Правила выполнения и отчётности

- Все записи через GitHub с подтверждением точных полных аргументов; читать полный заменяемый файл, проверять HEAD, после записи — фактический SHA/состав/полный diff или сохранённый текст. Связанные изменения одним push_files; delete_file последовательны, точные подтверждения готовить группой, не имитировать удаление пустым content.
- Не reset --hard/clean/force push/автоматический stash. Не коммитить DataRoot, заметки/вложения, бэкапы, секреты, рабочий Web.config/node_modules. Код/SQL/зависимости/lock/bundle не менять под видом docs.
- Перед получением сохранить вкладки, main/status/diff/staged проверить, fetch и merge --ff-only точного SHA, остановиться при ошибке. Untracked vendor не трогать. Последний предоставленный локальный снимок — 4d80a0110eb3eb1d88ffbf65b14ae2fa9d33d5d0, main/origin/main/origin/HEAD совпали, tracked/staged diff не показан, untracked src/WebVault.Web/assets/vendor/. Это не вечное состояние.
- После содержательного этапа: экспертные проценты общей ревизии/пакета, реальные удаления/добавления, SHA/состав/проверки/ограничения/остаток, необходимость build/публикации и безопасные команды получения конечного SHA на ПК. Не объявлять локальное получение или непроведённые тесты; синхронизация не повышает прогресс.
