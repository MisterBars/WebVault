# Управление пользователями — этап 1

Статус: код подготовлен, выполнение в IIS не проверено. БД не меняется; нужны применённый 02_auth.sql и работающая авторизация.

## Запуск
Войти на auth.html под администратором, затем открыть users.html на том же origin (например, всё через 127.0.0.1:8085, не смешивать localhost). Создать обычного пользователя и проверить вход в отдельном приватном окне.

## API
- GET api/admin/users.ashx: только администратор, список первых 200 пользователей; хеши, соли и токены не возвращаются. Пагинация пока не реализована.
- POST api/admin/users.ashx: только администратор, JSON login/displayName/password; X-WebVault-Request: 1 и X-CSRF-Token из me. Создаёт только обычного активного пользователя; isAdmin из запроса не используется. Успех 201, дубликат логина 409 login_exists.
- Перед вставкой повторно проверяются действительность сессии, активность и административный статус в транзакции.
- WebApi.cs — общие проверки для новых защищённых API. Существующий AuthHandler пока остаётся отдельным; объединение его вспомогательных функций в общий слой — будущий рефакторинг.

## Проверки
- [ ] Администратор видит список и создаёт пользователя.
- [ ] Пароли не отображаются в списке или ответе создания.
- [ ] Дубликат логина в другом регистре отклоняется.
- [ ] Без входа GET/POST получают 401; обычный пользователь получает 403.
- [ ] POST без верного CSRF отклоняется.
- [ ] Передача isAdmin=true не создаёт администратора.
- [ ] Новый пользователь входит и выходит через auth.html.
- [ ] Старые setup/login/me/logout продолжают работать.

Управление ролями, блокировка через интерфейс, сброс/смена пароля и самостоятельная регистрация пока не реализованы. Администратор задаёт начальный пароль и знает его — для реального использования другими людьми нужна следующая возможность самостоятельной смены пароля. Не представлять этот этап завершённой системой приватных заметок.
