## Новый кандидат
У имени редактируемого свойства в dynamic/reading появляется × с title/aria-label «Удалить свойство …». Это удаление поля целиком, не крестик отдельного chip. Сначала открывается локальный dialog с названием поля; начальный фокус на Отмена. Escape/Отмена не меняют документ. Подтверждение использует существующий onCommit/commitPropertyChange, отдельный шаг общей истории и прежнее автосохранение. Удаляется поле только текущей заметки, не общая схема и не одноимённые поля других заметок.

Незавершённый ввод любого поля, форма добавления и другой диалог блокируют удаление. Существующие проверки пользователя/заметки/режима/busy/ожидаемого документа сохраняются в onCommit. Диалог повторно использует базовый .wv-property-type-panel и .wv-property-type-actions: поэтому существующая защита истории/переходов распознаёт его как незавершённый диалог. Дополнительный класс .wv-property-remove-panel обозначает его назначение.

YAML разбирается для получения диапазона ключа/значения; применяется только текстовое удаление без сериализации остальных полей/тела. Соседние отдельные комментарии сохраняются, комментарий на строке удаляемого поля удаляется с ним. Результат повторно разбирается и проверяется на сохранность остальных ключей, типов, значений и raw. После последнего поля остаётся пустой frontmatter; Добавить свойство остаётся доступным. Сложные/readonly/anchored/tagged значения и неоднозначные ключи требуют исходника.

Контракт: button.wv-property-remove-button[aria-expanded], .wv-property-remove-panel[role=dialog], style wv-property-remove-style; text-muted/normal/error, background-modifier-hover, radius-s. Маркер window.__WV_PROPERTY_REMOVE_TEST='properties-remove-16'.

## Проверка сайта
1. Маркер properties-remove-16, × у имени в dynamic/reading; крестики chips сохраняют своё действие.
2. Отмена/Escape ничего не меняют; подтверждение удаляет всё поле.
3. Undo возвращает поле/значения, Redo удаляет; проверять в обоих режимах.
4. Удаление текста, списка, числа, даты/флажка; последнее поле и повторное добавление.
5. В source соседние поля/комментарии и тело не изменены, результат переживает сохранение/открытие.
6. Незавершённый ввод другого поля не теряется, удаление блокируется до его подтверждения/отмены; readonly/сложные поля не удаляются кнопкой.
